# Summary

여러 로봇·시스템에서 흩어져 쌓인 원본 데이터를 그대로 분석하기는 어렵다. **[[ETL(Extract Transform Load)|ETL]]** 과정을 거쳐 정제된 데이터를 **[[데이터 웨어하우스(Data Warehouse)|데이터 웨어하우스]]**에 통합해 두면, 이후의 분석·의사결정에 일관되게 활용할 수 있다.

# Notes

<aside>데이터 웨어하우스(Data Warehouse)</aside>

여러 소스(로봇 로그, 서버 DB, 외부 IoT 데이터 등)에서 모은 데이터를 **분석 목적으로 통합·정리해 저장**하는 대규모 저장소다.

- 일상적인 서비스 운영을 위한 DB(트랜잭션 처리 중심)와 달리, **과거 데이터를 오랜 기간 누적**하고 대규모 집계·조회에 최적화되어 있다
- 데이터가 자주 갱신되기보다는, 정해진 주기(예: 매일 야간)로 새로운 데이터가 적재되는 경우가 많다

<aside>데이터 레이크(Data Lake)와의 대비 — 스키마 적용 시점</aside>

데이터 웨어하우스는 ETL로 정제한 뒤 **미리 정한 스키마에 맞춰(Schema-on-Write)** 저장한다. 반면 **[[데이터 레이크(Data Lake)|데이터 레이크]]** 는 정형·비정형을 가리지 않고 **가공 전 원본 그대로** 저장해 두었다가, 조회할 때 필요한 구조를 그때그때 적용한다(Schema-on-Read). 로봇의 원본 센서 로그·이미지처럼 나중에 어떤 형태로 쓰일지 아직 정해지지 않은 데이터는 우선 데이터 레이크에 원본으로 쌓아 두고, 이후 가공해 데이터 웨어하우스로 옮기는 방식이 흔히 쓰인다.

<aside>ETL(Extract, Transform, Load)</aside>

여러 소스의 데이터를 데이터 웨어하우스로 옮기는 표준적인 절차다.

| 단계 | 역할 |
|---|---|
| Extract(추출) | 로봇 로그, 센서 DB 등 여러 소스에서 원본 데이터를 가져옴 |
| Transform(변환) | 형식을 통일하고, 결측치·이상치를 정리하며, 분석하기 좋은 구조로 가공 |
| Load(적재) | 정제된 데이터를 데이터 웨어하우스에 저장 |



<aside>예시 — 로봇 로그의 ETL 처리</aside>

**예시**: 로봇 A의 로그는 섭씨 온도로, 로봇 B의 로그는 화씨 온도로 기록되어 있을 때, ETL의 Transform 단계에서 이를 섭씨로 통일하고 결측 구간을 표시한 뒤, Load 단계에서 데이터 웨어하우스에 함께 적재해야 이후 두 로봇의 데이터를 일관되게 비교·분석할 수 있다.

---

<aside>핵심 정리</aside>

- 데이터 웨어하우스는 여러 소스의 데이터를 분석 목적으로 통합·누적하는 저장소이며, 실시간 트랜잭션 처리가 목적이 아니다
- 데이터 웨어하우스(Schema-on-Write, 정제된 구조)와 데이터 레이크(Schema-on-Read, 원본 그대로)는 스키마를 적용하는 시점이 반대다
- ETL은 추출(Extract) → 변환(Transform) → 적재(Load) 순서로 진행되며, Transform의 핵심 역할은 형식 통일·정제·가공이다
