# Summary

데이터 웨어하우스에 정제·통합된 데이터가 쌓이면, 그 안에서 의미 있는 패턴을 찾아내는 **[[데이터 마이닝(Data Mining)|데이터 마이닝]]**이 가능해진다. 한편 데이터의 양 자체가 한 대의 서버로 감당하기 어려울 만큼 커지면, 데이터를 여러 서버에 나눠 저장하는 **[[샤딩(Sharding)|샤딩]]**이 필요하다.

# Notes

<aside>데이터 마이닝(Data Mining)</aside>

대량으로 축적된 데이터에서 **사람이 미리 알지 못했던 규칙·패턴·상관관계**를 발견해내는 것이다.

- 단순히 정해진 값을 조회하는 것이 아니라, "어떤 조건일 때 특정 부품 고장이 잦아지는가" 같은 **숨겨진 패턴을 찾아내는 것**이 목적이다
- 앞서 다룬 클러스터링(비지도학습)이나 통계적 상관 분석 등이 데이터 마이닝의 대표적인 기법으로 쓰인다

"데이터 마이닝의 주요 목적은 이미 알고 있는 값을 빠르게 조회하는 것이다"라는 서술은 단순 조회와 패턴 발견을 혼동한 오답이다 — 데이터 마이닝의 핵심은 **몰랐던 규칙을 새로 발견**하는 데 있다.

<aside>샤딩(Sharding)</aside>

**[[샤딩(Sharding)|샤딩]]**은 하나의 큰 데이터셋을 여러 조각(샤드)으로 나눠 **서로 다른 서버에 분산 저장**하는 기법이다. 로봇 수가 매우 많아 하나의 DB 서버로 모든 데이터를 감당하기 어려울 때, 데이터를 나눠 저장해 저장 용량과 처리량을 함께 확장할 수 있다.

<aside>샤딩 구현 시 고려사항</aside>

| 고려사항 | 설명 |
|---|---|
| 샤딩 키 선택 | 데이터를 어떤 기준(예: 로봇 ID)으로 나눌지가 중요 — 잘못 고르면 특정 샤드에 데이터가 몰리는 **핫스팟(hot spot)** 문제가 생김 |
| 샤드 간 데이터 균형 | 각 샤드에 데이터가 고르게 분산되도록 설계해야 일부 서버만 과부하되는 것을 방지 |
| 샤드 간 조회(Cross-shard Query) | 여러 샤드에 걸친 데이터를 한 번에 조회해야 하는 경우 성능이 복잡해질 수 있음 |
| 리샤딩(Resharding) | 샤드 수를 늘리거나 재배치할 때 서비스 중단 없이 데이터를 재분배하는 절차가 필요 |

"샤딩을 구현할 때는 어떤 기준으로 데이터를 나눌지는 고려할 필요가 없고, 단순히 순서대로 나누기만 하면 된다"는 서술은 샤딩 키 선택의 중요성(핫스팟 문제)을 무시한, 고려사항으로 적절하지 않은 접근이다.

<aside>일관 해싱(Consistent Hashing) — 핫스팟과 리샤딩 문제의 해결책</aside>

단순히 `해시값 % 샤드수`로 나누면, 샤드 수가 바뀔 때(서버 추가·제거) 나머지 연산 결과가 거의 다 바뀌어 **대부분의 데이터를 재배치**해야 하는 문제가 있다. **[[일관 해싱(Consistent Hashing)|일관 해싱]]** 은 해시 값의 범위를 원형(ring)으로 배치해 각 샤드가 일부 구간을 담당하게 하는 방식으로, 샤드가 추가·제거되어도 그 **인접 구간의 데이터만 재배치**하면 되고, 데이터도 원 전체에 고르게 흩어져 핫스팟도 함께 줄여준다.

<aside>예시 — 대규모 로봇 플릿의 데이터 확장</aside>

**예시**: 로봇이 수백 대로 늘어나며 하나의 DB로는 로그 저장이 벅차지자, 로봇 ID를 기준으로 데이터를 여러 서버(샤드)에 나눠 저장한다. 이후 데이터 웨어하우스에 통합된 데이터에 데이터 마이닝을 적용해, 특정 배터리 로트(lot)에서 유독 고장이 잦다는, 이전에는 몰랐던 패턴을 발견한다.

<aside>핵심 정리</aside>

- 데이터 마이닝은 축적된 데이터에서 몰랐던 규칙·패턴을 새로 발견하는 것이며, 단순 조회와는 다르다
- 샤딩은 대용량 데이터를 여러 서버에 분산 저장하는 기법이며, 샤딩 키 선택(핫스팟 방지)·데이터 균형·샤드 간 조회·리샤딩을 함께 고려해야 한다
- 일관 해싱은 해시 공간을 원형으로 배치해, 단순 나머지 연산 방식보다 리샤딩 시 데이터 이동량과 핫스팟을 함께 줄여준다
