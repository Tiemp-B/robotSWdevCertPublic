# Summary

**데이터 로깅(Data Logging)**은 로봇 상태 데이터를 시계열로 기록해 **사후적으로** 원인 추적·감사·성능 분석의 근거로 삼는 기능이며, 실시간 폐루프 제어에 직접 쓰이지 않는다. **이상치 탐지(Outlier Detection)**는 쌓인(또는 실시간으로 들어오는) 데이터에서 정상 범위를 벗어난 값을 판별하는 기법으로, 대표 방법이 **표준편차** 기반의 Z-score와 **사분위수** 기반의 IQR이다.

# Notes

<aside>데이터 로깅의 목적</aside>

| 목적 | 설명 |
|---|---|
| 원인 추적(사후 진단) | 오류 발생 시점 전후 데이터를 되짚어 원인 분석 |
| 감사 추적(Audit Trail) | 언제 어떤 명령·이벤트가 있었는지 기록해 책임 소재 확인 |
| 성능/트렌드 분석 | 장기 데이터로 성능 저하·마모 추세 파악 |
| SCADA 이력 관리(Historian) 연동 | [[3. SCADA 구조와 산업용 모니터링 시스템\|SCADA]]의 이력 저장 기능과 동일 데이터 공유 |

"데이터 로깅이 로봇의 실시간 제어 피드백에 직접 사용된다"는 서술은 틀렸다 — 로깅은 이미 지나간 데이터를 저장하는 **사후적 기록**이며, 실시간 폐루프 제어는 로깅과 별도의 저지연 센서 피드백 경로를 사용한다([[1. 로봇 제어기 특성 개요|1. 로봇 제어기 특성]] 참고).

<aside>로그 레벨과 보존 정책</aside>

DEBUG(개발용 상세 추적, 운영 환경에선 보통 비활성화) < INFO(정상 주요 이벤트) < WARN(주의 필요) < ERROR(기능 실패) 순으로 심각도가 커진다. 모든 원본 로그를 무기한 보관하는 것은 저장 공간상 비현실적이므로, **[[로그 로테이션(Log Rotation)|로그 로테이션]]**으로 일정 크기/기간마다 로그 파일을 분리·압축하고 보존 기간이 지나면 요약본만 남기거나 삭제하는 정책이 일반적이다.

<aside>Z-score(3-시그마 규칙) 기반 이상치 탐지</aside>

평균 $\mu$, 표준편차 $\sigma$로 각 값의 표준점수(**[[Z-score(표준점수)|Z-score]]**)를 구한다.

$$z = \frac{x - \mu}{\sigma}$$

일반적으로 $|z|>3$(정규분포 가정 시 평균 $\pm3\sigma$ 밖은 전체의 약 0.3%)을 표준적인 이상치 임계값으로 삼으며, 더 민감하게 탐지하고 싶을 때는 $|z|>2$(약 5% 밖)를 쓰기도 한다 — 임계값은 절대적 법칙이 아니라 데이터 특성에 맞춰 조정하는 경험적 기준이라는 점에 유의한다. "데이터의 표준편차를 이용해 평균에서 일정 범위를 벗어난 값을 이상치로 판단하는 방법"이 바로 이 Z-score 규칙이다.

<aside>IQR(사분위수 범위) 기반 이상치 탐지</aside>

정규분포를 가정하기 어려운 데이터에는 **[[IQR(사분위수 범위)|IQR]]** 방법이 더 안정적이다.

- 1사분위수 $Q_1$, 3사분위수 $Q_3$에 대해 $IQR = Q_3 - Q_1$
- $Q_1 - 1.5\times IQR$ 미만이거나 $Q_3 + 1.5\times IQR$ 초과인 값을 이상치로 판정(박스플롯 수염의 기준과 동일)

<aside>이상치 탐지와 필터링의 차이</aside>

이상치 탐지는 "판별"에, [[이동평균 필터(Moving Average Filter)|이동평균 필터]]·[[칼만 필터(Kalman Filter)|칼만 필터]]([[1. 로봇 제어기 특성 개요|1. 로봇 제어기 특성]] 참고)는 잡음 "완화"에 초점이 있다는 점에서 목적이 다르다. 실무에서는 필터링으로 잡음을 줄인 뒤 남은 급격한 이탈값을 이상치로 판정하는 방식을 함께 쓰는 경우가 많다.

<aside>예시 — 로봇 관절 전류 이상치 탐지</aside>

**예시**: 정상 작업 중 관절 모터 전류가 평균 2A, 표준편차 0.3A로 유지되다가 특정 순간 4.5A로 튀었다면 $z=(4.5-2)/0.3\approx8.3$으로 임계치를 크게 초과해 이상치로 판정되고, 충돌 또는 기구적 걸림(jamming) 가능성에 대한 알람([[4. 데이터 시각화와 알람(HMI)]] 참고)으로 이어질 수 있다.

<aside>핵심 정리</aside>

- 데이터 로깅 목적 = **사후 원인추적·감사·성능분석**(실시간 폐루프 제어에는 미사용), 보존은 **로그 로테이션**으로 관리
- **Z-score**: $|z|>3$이 표준(민감 탐지 시 $|z|>2$), 정규분포 가정 필요
- **IQR**: $Q_1-1.5IQR \sim Q_3+1.5IQR$ 밖, 정규분포 가정 불필요해 더 안정적
- 이상치 탐지(판별) ≠ 필터링(완화) — 목적이 다르며 함께 쓰이는 경우가 많음
