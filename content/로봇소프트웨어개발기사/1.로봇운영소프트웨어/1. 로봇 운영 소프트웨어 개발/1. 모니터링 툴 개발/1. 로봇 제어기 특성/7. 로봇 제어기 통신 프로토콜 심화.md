# Summary

로봇 제어기와 모터 드라이버·센서·상위 PC를 잇는 통신은 지연시간이 들쭉날쭉한 일반 이더넷/Wi-Fi 대신, 정해진 시간 안에 데이터 도착을 보장하는 **[[필드버스(Fieldbus)|필드버스]]**를 사용하는 경우가 많다. 이 페이지는 [[1. 로봇 제어기 특성 개요]] 개요에서 소개한 필드버스 개념을 확장해, 대표 프로토콜별 실시간성·구조 차이를 비교하고 상위 감시 계층인 **[[SCADA]]**까지 정리한다.

# Notes

<aside>왜 필드버스가 필요한가</aside>

일반 TCP/IP·Wi-Fi는 네트워크 부하에 따라 응답시간이 변동해 **비결정론적(non-deterministic)**이다. 로봇 제어기의 서보 루프는 매 주기(수백 µs~수 ms)마다 반드시 데이터를 주고받아야 하므로 지연시간이 예측 가능한 **결정론적 통신**이 필요하며, 이를 만족하도록 설계된 산업용 통신 규격이 필드버스다.

<aside>CAN(Controller Area Network) 심화</aside>

- **멀티마스터 구조**: 특정 노드가 아니라 **버스에 연결된 모든 노드가 메시지를 송신**할 수 있다 — 단일 마스터-슬레이브 구조가 아니다
- **충돌 중재(Arbitration)**: 여러 노드가 동시에 송신을 시도하면, **메시지 ID 값이 낮을수록(=우선순위가 높을수록)** 그 메시지가 먼저 전송되고 나머지 노드는 자동으로 양보한다(데이터 파괴 없는 무손실 중재)
- CAN은 메시지 우선순위 중재로 긴급 메시지를 지연 없이 전달하도록 설계되어 있어 **실시간성이 요구되는 분야에도 쓰인다** — "CAN은 실시간 통신이 불가능하다"는 서술은 설계 목적과 정반대다
- 최대 전송 속도는 통상 1Mbps 수준으로 다른 필드버스보다 느리지만, 배선이 단순하고 노이즈에 강해 이동로봇·서브시스템(액추에이터 모듈 내부 통신)에서 여전히 널리 사용된다

<aside>EtherCAT — 가장 결정론적인 산업용 실시간 이더넷</aside>

EtherCAT은 산업용 실시간 이더넷 중 가장 결정론적인 응답을 제공한다고 평가되며, 목표 사이클타임 **약 100µs 이하, 지터 약 1µs 이하** 수준을 지원한다(EtherCAT Technology Group 발표 기준 — 1,000개 I/O 처리 32.5µs, 100축 제어 125µs). 프레임이 슬레이브를 순차 통과하며 실시간으로 데이터를 읽고 쓰는 방식([[PDO(Process Data Object)|PDO]] 사용)과, 나노초 단위 정밀도의 Distributed Clock(분산 클록) 동기화가 다축 서보 제어에 특히 유리하다.

로봇 제어기 아키텍처에서는 **EtherCAT을 구동부(드라이브·분산 I/O)의 실시간 백본으로, CAN을 서브시스템(액추에이터 모듈 등) 내부 통신으로** 함께 쓰는 계층적 구성이 흔하다.

<aside>주요 필드버스/산업 이더넷 비교</aside>

| 프로토콜 | 구조 | 최대 속도 | 결정성 | 특징 |
|---|---|---|---|---|
| [[CAN(Controller Area Network)\|CAN]] | 멀티마스터, 버스형 | ~1Mbps | 중간(우선순위 중재) | 단순·저가·강인, 자동차/로봇 관절 통신 |
| [[EtherCAT]] | 마스터-슬레이브, 링/데이지체인 | ~100Mbps | 매우 높음(~100µs 이하) | PDO 기반 실시간 읽기/쓰기, 다축 서보 제어 |
| [[Modbus]] | 마스터-슬레이브, 폴링 | ~115kbps(RTU) | 낮음~중간 | 구조 단순, 계측·감시(SCADA)용, 실시간 서보 부적합 — Modbus TCP는 네트워크 부하에 따라 응답시간이 변동해 비결정론적 |
| [[Profinet]] | 마스터-슬레이브, 이더넷 기반 | ~100Mbps | 높음 | 지멘스 계열, EtherCAT과 유사한 실시간 클래스 지원 |
| [[PROFIBUS]] | 마스터-슬레이브, 토큰패싱 | ~12Mbps | 중간~높음 | Profinet의 전신, 기존 설비에서 여전히 사용 |
| [[CANopen]] | CAN 기반 상위 프로토콜 | CAN과 동일 | 중간 | CAN 위에 표준 장치 프로파일(PDO/SDO)을 얹어 상호운용성 확보 |
| [[SERCOS]] | 링형, 광섬유/이더넷 기반 | ~100Mbps 이상 | 매우 높음 | 서보 드라이브 동기 제어 전용 실시간 프로토콜 |
| [[POWERLINK]] | 마스터-슬레이브, 이더넷 기반 | ~100Mbps | 매우 높음 | 시분할(Time-slicing) 방식으로 결정성 확보 |

**요약**: CAN·CANopen은 저속·저비용·멀티마스터 계열, EtherCAT·Profinet·SERCOS·POWERLINK는 이더넷 기반 고속·고정밀 실시간(다축 서보) 계열, Modbus·PROFIBUS는 범용 계측·감시용으로 역할이 나뉜다.

<aside>시리얼/무선 통신</aside>

로봇 제어기 내부 보드 간·센서 모듈과의 근거리 통신에는 [[RS-232]](1:1, ~15m), [[RS-485]](차동·멀티드롭, 장거리·다수 장치), [[I2C]](2선식, 보드 내부 저속 센서), [[SPI]](4선식, 고속 근거리)가 흔히 쓰인다. 배선이 어려운 이동로봇·원격 모니터링에는 [[Wi-Fi]](고속·가변 지연)·[[Bluetooth]](근거리 저전력) 등 무선 통신이 쓰이지만, 지연시간이 가변적이라 결정성이 중요한 서보 제어 구간에는 잘 쓰이지 않고 주로 상위 모니터링·원격 조작에 사용된다.

<aside>상위 감시 시스템 — SCADA</aside>

**[[SCADA]]**는 필드버스로 수집한 현장 데이터를 상위 레벨에서 통합 감시·제어하는 소프트웨어 계층으로, HMI 화면에 시각화하고 이상 상황 시 알람을 발생시킨다. Modbus·PROFIBUS처럼 상대적으로 느리지만 표준화된 프로토콜이 SCADA 연동에 자주 쓰이는데, SCADA 자체가 서보 루프 같은 초고속 실시간성이 아니라 초 단위 주기의 감시·기록을 목적으로 하기 때문이다 — 로봇 제어기에서는 관절 서보 통신(CAN/EtherCAT)과 상위 SCADA 연동 통신(Modbus/TCP-IP)이 **서로 다른 계층·다른 프로토콜**로 분리되는 것이 일반적이다.

---

<aside>핵심 정리</aside>

- **CAN** = 멀티마스터(단일 마스터 아님) + 메시지ID 기반 우선순위 중재로 준실시간 통신 가능(실시간 불가 아님), ~1Mbps
- **EtherCAT** = 가장 결정론적인 산업 실시간 이더넷, ~100µs 이하 사이클타임, PDO+Distributed Clock — 흔히 EtherCAT(백본)+CAN(서브시스템) 계층 구성
- **Modbus** = 구조 단순·비결정론적, SCADA 연동에 적합하나 실시간 서보 부적합
- **SCADA**는 필드버스 데이터를 모아 감시·기록하는 상위 계층으로, 서보 통신과는 분리된 느린 주기로 동작
