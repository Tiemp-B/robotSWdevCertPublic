# Summary

로봇 제어기의 저수준 제어 계층에서는 서보 루프·센서 읽기·통신 처리 등 여러 태스크가 레지스터·버퍼 같은 공유 자원에 동시에 접근한다. 보호 없이 접근하면 결과가 접근 순서에 따라 달라지는 **경쟁 조건(Race Condition)**이 생기고, 이를 막는 대표 수단이 **[[뮤텍스(Mutex)|뮤텍스]]**와 **[[세마포어(Semaphore)|세마포어]]**다. 반대로 동기화를 잘못 설계하면 태스크들이 서로를 무한정 기다리는 **[[데드락(Deadlock)|데드락]]**에 빠질 수 있다.

# Notes

<aside>경쟁 조건과 임계영역</aside>

서보 제어 스레드가 매 주기 `total_cycles = total_cycles + 1`을 실행하고, 모니터링 스레드가 이 값을 주기적으로 읽어 화면에 표시한다고 하자. 이 한 줄은 실제로는 **①읽기 → ②더하기 → ③저장**의 3단계로 실행되므로, 서보 제어 스레드가 ①~② 사이에 문맥 전환(context switch)되어 다른 스레드가 값을 먼저 바꿔버리면 낡은 값에 1을 더해 덮어써 **갱신이 유실**될 수 있다 — 이것이 **경쟁 조건(Race Condition)**이다.

**[[임계영역(Critical Section)|임계영역]]**은 여러 스레드가 동시에 실행하면 데이터 일관성이 깨질 수 있는, 공유 자원에 접근하는 코드 구간을 가리킨다. 임계영역을 잠금(lock)으로 감싸 한 번에 하나의 스레드만 진입하도록 강제하면 경쟁 조건이 해결된다.

<aside>뮤텍스 vs 세마포어</aside>

| 구분 | 뮤텍스(Mutex) | 세마포어(Semaphore) |
|---|---|---|
| 값 | 0/1 이진(Lock/Unlock) | **정수 카운터**(이진+카운팅 모두 존재) |
| 소유권 | **있음** — 잠근 스레드만 해제 가능 | **없음** — 다른 스레드가 대신 해제(signal) 가능 |
| 용도 | 한 자원에 대한 **상호배제** | 동일 자원 N개에 대한 **동시 접근 개수 제어**, 태스크 간 이벤트 신호 |
| 사용 범위 | 주로 단일 프로세스 내 스레드 간 | 프로세스 간 동기화에도 사용 |

<aside>데드락(Deadlock)의 4가지 조건</aside>

**[[데드락(Deadlock)|데드락]]**은 둘 이상의 태스크가 서로 상대가 점유한 자원을 무한정 기다려 아무도 진행하지 못하는 상태이며, 아래 4조건이 **모두** 성립해야 발생한다.

- **상호 배제(Mutual Exclusion)**: 자원을 한 번에 한 태스크만 사용
- **점유와 대기(Hold and Wait)**: 자원을 쥔 채로 다른 자원을 추가 요청
- **비선점(No Preemption)**: 점유 중인 자원을 강제로 빼앗을 수 없음
- **순환 대기(Circular Wait)**: 태스크들이 원형으로 서로의 자원을 기다림

**예시**: 모션 제어 스레드가 뮤텍스 A(관절 상태 버퍼)→B(통신 버퍼) 순서로, 통신 처리 스레드가 B→A 순서로 잠그려 하면, 각자 하나씩 선점한 상태에서 서로의 나머지 자원을 영원히 기다려 데드락에 빠진다.

<aside>데드락과 구분해야 할 개념 — 우선순위 역전</aside>

**[[우선순위 역전(Priority Inversion)|우선순위 역전]]**은 데드락의 발생 조건이 아니라 별개의 스케줄링 문제다. 낮은 우선순위 태스크가 자원(뮤텍스)을 점유한 사이 높은 우선순위 태스크가 그 자원을 기다리는데, 중간 우선순위 태스크가 낮은 우선순위 태스크를 선점해버려 결과적으로 높은 우선순위 태스크가 무한정 밀리는 현상이다. **1997년 NASA 화성탐사선 Mars Pathfinder**가 VxWorks RTOS에서 우선순위 상속 없이 뮤텍스를 이진 세마포어처럼 사용해 이 문제로 시스템 리셋을 반복한 사례가 널리 알려져 있다 — 해결책인 **우선순위 상속 프로토콜**은 [[2. 실시간 운영체제와 스케줄링]]에서 다룬다(중복 서술 안 함).

<aside>데드락 예방</aside>

예방은 4조건 중 **점유와 대기·비선점·순환 대기** 중 하나를 깨뜨리는 방식으로 이루어진다(상호 배제는 동기화의 근본 목적인 데이터 일관성을 담당하는 조건이라 예방 대상에서 제외된다).

- **전부 할당(All-or-Nothing)**: 실행 전에 필요한 모든 자원을 한꺼번에 할당받아 "점유와 대기" 조건을 제거
- **잠금 순서 통일**: 모든 스레드가 항상 같은 순서(A→B)로 자원을 잠그도록 강제해 "순환 대기" 조건을 제거 — 위 예시에서 통신 처리 스레드도 A→B 순서로 잠그게 하면 데드락이 발생하지 않는다

<aside>핵심 정리</aside>

- 동기화 없이 공유 자원에 접근하면 **경쟁 조건**(갱신 유실 등) 발생 → 임계영역 + 잠금으로 해결
- **뮤텍스**: 소유권 있음, 이진 / **세마포어**: 소유권 없음, 이진+카운팅
- 데드락 4조건(상호배제·점유대기·비선점·순환대기)은 **모두 성립해야** 발생
- 예방은 상호배제 제거가 아니라 **점유대기·비선점·순환대기 중 하나를 깨는 것**
- 우선순위 역전은 데드락과 별개의 문제(Mars Pathfinder 사례), 해결책은 우선순위 상속
