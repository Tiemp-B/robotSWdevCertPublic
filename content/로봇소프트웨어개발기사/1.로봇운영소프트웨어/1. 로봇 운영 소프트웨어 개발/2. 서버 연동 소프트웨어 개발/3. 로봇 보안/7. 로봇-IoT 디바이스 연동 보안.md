# Summary

로봇이 다양한 IoT 디바이스(센서, 액추에이터, 게이트웨이 등)와 연동될 때는, 이 디바이스들이 대체로 자원이 제한적이고 관리가 소홀해지기 쉬워 일반적인 서버-클라이언트 환경과는 다른 고유한 보안 취약점이 생긴다.

# Notes

<aside>IoT 디바이스 환경의 특수성</aside>

- 저전력·저성능 하드웨어 — 복잡한 암호화 연산을 수행하기 부담스러움
- 다수의 디바이스가 물리적으로 분산 배치 — 개별 디바이스에 대한 물리적 접근 통제가 어려움
- 장기간 방치되는 경우가 많아 펌웨어 업데이트가 누락되기 쉬움

<aside>로봇-IoT 연동에서 흔한 보안 취약점</aside>

| 취약점 | 설명 |
|---|---|
| 기본 계정 미변경 | 제조사 출고 시 설정된 기본 아이디/비밀번호를 그대로 사용 |
| 펌웨어 미업데이트 | 알려진 취약점이 패치되지 않은 채 방치됨 |
| 평문 통신 | 센서·제어 데이터를 암호화 없이 전송 |
| 물리적 접근 통제 미비 | 디바이스에 누구나 물리적으로 접근해 조작 가능 |

<aside>취약점 해결 방법과 경량 보안</aside>

- 출고 시 기본 계정·비밀번호를 반드시 변경
- 정기적인 펌웨어 업데이트 체계 마련
- 디바이스 간 통신에도 [[4. 도청_변조 위협과 대응|TLS]] 등으로 암호화 적용(자원 제약이 있다면 경량 암호화 알고리즘 채택)
- 디바이스별로 개별 인증서·키를 발급해 신원을 구분



<aside>디바이스 신원 관리</aside>

다수의 IoT 디바이스가 연동될 때 모든 디바이스가 같은 계정·키를 공유하면, 그중 하나만 탈취돼도 전체 시스템이 위험해진다. 디바이스별로 개별 인증서나 키를 발급해 두면, 하나가 탈취되더라도 피해 범위를 그 디바이스로 한정할 수 있다.

<aside>예시 — 로봇에 연결된 센서 게이트웨이 보안</aside>

**예시**: 로봇에 연결된 다수의 무선 센서가 하나의 게이트웨이를 통해 데이터를 모을 때, 게이트웨이의 기본 관리자 비밀번호를 그대로 두거나 센서-게이트웨이 간 통신이 암호화되지 않으면, 공격자가 게이트웨이를 장악해 로봇에 잘못된 센서값을 주입할 수 있다.

<aside>핵심 정리</aside>

- IoT 디바이스는 저전력·분산 배치·방치되기 쉬운 특성 때문에 기본 계정 미변경, 펌웨어 미업데이트, 평문 통신 같은 고유 취약점이 생기기 쉬움
- "자원이 제한적이니 보안을 생략한다"는 잘못된 대응 — 경량 암호화 등으로 보안은 반드시 적용
- 디바이스별 개별 인증서·키 발급으로 하나의 탈취가 전체로 번지지 않게 해야 함
