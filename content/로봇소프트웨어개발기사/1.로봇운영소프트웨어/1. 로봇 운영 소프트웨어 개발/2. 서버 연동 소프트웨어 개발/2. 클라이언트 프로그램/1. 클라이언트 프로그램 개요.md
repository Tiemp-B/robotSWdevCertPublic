# Summary

**클라이언트 프로그램**은 사용자와 직접 상호작용하며 UI를 제공하고, 서버에 요청을 보내 응답을 받아 사용자에게 표시하는 프로그램이다. [[1. 서버 프로그램 개요|서버]]가 자원을 중앙에서 관리·중개하는 쪽이라면, 클라이언트는 **화면 렌더링과 사용자 입력 처리**를 담당하는 반대편 축이다. 이 페이지는 이후 페이지들(REST API, AJAX, WebSocket, 쿠키, 예외 처리)의 허브 역할을 한다.

# Notes

<aside>클라이언트의 역할</aside>

| 역할 | 설명 |
|---|---|
| UI 제공 | 사용자가 보고 조작할 화면(대시보드, 앱 등)을 렌더링 |
| 요청 생성 | 사용자의 입력·행동을 서버가 이해할 수 있는 요청으로 변환 |
| 응답 수신·가공·표시 | 서버 응답을 받아 사람이 이해하기 쉬운 형태로 가공해 화면에 표시 |
| 로컬 상태 관리 | 입력 중인 값, 화면 전환 상태 등 서버에 보내기 전의 임시 데이터 관리 |

<aside>클라이언트의 특성</aside>

- 사용자마다 각자의 기기에서 **개별적으로 실행**된다 — 서버처럼 하나의 프로세스가 여러 사용자를 동시에 처리하는 구조가 아니다
- 서버에 비해 상대적으로 **자원 제약**이 있을 수 있다(모바일 기기 등)
- 서버와 달리 **항상 연결을 대기할 필요가 없다** — 사용자가 조작할 때, 또는 필요한 시점에만 서버에 연결하면 된다

<aside>서버-클라이언트 역할 분담 재확인</aside>

| 항목 | 서버 | 클라이언트 |
|---|---|---|
| 핵심 역할 | 자원 관리, 요청 처리, 데이터 중개 | UI 제공, 사용자 입력 처리 |
| 실행 방식 | 상시 대기, 다중 사용자 동시 처리 | 사용자별 개별 실행 |
| 화면 렌더링 | 담당하지 않음 | 담당 |

<aside>클라이언트 프로그램의 유형</aside>

| 유형 | 예시 |
|---|---|
| 웹 클라이언트 | 브라우저에서 동작하는 웹 대시보드 |
| 네이티브 앱 클라이언트 | 데스크톱/모바일 전용 애플리케이션 |
| 임베디드 클라이언트 | 로봇 자체에 내장되어 관제 서버와 통신하는 소형 클라이언트 |

<aside>예시 — 로봇 관제 대시보드 클라이언트</aside>

**예시**: 운영자가 브라우저로 접속하는 로봇 관제 대시보드는 로봇 목록과 상태를 화면에 그리고(UI 제공), 운영자가 정지 버튼을 누르면 이를 서버 요청으로 변환하며(요청 생성), 서버로부터 받은 처리 결과를 다시 화면에 반영한다(응답 가공·표시). 로봇의 실시간 폐루프 제어나 다수 운영자의 요청을 동시에 받는 것은 클라이언트가 아니라 서버·로봇 제어기의 몫이다.

<aside>핵심 정리</aside>

- 클라이언트는 **UI 제공·요청 생성·응답 가공/표시·로컬 상태 관리**를 담당 — 서버의 "자원 관리·요청 처리" 역할과 대비
- 클라이언트는 사용자마다 개별 실행되며, 서버와 달리 항상 연결을 대기할 필요가 없음
- 웹/네이티브 앱/임베디드 클라이언트 등으로 유형을 나눌 수 있음
