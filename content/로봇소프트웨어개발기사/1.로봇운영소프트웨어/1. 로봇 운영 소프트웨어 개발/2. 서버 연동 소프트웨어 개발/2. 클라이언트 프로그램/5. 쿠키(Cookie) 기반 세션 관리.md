# Summary

**[[쿠키(Cookie)|쿠키]]**는 서버가 클라이언트(브라우저)에 직접 저장하도록 지시하는 작은 데이터 조각으로, **클라이언트 측에 데이터 자체를 저장**한다는 점에서 [[3. 세션과 상태 관리|서버 측에 상태를 저장하고 식별자만 전달하는 세션]]과 대비된다. 쿠키는 용량과 만료 시간에 제약이 있으며, 저장되는 정보의 성격에 따라 보안 속성도 함께 고려해야 한다.

# Notes

<aside>쿠키 개념</aside>

서버가 HTTP 응답 헤더(`Set-Cookie`)로 클라이언트에 저장을 지시하면, 브라우저는 이후 같은 서버로 보내는 모든 요청에 그 쿠키를 자동으로 함께 전송한다.

<aside>쿠키의 용량과 만료 제약</aside>

| 제약 | 내용 |
|---|---|
| 용량 제한 | RFC 6265 기준 브라우저가 최소 보장해야 하는 값이 쿠키당 약 **4KB** — 실무에서 흔히 인용되는 상한선이며, 큰 데이터를 담기엔 부적합 |
| 만료 시간 | `Expires`(절대 시각) 또는 `Max-Age`(상대 시간)로 설정. 설정하지 않으면 "세션 쿠키"가 되어 브라우저 종료 시 삭제됨 |

<aside>쿠키 속성</aside>

| 속성 | 목적 |
|---|---|
| Secure | HTTPS 연결에서만 쿠키를 전송 |
| HttpOnly | 자바스크립트(`document.cookie`)로 쿠키 값에 접근하지 못하게 막아 XSS로 인한 탈취를 완화 |
| SameSite | 다른 도메인으로의 쿠키 전송을 제한(Strict/Lax/None) — **SameSite=None으로 설정하려면 Secure도 함께 설정해야 한다** |

이 속성들이 구체적으로 어떤 공격(XSS, CSRF 등)을 막는지에 대한 심화 내용은 "3. 로봇 보안" 세세항목에서 다루며, 여기서는 쿠키 자체의 속성으로만 다룬다.

<aside>쿠키(클라이언트 저장) vs 세션(서버 저장)</aside>

| 항목 | 쿠키 | 세션 |
|---|---|---|
| 데이터 저장 위치 | 클라이언트(브라우저) | 서버 |
| 클라이언트가 보관하는 것 | 데이터 자체 | 세션 ID(식별자)뿐 |

다만 이 둘은 배타적이지 않다 — [[3. 세션과 상태 관리|세션 방식]]도 발급된 세션 ID 자체는 대개 쿠키에 담아 클라이언트에 전달하므로, **쿠키는 세션 ID를 나르는 운반 수단으로도 함께 쓰인다.**

<aside>쿠키의 한계</aside>

"쿠키에 민감한 정보를 그대로 저장해도 안전하다"는 옳지 않다 — 쿠키는 클라이언트에 그대로 노출되고 사용자가 직접 열람·조작할 수 있는 위치에 저장되므로, 민감한 정보는 쿠키에 직접 담기보다 서버 측에 두고(세션 방식) 클라이언트에는 식별자만 전달하는 편이 안전하다.

<aside>예시 — "로그인 상태 유지" 기능</aside>

**예시**: 사용자가 로그인 화면에서 "로그인 상태 유지"를 체크하면, 서버는 만료 시간을 길게 설정한 쿠키에 세션 ID를 담아 내려준다. 브라우저를 껐다 켜도 이 쿠키가 남아 있어, 서버는 요청에 담긴 세션 ID로 로그인 상태를 그대로 인식해 자동 로그인시킨다.

---

<aside>핵심 정리</aside>

- 쿠키는 **클라이언트 측에 데이터 자체를 저장**하며, 용량(약 4KB, RFC 6265 최소 보장치)과 만료 시간(Expires/Max-Age)에 제약이 있음
- Secure/HttpOnly/SameSite 등 속성으로 전송·접근 범위를 제한(SameSite=None은 Secure 필수)
- 쿠키(클라이언트 저장)와 세션(서버 저장)은 대비되는 개념이지만, 세션 ID 자체는 보통 쿠키로 운반됨
- 민감한 정보를 쿠키에 그대로 저장하는 것은 안전하지 않음
