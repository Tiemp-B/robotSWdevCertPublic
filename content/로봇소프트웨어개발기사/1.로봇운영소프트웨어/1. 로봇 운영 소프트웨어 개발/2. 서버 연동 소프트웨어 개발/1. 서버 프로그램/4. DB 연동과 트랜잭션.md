# Summary

서버는 데이터 정합성을 보장하기 위해 **[[트랜잭션(Transaction)|트랜잭션]]** 단위로 데이터베이스 작업을 처리하며, 트랜잭션은 **ACID**(원자성·일관성·고립성·지속성)를 만족해야 한다. 여러 트랜잭션이 동시에 수행될 때 서로 영향을 주지 않도록 보장하는 속성이 **고립성(Isolation)**이다. 또한 서버는 매 요청마다 DB 연결을 새로 맺는 대신 **[[커넥션 풀(Connection Pool)|커넥션 풀]]**로 연결을 재사용해 성능을 확보한다.

# Notes

<aside>트랜잭션과 ACID</aside>

**[[트랜잭션(Transaction)|트랜잭션]]**은 DB 상태를 변화시키는 하나의 논리적 작업 단위로, 안의 모든 연산이 전부 성공하거나 전부 실패해야 한다(all-or-nothing).

| 속성 | 의미 |
|---|---|
| 원자성(Atomicity) | 모든 연산이 전부 반영되거나 전부 반영되지 않음 |
| 일관성(Consistency) | 트랜잭션 전후로 DB가 제약조건을 만족하는 일관된 상태 유지 |
| 고립성(Isolation) | 동시 수행되는 트랜잭션들이 서로의 중간 상태에 영향받지 않음 |
| 지속성(Durability) | 커밋된 결과는 이후 장애가 발생해도 영구 보존 |



<aside>트랜잭션 격리 수준과 이상 현상</aside>

격리 수준은 SQL 표준상 아래 순서로 강해지며, 강할수록 정합성은 좋아지지만 동시 처리 성능은 낮아진다.

| 격리 수준 | 방지되는 이상 현상 |
|---|---|
| Read Uncommitted | 없음(Dirty Read 허용) |
| Read Committed | Dirty Read 방지 |
| Repeatable Read | Dirty Read + Non-repeatable Read 방지 |
| Serializable | Dirty Read + Non-repeatable Read + Phantom Read 모두 방지 |

- **Dirty Read**: 다른 트랜잭션이 아직 커밋하지 않은 데이터를 읽어버림
- **Non-repeatable Read**: 같은 조건으로 두 번 조회했는데 그 사이 다른 트랜잭션의 커밋으로 결과가 달라짐
- **Phantom Read**: 범위 조회 시 그 사이 다른 트랜잭션이 추가한 행이 새로 나타남

<aside>데이터베이스 커넥션 풀</aside>

매 요청마다 DB 연결을 새로 생성·종료하면 연결 수립 비용(TCP 연결, 인증 등)이 반복된다. **[[커넥션 풀(Connection Pool)|커넥션 풀]]**은 미리 일정 수의 연결을 만들어 두고 요청마다 빌려 쓰고 반환하는 방식으로, 연결 생성·해제 비용 절감, 서버·DB 자원 효율화, 동시 연결 수 제한을 통한 DB 과부하 방지를 목적으로 한다.

풀 크기를 너무 작게 잡으면 요청이 몰릴 때 연결 대기 병목이 생기고, 너무 크게 잡으면 DB 자원을 불필요하게 소모한다. 사용 후 연결을 반환하지 않아 풀이 고갈되는 **커넥션 누수(Connection Leak)**는 실무에서 흔한 버그이므로, 예외 발생 시에도 반환을 보장하는 처리가 필요하다.

<aside>예시 — 다수 로봇 상태 기록에서의 트랜잭션과 커넥션 풀</aside>

**예시**: 로봇의 위치와 배터리 잔량을 동시에 갱신해야 할 때, 이 두 값을 하나의 트랜잭션으로 묶지 않으면 위치만 갱신되고 배터리 값 갱신이 실패하는 불일치(원자성 위반)가 생길 수 있다. 각 요청은 커넥션 풀에서 연결을 짧게 빌려와 트랜잭션을 처리한 뒤 즉시 반환해, 수십 대 로봇의 동시 상태 갱신 요청에도 DB 연결이 고갈되지 않도록 한다.

<aside>핵심 정리</aside>

- ACID 중 "동시 수행 트랜잭션이 서로 영향받지 않는 것"은 **고립성(Isolation)**
- 격리 수준: Read Uncommitted < Read Committed < Repeatable Read < Serializable, 강할수록 이상현상 방지↑·동시성↓
- 커넥션 풀은 **연결 재사용으로 생성 비용을 줄이고 DB 과부하를 방지** — 커넥션 누수 주의
