# Summary

IoT 디바이스는 무선 구간의 특성상 언제든 연결이 끊기거나 지연될 수 있다. 로봇이 이런 디바이스들과 **일관된 데이터**를 유지하려면, 데이터가 도착한 순서를 올바르게 정렬하고, 유실·중복·지연에 대비하는 **동기화·신뢰성 확보 기법**이 필요하다.

# Notes

<aside>왜 신뢰성 확보가 필요한가</aside>

IoT 디바이스는 저전력·저대역폭 무선([[2. CoAP와 경량 IoT 프로토콜|CoAP]], [[3. LoRaWAN과 저전력 광역 통신|LoRaWAN]] 등)을 사용하는 경우가 많아, 유선 네트워크보다 **연결 끊김·지연·순서 뒤바뀜**이 훨씬 흔하게 발생한다. 이런 환경에서도 로봇이 여러 디바이스의 데이터를 올바르게 해석하려면 별도의 보완 기법이 필요하다.

<aside>타임스탬프 기반 정렬</aside>

각 디바이스가 데이터를 보낼 때 **측정 시각(타임스탬프)** 을 함께 담아 보내면, 네트워크 지연으로 도착 순서가 뒤바뀌더라도 로봇 쪽에서 실제 발생 순서대로 재정렬할 수 있다. 도착한 순서를 그대로 발생 순서로 오인하면, 오래된 값이 최신 값을 덮어써 잘못된 판단으로 이어질 수 있다.

<aside>중복 제거와 재전송 처리</aside>

신뢰성을 높이기 위해 디바이스가 확인(ACK)을 받을 때까지 같은 메시지를 재전송하는 경우, 수신 측에는 **동일한 메시지가 중복 도착**할 수 있다. 각 메시지에 고유 순번(시퀀스 번호)을 부여해, 이미 처리한 순번의 메시지는 무시하는 방식으로 중복을 걸러낸다.

<aside>오프라인 버퍼링과 재동기화</aside>

디바이스가 일시적으로 네트워크에서 끊기면, 그동안의 데이터를 유실하지 않고 **디바이스 자체 메모리에 임시 저장(버퍼링)** 했다가, 연결이 복구되면 밀린 데이터를 순서대로 전송해 로봇 쪽 상태를 다시 최신으로 맞추는 방식이다.

<aside>예시 — 연결이 불안정한 야외 센서와의 동기화</aside>

**예시**: 야외 로봇과 LoRaWAN으로 연결된 토양 센서가 통신 음영 지역을 지나며 잠시 연결이 끊긴다. 센서는 그동안의 측정값을 타임스탬프와 함께 내부에 저장해 두었다가, 연결이 복구되자 밀린 값들을 순서대로 전송한다. 로봇은 각 값의 타임스탬프를 기준으로 실제 발생 순서에 맞춰 상태를 재구성하고, 이미 수신했던 순번은 중복 처리하지 않는다.

---

<aside>핵심 정리</aside>

- IoT 디바이스는 유선보다 연결 끊김·지연·순서 뒤바뀜이 흔해, 타임스탬프 기반 정렬·중복 제거·오프라인 버퍼링 같은 보완 기법이 필요하다
- 타임스탬프로 실제 발생 순서를, 시퀀스 번호로 중복 메시지를 각각 처리한다
- 연결이 끊긴 구간의 데이터도 디바이스 버퍼링을 통해 복구 후 재동기화할 수 있다
