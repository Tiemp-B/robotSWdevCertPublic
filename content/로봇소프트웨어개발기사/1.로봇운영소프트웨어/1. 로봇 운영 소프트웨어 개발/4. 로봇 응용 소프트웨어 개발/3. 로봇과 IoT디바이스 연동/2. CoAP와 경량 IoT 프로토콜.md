# Summary

**[[CoAP(Constrained Application Protocol)|CoAP]]** 는 배터리·메모리가 매우 제한된 초저전력 IoT 디바이스를 위해 설계된 경량 통신 프로토콜이다. 웹의 HTTP와 비슷한 요청-응답 방식을 쓰면서도, 훨씬 가벼운 UDP 기반으로 동작해 자원이 부족한 디바이스에서도 사용할 수 있다.

# Notes

<aside>CoAP란</aside>

**[[CoAP(Constrained Application Protocol)|CoAP]]** (Constrained Application Protocol)는 이름 그대로 **제약(constrained)** 이 있는 디바이스와 네트워크를 위한 응용 계층 프로토콜이다. GET/POST/PUT/DELETE 같은 **HTTP와 유사한 REST 방식의 메서드**를 제공해, 웹 개발자가 익숙한 방식 그대로 IoT 디바이스와 통신할 수 있게 한다.

<aside>CoAP와 HTTP의 차이</aside>

| 항목 | HTTP | CoAP |
|---|---|---|
| 전송 계층 | TCP | UDP |
| 헤더 오버헤드 | 큼(텍스트 기반) | 매우 작음(4바이트의 이진 헤더) |
| 대상 | 일반 웹 서버·클라이언트 | 저전력·저메모리 IoT 디바이스 |
| 신뢰성 확보 방식 | TCP 자체의 재전송 | CoAP 자체의 확인(ACK) 메시지로 재전송 처리 |

CoAP는 UDP를 사용하지만, 메시지에 **Confirmable(확인 필요)** 표시를 해 두면 수신자가 ACK를 보내도록 요구해 신뢰성을 확보할 수 있다. "CoAP는 UDP 기반이므로 신뢰성 있는 전달을 전혀 보장할 수 없다"는 서술은 CoAP의 Confirmable 메시지 방식을 무시한 오답이다.

<aside>CoAP가 MQTT와 다른 점</aside>

MQTT는 [[발행-구독 모델(Publish-Subscribe)|발행-구독]] 방식으로 다수의 노드가 브로커를 통해 비동기로 통신하는 데 적합한 반면, CoAP는 **1:1 요청-응답 방식**으로 특정 디바이스에 직접 값을 요청하거나 설정을 변경할 때 적합하다. 로봇이 "센서 A의 현재 값을 알려줘"처럼 개별 디바이스에 직접 질의할 때는 CoAP가, 다수 센서의 데이터를 지속적으로 구독해 받을 때는 MQTT가 더 알맞다.

<aside>예시 — 로봇의 CoAP 활용</aside>

**예시**: 순찰 로봇이 복도를 지나며 각 구역의 온도 센서(CoAP 서버로 동작)에 `GET /temperature` 요청을 보내 현재 온도를 즉시 조회한다. 센서는 평소에는 아무 데이터도 보내지 않다가, 요청이 올 때만 응답하므로 배터리 소모를 최소화할 수 있다.

---

<aside>핵심 정리</aside>

- CoAP는 HTTP와 유사한 REST 방식이지만 UDP 기반의 매우 가벼운 헤더로 동작해 저전력·저메모리 디바이스에 적합하다
- Confirmable 메시지로 UDP 위에서도 신뢰성 있는 전달을 구현할 수 있다
- MQTT(발행-구독, 다수 노드의 지속적 구독)와 CoAP(1:1 요청-응답, 개별 조회)는 통신 패턴이 다르다
