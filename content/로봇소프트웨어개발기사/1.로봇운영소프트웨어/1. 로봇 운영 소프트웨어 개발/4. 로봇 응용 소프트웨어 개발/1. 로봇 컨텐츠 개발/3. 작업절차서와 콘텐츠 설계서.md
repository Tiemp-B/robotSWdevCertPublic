# Summary

작업절차서와 콘텐츠 설계서 작성은 ADDIE의 **개발** 단계에 해당하며, [[2. 콘텐츠 정의서와 시나리오 기획|시나리오]]를 구체적인 구현 문서로 다듬는 과정이다. 이후 **실행·평가** 단계에서는 프로토타입을 시험하고 사용자 대상 평가를 거치는데, 이때 **[[사용성 테스트(Usability Testing)|사용성 테스트]]**의 목적은 사전 정의된 성능 지표 확인이 아니라 **실제 사용자가 겪는 문제점을 발견해 개선 방향을 찾는 것**이다.

# Notes

<aside>작업절차서(개발 단계)</aside>

시나리오의 각 태스크(작업단위)를 정의하고, 이를 구현하기 위한 구체적인 기술·알고리즘 절차를 기술한 문서다. **설계는 하향식(Top-Down, 전체 구조에서 세부로)**, **개발은 상향식(Bottom-Up, 세부 구현을 먼저 완성해 전체로 조립)**으로 진행하며, 사용자와 직접 맞닿는 GUI/TUI 관련 부분을 최우선으로 개발한다.

<aside>콘텐츠 설계서</aside>

작업절차서를 종합해 씬(장면)별 시간·로봇 모션·음성 파일·음악/효과 등을 표 형태로 통합한 최종 문서다. 이 설계서를 기준으로 실제 콘텐츠 저작 작업이 이뤄진다([[4. 저작 소프트웨어와 메타모델]] 참고).

<aside>시험 및 평가(실행·평가 단계)</aside>

프로토타입을 실행해 설계서 충족 여부, 멀티미디어 동기화, 모션의 자연스러움 등을 기술적으로 점검한다(시험항목서). 오류가 있으면 작업절차서 단계로 되돌아가 재작업한다. 기술적 점검 이후에는 목표 사용자를 대상으로 시범 실행하고 정량·정성적 피드백을 모아 콘텐츠 평가서를 작성한다.

<aside>UX UI 평가 방법</aside>

| 방법 | 특징 |
|---|---|
| [[휴리스틱 평가(Heuristic Evaluation)\|휴리스틱 평가]] | 전문가 그룹이 빠르게 사용성 문제점을 도출 |
| 페이퍼 프로토타입 평가 | 간단한 프로토타입을 실제 사용자가 사용해보며 평가 |
| 선호도 평가 | 경쟁·비교 제품과 상대적으로 비교해 우열을 판단 |
| 성능 평가 | 객관적 수치 지표로 평가 — 감성적·사용성 측면은 반영하지 못함 |

<aside>사용성 테스트(Usability Testing)의 목적</aside>

사용성 테스트는 사전에 정해 둔 성능 지표를 확인하는 것이 목적이 아니라, **실제 사용자가 제품을 사용하는 과정에서 겪는 어려움과 문제점을 찾아내 개선 방향을 도출하는 것**이 주된 목적이다. "매출이나 시장성을 예측하는 것"이나 "개발자의 구현 역량을 평가하는 것"은 사용성 테스트의 목적이 아니다.

<aside>평가 절차의 3단계</aside>

**사전평가**(실험 동의·자격 확인·사전 설문·사전 훈련) → **본평가**(실제 실험 수행) → **사후평가**(설문 등으로 감성적·정성적 정보 수집) 순으로 진행하는 것이 일반적이다.

<aside>예시 — 로봇 드라마 프로토타입 시험</aside>

**예시**: 완성된 로봇 드라마 콘텐츠의 Scene 1을 시범 실행해 모션과 음성·효과음이 어긋나지 않는지 기술적으로 점검한 뒤, 목표 사용자(10세 이상) 몇 명을 대상으로 시범 관람시켜 "감동적이었는가", "지루하게 느껴진 구간이 있었는가" 같은 사용성·감성 피드백을 수집해 콘텐츠 평가서에 반영한다.

---

<aside>핵심 정리</aside>

- 작업절차서는 하향식 설계·상향식 개발로 진행하며, 콘텐츠 설계서는 씬별 요소를 통합한 최종 산출물이다
- 실행·평가 단계는 기술적 점검(시험항목서) 후 사용자 대상 평가(콘텐츠 평가서) 순으로 진행된다
- **사용성 테스트의 목적은 실제 사용 과정의 문제점 발견과 개선**이며, 성능 지표 확인이나 시장성 예측이 아니다
- 평가는 사전-본-사후 3단계로 이뤄지며, 사후평가에서 감성적 정보를 보완적으로 수집한다
