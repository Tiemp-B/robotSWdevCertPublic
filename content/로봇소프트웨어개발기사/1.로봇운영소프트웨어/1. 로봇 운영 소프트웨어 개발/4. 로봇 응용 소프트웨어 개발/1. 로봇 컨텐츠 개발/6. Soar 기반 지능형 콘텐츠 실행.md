# Summary

단순한 스크립트만으로는 예기치 못한 상황(예: 로봇 유형의 갑작스러운 전환)에 유연하게 대응하기 어렵다. 이런 문제를 해결하기 위해 인공지능 인지 아키텍처인 **[[Soar]]** 를 활용해 메타모델을 해석·실행하는 지능형 콘텐츠 실행 소프트웨어를 만들 수 있다. (별개로 보안 오케스트레이션, 자동화, 대응을 의미하는 SOAR도 있으니 유의한다)

# Notes

<aside>왜 지능형 실행 소프트웨어가 필요한가</aside>

단순 스크립트는 정해진 순서대로만 동작해, 예상하지 못한 상황(예: 이족보행 로봇이 갑자기 바퀴형 베이스로 바뀐 경우)에 유연하게 대응하기 어렵다. Soar 같은 AI 에이전트 아키텍처를 활용하면 상황에 맞는 대안을 스스로 탐색·선택할 수 있다.

<aside>Soar 아키텍처 개념</aside>

**state**(상태), **operator**(연산자), **result**(결과)를 기반으로 동작하는 인공지능 에이전트 아키텍처다.

<aside>Soar의 장기 기억 구조</aside>

| 기억 유형 | 내용 |
|---|---|
| 제작 메모리 | 절차적 지식(어떻게 하는가) |
| 시맨틱 메모리 | 사실적 지식 — 메타모델이 여기에 저장됨 |
| 일화성 메모리 | 과거에 겪은 경험 |

<aside>로봇 콘텐츠 맥락에서의 Soar 요소</aside>

| 요소 | 로봇 콘텐츠에서의 의미 |
|---|---|
| state | 현재 실행 경과시간·모션·재생 상태 |
| operator | 타임라인·이벤트에 따라 호출할 라이브러리·함수·파일 |
| result | 자연스럽고 만족스러운 콘텐츠 구현(시청 만족도) |

<aside>Soar 결정 사이클(개념)</aside>

입력(경과시간·상호작용 확인) → 상태 정교화(현재 상황 파악) → 연산자 제안·평가(다음 동작 후보 탐색, 없으면 대안 탐색) → 연산자 선택(가장 적합한 것 선택) → 연산자 적용(로봇에 명령 전송) → 출력(실행) 순으로 반복되는 흐름이다.

<aside>예시 — 로봇 유형 전환 대응</aside>

**예시**: 원래 이족보행으로 걷는 모션을 재생하려 했으나 로봇이 바퀴형 베이스로 교체된 상황을 감지하면, Soar 에이전트가 걷기 모션 대신 바퀴 구동 함수를 대안으로 제안·선택해 콘텐츠가 끊기지 않고 이어지도록 한다.

---

<aside>핵심 정리</aside>

- 단순 스크립트로는 예기치 못한 상황에 대응하기 어려워, Soar 같은 AI 에이전트 아키텍처로 메타모델을 해석·실행한다
- Soar는 state·operator·result를 기반으로 동작하며, 메타모델은 시맨틱 메모리에 저장된다
- Soar 결정 사이클은 입력 → 상태 정교화 → 연산자 제안·평가·선택·적용 → 출력의 흐름을 반복한다
