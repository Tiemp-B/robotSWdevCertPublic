# Summary

로봇 콘텐츠 개발은 **ADDIE(분석-설계-개발-실행-평가)** 모델을 따르며, 이 페이지는 그중 **분석**(콘텐츠 정의서)과 **설계**(시나리오 기획) 단계를 다룬다. 이 과정에서 로봇의 기능이 아니라 **사용자가 실제로 로봇을 사용하며 느끼는 경험(UX)**을 중심에 두고 요구사항을 도출하는 것이 핵심이다.

# Notes

<aside>로봇 콘텐츠의 구성과 종류</aside>

로봇 콘텐츠는 멀티미디어 데이터(영상·음원·이미지) + 로봇 동작 + 메타모델(시나리오 기반 실행 절차서)이 결합되어 사람에게 서비스·스토리·메시지를 전달하는 것이다. 서비스 형태에 따라 **정보·홈케어·맞춤형·기본·교육·오락·가사·감성·로봇기능·기관정보** 서비스 등으로 분류되며, 실제로는 교사보조·안내/홍보·보안·외식 도우미 서비스 같은 형태로 구현된다.

<aside>ADDIE 모델과 산출 문서</aside>

| 단계 | 산출 문서 |
|---|---|
| 분석 | 로봇 콘텐츠 정의서 |
| 설계 | 실행 시나리오 기획 |
| 개발 | 작업절차서·콘텐츠 설계서 |
| 실행 | 시험항목서 |
| 평가 | 로봇 콘텐츠 평가서 |

<aside>로봇 콘텐츠 정의서(분석 단계)</aside>

서비스 분야, 사용자 특성(성별·연령·선호도), 목표·요구사항·기대효과를 정의한다. 로봇을 의인화하는 콘텐츠라면 로봇의 신상특성(성별·나이·성격 등)과 의사소통 방식(언어/준언어/비언어)도 함께 정의한다.

<aside>UX·UI 개념과 사용자 중심 설계</aside>

**[[UX(User Experience)|UX]]**는 사용자가 대상물을 사용하며 직간접적으로 느끼는 경험(신체적 반응이나 선호도·사용성 같은 심리적 정도)을 체계적으로 설계하는 과정이다. **[[UI(User Interface)|UI]]**는 사용자가 그 대상을 쉽게 조작할 수 있도록 돕는 인터페이스다. UX 설계에서 가장 중요하게 고려해야 할 것은 **로봇의 기능이나 개발자의 구현 편의가 아니라, 사용자가 실제 작업 환경에서 무엇을 필요로 하는지(사용자 중심 설계)**다 — 로봇의 구조·기능에서 UX 요구사항을 도출하고, 사용자와 작업 환경을 고려해 로봇이 수행할 작업을 분석하는 것이 그 출발점이다. "개발자가 구현하기 쉬운 방식을 최우선으로 고려한다"는 서술은 UX 설계 요소로 적합하지 않다.

<aside>접근성(Accessibility) 고려사항</aside>

**[[접근성(Accessibility)|접근성]]**은 연령·장애 여부 등 신체적·인지적 특성이 서로 다른 다양한 사용자 모두가 사용할 수 있도록 설계하는 것이다. "표준적인 단일 사용자만을 기준으로 설계하고 예외적인 사용자는 고려하지 않는다"는 서술은 접근성 설계 요소로 적합하지 않다.

<aside>정보 계층 구조의 네 가지 유형</aside>

수집된 UX 요구사항은 정보 간 상관관계를 파악해 계층 구조로 정리한다.

| 유형 | 특징 |
|---|---|
| 계층 구조 | 상위·하위 정보가 인과관계로 연결(조직도형) — 가장 대표적이고 쉬운 방법 |
| 계열 구조 | 정보를 하나씩 순차적으로 배열(제품 설명서형) |
| 그리드 구조 | 계층+계열을 합친 형태(포털 사이트형) — 가장 널리 쓰임 |
| 네트워크 구조 | 비선형적으로 복잡하게 얽힌 형태 — 가장 유연하지만 가장 어려움 |

<aside>시나리오 기획(설계 단계)</aside>

시놉시스(제목·주제·의도·장르·등장인물·줄거리) 작성 → 메시지 시나리오(플롯) 설계 → 스토리보드(입출력 방식, 언어/준언어/비언어 메시지, 세부 시나리오) 작성 순으로 진행한다.

<aside>액션 플로우(참고 개념)</aside>

**[[액션 플로우(Action Flow)|액션 플로우]]**(태스크 플로우라고도 함)는 시나리오를 기반으로 특정 기능을 수행하는 절차의 순서를 플로우 차트처럼 도식화한 것이다. 다음 페이지의 작업절차서·콘텐츠 설계서로 구체화되기 전, 기능별 흐름을 미리 정리하는 단계로 이해하면 된다.

<aside>예시 — 로봇 드라마 "로보라마" 기획</aside>

**예시**: 가족애를 주제로 한 오락 서비스 로봇 드라마를 기획한다면, 10세 이상 사용자를 대상으로 정의서를 작성하고 휴머노이드 로봇을 플랫폼으로 선정한 뒤, "상사에게 질책받는 직장인이 가족의 위로로 극복한다"는 시놉시스와 세부 대사·지문을 담은 스토리보드를 작성한다.

<aside>핵심 정리</aside>

- 로봇 콘텐츠는 멀티미디어·로봇 동작·메타모델의 결합이며, ADDIE 모델(분석-설계-개발-실행-평가)을 따라 개발된다
- UX 설계에서 가장 중요한 것은 **사용자 중심 설계**이며, 접근성은 다양한 사용자를 배려하는 설계 원칙이다
- 정보 계층 구조는 계층·계열·그리드·네트워크 네 가지 유형이 있다
- 시나리오는 시놉시스 → 메시지 시나리오 → 스토리보드 순으로 구체화된다
