## 학습 1. 로봇 콘텐츠 설계서 작성하기 (1-1)

### 학습 목표
- 로봇 콘텐츠 구성 요소에 따라 콘텐츠 정의서 작성
- 서비스 형태별 시나리오 기반 작업 단위 정의
- 시나리오에 따른 저작·실행 작업 절차서 작성
- 실행 시나리오 기획 및 콘텐츠 설계서 작성

### 필요 지식
**1. 로봇 콘텐츠**
- **정의**: 동영상·음원·이미지 등 멀티미디어 데이터와 로봇의 모션·재생·디스플레이 기능이 결합되어 사람에게 서비스/스토리/메시지를 전달하는 것 (한정혜, 2011: "로봇에 탑재되어 로봇이 외부와 상호작용하는 데 필요한 모든 표현의 체계")
- **구성 요소**: 멀티미디어 데이터(파일) + 로봇 동작 + 메타모델(시나리오 기반 실행 절차서). 현은자 외(2009) 분류: 로봇의 행동(제스처·이동·상호작용), 명령/작업 처리(태스크·시나리오·지능·상황인지), 멀티미디어 콘텐츠(플래시·영화·음악)
- **종류**(오상록, 2008): 정보/홈케어/맞춤형/기본/교육/오락/가사/감성/로봇기능/기관정보 서비스 등. 실제 사례: 교사보조, 안내/홍보, 보안, 외식 도우미 서비스

**2. 개발 과정 (ADDIE 모델 기반: 분석-설계-개발-실행-평가)**
| 단계 | 산출 문서 |
|---|---|
| 분석 | 로봇 콘텐츠 정의서 |
| 설계 | 실행 시나리오 기획 및 작업단위 정의 |
| 개발 | 작업절차서 및 콘텐츠 설계서 |
| 실행 | 시험항목서 |
| 평가 | 로봇 콘텐츠 평가서 |

- **(1) 로봇 콘텐츠 정의서(분석)**: 서비스 분야, 사용자 특성(성별·연령·선호도·사용특성), 목표·주제·요구사항·기대효과 정의. 의인화 시 로봇의 신상특성(성별·나이·국적·성격·가치관·직업 등)도 정의. 의사소통 방식은 언어/준언어(음색·고저·리듬·속도)/비언어(응시·표정·몸짓·신체접촉) 중 선택. 이후 적합한 하드웨어/소프트웨어를 갖춘 로봇 플랫폼 선정, 비용·인원·기간 산정.
- **(2) 시나리오 기획(설계)**: 시놉시스(제목·주제·의도·장르·등장인물·줄거리) 작성 → 메시지 시나리오(플롯) 설계 → 스토리보드(입출력 방식, 언어/준언어/비언어 메시지, 환경, 상대방 포함 세부 시나리오) 작성
- **(3) 작업 절차서(개발)**: 태스크별 작업단위 정의 후 로봇공학 기술/알고리즘 작업절차서 작성. 설계는 하향식(Top-Down), 개발은 상향식(Bottom-Up). GUI/TUI 관련 부분을 최우선 개발.
- **(4) 콘텐츠 시험·평가서(실행 및 평가)**: 프로토타입 실행, 설계서 충족 여부·멀티미디어 동기화·모션 자연스러움 등 기술적 점검, 오류 시 작업절차서로 회귀. 콘텐츠 평가서로 목표 사용자 대상 시범 실행, 전문가 사용자경험 평가, 정량·정성적 피드백으로 지속 개선.

### 수행 내용
- **재료·자료**: 로봇 콘텐츠 요구사항 정의서, 로봇 하드웨어 사양서, 로봇 SW 플랫폼 설명서, 로봇 기능 정의서
- **기기(장비·공구)**: 컴퓨터, 프린터, 인터넷, 문서작성 SW
- **안전·유의사항**: 사용자 안전과 편의성 우선 고려, 사용자 요구·시나리오 적극 수용

**수행 순서**
1. **콘텐츠 정의서 작성 및 플랫폼 선정**: 정의서 양식(서비스분야, 사용자특성, 콘텐츠특성, 로봇특성, 메시지전달방식)에 작성. 예시로 로봇드라마 "로보라마"를 오락서비스로 정의(10세 이상 대상, 가족애 주제, 자연스러운 동작 요구). 휴머노이드 로봇이 가장 적합함을 결정. 개발 비용·인원·기간 산정.
2. **시놉시스 및 시나리오 작성**: 예시작 "아버지의 이름으로"(직장인 배대리가 상사 최과장에게 질책받고 가족의 위로로 극복하는 6개 씬 구성 드라마) 시놉시스 및 Scene 1(직장 상사에게 질책받는 장면) 상세 대사·지문 작성 예시 제공.
3. **작업절차서 및 콘텐츠 설계서 작성**: Scene 1 작업단위 분류(① 로봇 전신모션: 팔 휘두르기·전화받기·걷기·앉기/일어서기·무릎꿇기 등, ② 음성: TTS로 wav/mp3 제작, ③ 음향효과: 전화벨·배경음악). 작업 흐름도(모션 만들기→대사 음성파일 생성→음향효과 준비→동기화) 및 모션 만들기 작업절차서(구현 특징 파악→편집기 실행→관절각 데이터 저장→재생 확인, ROBOTIS-OP 액션에디터 예시) 작성. 최종 로봇 콘텐츠 설계서(씬별 시간·로봇모션·음성파일·음악/효과·눈LED를 표 형태로 통합)를 완성 — Scene1 기준 모션 10개, 음성파일 10개, 음악/음향효과 4개 산출.

### 교수·학습 방법 요약
- 로봇 콘텐츠 정의/구성요소/종류 설명, 대표 콘텐츠 영상 시청, 조별(5~6명) 주제 선정, 멀티미디어 개발단계 비교 설명, 조별 정의서/절차서/설계서 작성 실습

### 평가
- **평가방법**: 포트폴리오, 서술형 시험, 사례연구, 구두발표 (각각 상/중/하 성취수준으로 콘텐츠 정의서·작업단위정의·작업절차서·설계서 작성 능력 평가)
- **피드백**: 자료 품질 비교공유(포트폴리오), 필수/선택 구분 서술형 문제(시험), 우수사례 공유(사례연구), 전원 참여 개선방안 논의(구두발표)

## 학습 2. 로봇 콘텐츠 개발하기 (2-1)

### 학습 목표
- 콘텐츠 개발 계획 수립, 저작 환경(OS·API·SDK) 구축
- 웹/앱 콘텐츠 결정 및 개발환경 설정
- 메타모델 정의(타임라인/이벤트 기반), 모션-멀티미디어 동기화, 테스트·수정

### 필요 지식
**1. 로봇 콘텐츠 메타모델**: 멀티미디어와 로봇 동작을 시나리오 기반으로 실행하기 위한 절차서

**로봇 콘텐츠 저작 소프트웨어**
- **OPRoS**: 2007년 개발 시작, 컴포넌트 기반 오픈소스 플랫폼. IDE + 프레임워크 + 서버 + 시험/검증도구 구성.
- **로보이드 스튜디오**: 2008년 첫 공개(현재 v1.4.2), GUI 기반, 타임라인 모션 에디터 + 콘텐츠 컴포우저 제공, 멀티미디어-모션 동기화 기본 제공.
- **스크립트 기반 저작**: GUI 소프트웨어가 없을 경우 텍스트 기반 메타모델 파일 작성.

**로봇 콘텐츠 실행 로봇 (휴머노이드)**
- 성인급: HONDA ASIMO, AIST HRP, KAIST HUBO, 로보티즈 똘망(THOR-MANG), Boston Dynamics ATLAS, IIT iCub, IRM TORO
- 어린이급: 알데바란 NAO, 로보티즈 ROBOTIS-OP
- 바퀴형 상체 휴머노이드: 소프트뱅크 PEPPER, 로보케어 실벗(SILBOT)
- 본 모듈은 **ROBOTIS-OP(OP2)** 사용

**ROBOTIS-OP2 사양**
- 전신 DARwIn-OP 후속(2011년 초판→2015년 OP2), 키 45cm, 무게 2.9kg
- OS: Lubuntu 12.04 32bit(Kernel 3.2.66)
- 하드웨어: CPU Intel Atom N2600 1.6GHz dual core, RAM 4GB, 저장 32GB mSATA, LAN 1Gbps, 제어기 CM-740, 액추에이터 DYNAMIXEL MX-28T 20개, 센서(3축 자이로·3축 가속도·버튼3개·마이크2개)
- SW: 데스크톱 PC에서 UltraVNC Viewer로 OP2 내장 PC 원격 접속·제어
- 프레임워크 구조: Namespace Robot 하위에 Platform Independent(Motion/Vision/Etc/H·W 클래스군)와 Platform Dependent(Linux 전용 클래스: LinuxActionScript, LinuxCM730 등) 구분

### 수행 내용
- **재료·자료**: 로봇 하드웨어/OS 사양서, 기능정의서, SW 플랫폼 설명서·개발 매뉴얼, 오픈소스 지재권 지침서
- **기기**: 컴퓨터, SDK, 프로그램 개발 SW, 컴파일러, 실행 로봇
- **안전·유의사항**: 저작권 및 오픈소스 지재권 규정 준수

**수행 순서**
1. **개발 계획 수립**: 로봇 선정(로보티즈 OP2), OP2에 우분투 리눅스 Hydro 설치(ROS 활용 위해), API 라이브러리(C++, sourceforge.net/projects/darwinop) 확보하여 저작 환경 구축.
2. **개발 계획서 작성**: 개발팀 구성(프로듀서·모션제작팀·멀티미디어제작팀). Scene1 모션 개발 계획표 작성 — 11종 모션, 10개 음성파일, 4개 음악/효과 파일. 예시 표에서 단위모션별 난이도(상/중/하)와 예상 제작시간 산정(합계 370분=6시간10분). 재사용 가능 단위 모션(예: "오른팔로 가리키기" 3회 재사용) 식별로 효율화. 음성은 성우 섭외 또는 TTS(Google gTTS, Mimic) 활용.
3. **로봇 콘텐츠 개발**:
   - **메타모델 작성**: 타임라인 기반 표(시간·모션·음성재생·배경음악/효과음재생·눈LED색깔)로 Scene1 전체 컷 순서 정리 (00:00:00~00:04:40).
   - **모션-멀티미디어 동기화**: 효과음/배경음악 파일 확보, 음성파일(TTS 또는 녹음) 생성 후 시간 측정, 액션에디터의 'Time(x8msec)' 값으로 모션 스텝 시간 조정(예: 125=1초), MATLAB 시뮬레이터는 목표시간 입력 시 전체 궤적 자동 조정. 컷별 재생-모션 동시 확인.
   - **테스트·수정**: 첫 씬에 대해 완료한 작업을 6개 씬 전체에 반복 수행, 동기화 테스트·수정.

### 교수·학습 방법 / 평가 / 피드백
- 교수: 개발계획 수립 지도, 운영체제·API·SDK 설명 및 설치법 안내(웹용/앱용, 편집기, 컴파일환경 고려), 메타모델 정의·동작추가 방법, 동기화 시간배정 확인
- 평가방법: 포트폴리오/서술형시험/사례연구/구두발표 (개발계획서·저작환경구축·메타모델·동기화·테스트 항목별 성취수준 평가)
- 피드백: 자료 품질 비교공유, 보고서 재제출 기회, 우수사례 공유, 프로젝트 발표 후 개선방안 논의

## 학습 3. 로봇 콘텐츠 실행 소프트웨어 개발하기 (3-1)

### 학습 목표
- 실행 개발계획 수립, 실행 소프트웨어 설계
- 메타모델 해석기로 로봇동작/멀티미디어 실행
- 실행 후 에러 테스트

### 필요 지식

**1. 휴머노이드 로봇용 실행 소프트웨어 제작**
- **소프트웨어 패키지 구조**: 김종욱(2015a)의 optWalk 패키지(이족보행 등 다양한 모션, C++)를 확장한 **roborama_op** 패키지 사용(휴머노이드파크 웹사이트 배포). 파일 관계: main.cpp/h(UI+메타모델 흐름제어) — MathFunc.cpp/h(수학함수) — RobotContentsMetaModel.soar(Soar 코드) — JointAngles.h(관절각 파라미터) — SelfMotion.cpp/h(동작 생성·제어) — robotisOP.cpp/h(규격·기구학/동역학) — MotionDB.h(관절궤적 데이터)

**2. 로봇 모션 생성 소프트웨어**
- **(가) 액션에디터**: 토크 OFF 상태로 손으로 직접 자세(모션 프리미티브) 제작 후 재생 시 자동 내삽(interpolation). 장점: 전문지식 불필요. 단점: 재사용/편집 불가, 다양한 보행특성 이족보행 불가, 모션-멀티미디어 연동 불가.
- **(나) 모델 기반 모션 생성**(김종욱 2015a): DH법+투영법으로 OP 전신 모델링, 토크/영모멘트점(ZMP) 계산. 시상면(θ)/관상면(φ)/횡평면(ψ) 상대관절변수 및 좌/우(L/R)별 절대관절변수(위첨자 L/R, 아래첨자 an/kn/hp/sh/el/nk) 정의.
  - **모션 프리미티브 기반 생성**: 최소 주요자세(예: 반가움 표시 = 직립→팔 수직→팔 좌측 15° 3자세)의 절대관절변수 벡터를 정하고 혼합다항식(blending polynomial)으로 궤적 생성 [식(1)~(3)]. 세그먼트/시간벡터/각도벡터/각속도벡터로 표현.
  - **동작 합성**: (1) 두 동작 연결(이어붙이기) — 시작시간=종료시간 일치, 각도차 보정, 각속도 일치 조건 적용 [식(4)(5)]. (2) 두 동작 동시 표현(합성) — 짧은 궤적을 긴 궤적 종료시간에 맞춰 시간비율로 늘여 합산 [식(6)(7)]. 손흔들기+인사 동작 예시 시뮬레이션.
  - **정서적 보행**: 하체 관절궤적을 PSO(입자군집최적화)로 최적화, ZMP 안정 궤적 추종. 시간축 조정계수(α, 클수록 속도↑)와 각도 배율계수(β, 클수록 보폭↑)로 슬픈/기쁜 상태 등 감정별 보행 파라미터 차별화(예시 값 제공) [식(8)]. 눈 LED 색상도 함께 조정(슬픔=흰색, 화남=붉은색). OP2 실물 실험 사진 예시.

**2. 로봇 콘텐츠 메타모델 구현 — Soar 활용**
- roborama_op는 리눅스 기반이라 스크립트 기반 메타모델 작성에 적합. 예기치 못한 상황 대응 위해 단순 스크립트가 아닌 인공지능 에이전트 아키텍처 **Soar**(state, operator, result) 사용 (작업지능 소프트웨어 개발 학습모듈 LM1903080308 참조).
- Soar 장기기억: 제작 메모리, 시맨틱 메모리, 일화성 메모리. 메타모델은 시맨틱 메모리에 저장, 제작 메모리와 연결.
- **Soar 요소 해석**: state=현재 실행 경과시간/모션/재생 상태, operator=타임라인/이벤트에 따른 라이브러리·함수·파일 호출, result=자연스럽고 극적인 콘텐츠 구현을 통한 시청 만족도.
- **Soar 결정 사이클**: ① 입력(경과시간/상호작용) ② 상태 정교화(현재 컷 상태 확인, WME 수정) ③ 연산자 제안·평가(다음 모션/파일 조회, 없으면 대체안 검색·평가 — 예: 이족보행→모바일베이스 전환 감지 시 걷기 모션 대신 바퀴구동 함수 제안) ④ 연산자 선택(선호도 기반 최적 모션·음성 선택) ⑤ 연산자 적용(OP2로 명령 전송) ⑥ 출력(모션 실행 및 재생)

## 학습 4. 로봇 콘텐츠 저작 도구 개발하기 (4-1)

### 학습 목표

### 필요 지식 — 로봇 콘텐츠 가상 플랫폼

**1. Gazebo를 이용한 실행**
- Gazebo: 멀티로봇 실내외 시뮬레이터(gazebosim.org). 물리엔진(ODE/Bullet/Simbody/DART), 3D 그래픽, 다양한 센서(LRF·Kinect·카메라, 노이즈 포함), 플러그인, TCP/IP, 클라우드 시뮬레이션 지원.
- **실행 7단계**(그림 4-1): ① ROS 패키지 설치 및 Gazebo 연동(gazebo 설치확인→ros-*-gazebo-ros-pkgs 설치→roscore/gazebo 연동 확인) ② 로봇 모델링(URDF↔SDF 변환, `<gazebo>` 요소 추가, URDF 예제 코드 제시: base_link+wheel 조인트) ③ 센서 추가(Xacro 파일 수정, Hokuyo 레이저·카메라 부착 예시) ④ 맵 불러오기(gazebo_worlds 패키지, Menu-Save as로 가구 추가, gazebosim.org/models 활용) ⑤ 플러그인으로 로봇 움직이기(모션 프리미티브 기반 연속동작) ⑥ 메타모델 불러오기(soarwrapper 패키지로 ROS-Soar 연결, HRI 패키지 활용) ⑦ 멀티미디어 파일 불러오기(sound_play 패키지 활용, Gazebo 자체엔 재생기능 없음)

**2. MATLAB을 이용한 실행**
- **(1) 전역좌표계 변환**: 한 화면에 여러 로봇·가구를 배치하려면 각 개체의 지역좌표계를 전역좌표계(XYZ)로 동차변환행렬(homogeneous transformation matrix)로 매핑 [식(9)(11)]. 예시: 최과장 로봇, 배대리 로봇, 책상의 지역좌표계 원점 좌표와 단위벡터 기반 변환식.
- **(2) 멀티미디어 파일 재생**: MATLAB `audioread` + `sound` 함수로 wav/mp3 재생, 메타모델 파일 해당 시점에 배치하여 동기화.
