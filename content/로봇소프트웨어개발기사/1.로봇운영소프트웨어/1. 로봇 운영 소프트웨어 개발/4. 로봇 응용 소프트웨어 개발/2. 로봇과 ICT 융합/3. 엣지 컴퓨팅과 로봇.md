# Summary

[[2. 클라우드 컴퓨팅과 로봇|앞 페이지]]에서 본 클라우드는 강력하지만 네트워크 왕복 지연을 피할 수 없다. **[[엣지 컴퓨팅(Edge Computing)|엣지 컴퓨팅]]**은 클라우드까지 데이터를 보내지 않고, **로봇 근처(로봇 내부 또는 현장의 로컬 서버)에서 즉시 처리**하는 방식이다. 실시간성이 중요한 로봇 제어·안전 기능은 클라우드가 아니라 엣지에서 처리되는 것이 원칙이다.

# Notes

<aside>엣지 컴퓨팅 개념</aside>

데이터가 발생하는 곳(로봇, 센서, 현장 장비) 가까이에서 연산을 수행해, 클라우드까지 왕복하는 지연 없이 즉시 결과를 얻는 방식이다. "엣지(edge)"는 네트워크의 중심(클라우드)이 아니라 가장자리(현장)를 의미한다.

<aside>클라우드와 엣지의 비교</aside>

| 항목 | 클라우드 컴퓨팅 | 엣지 컴퓨팅 |
|---|---|---|
| 처리 위치 | 원격 데이터센터 | 로봇 내부 또는 현장 로컬 서버 |
| 지연시간 | 네트워크 왕복 지연 발생 | 매우 낮음(즉시 처리) |
| 연산 규모 | 대규모(제약 적음) | 상대적으로 제한적 |
| 네트워크 단절 시 | 기능 중단 위험 | 로컬에서 계속 동작 가능 |
| 적합한 용도 | 대규모 분석, 다수 로봇 데이터 통합 | 실시간 제어, 안전 정지, 즉각적 장애물 회피 |

<aside>로봇에서 엣지 컴퓨팅이 필요한 이유</aside>

로봇의 충돌 회피, 균형 유지, 비상 정지 같은 기능은 **수십~수백 ms 이내의 반응**이 요구된다. 이런 판단을 매번 클라우드로 보내고 응답을 기다리면 네트워크 지연·단절 위험 때문에 안전을 보장할 수 없다. 따라서 이런 기능은 로봇 자체 또는 현장의 엣지 서버에서 처리하고, 클라우드는 그보다 여유 있는 대규모 분석·장기 데이터 축적에 활용하는 **역할 분담**이 원칙이다.

<aside>포그 컴퓨팅 — 엣지와 클라우드 사이의 중간 계층</aside>

실제로는 엣지와 클라우드 두 계층만이 아니라, 그 사이에 **[[Fog Computing(포그 컴퓨팅)|포그 컴퓨팅]]**이라는 중간 계층을 두기도 한다. 여러 엣지 노드의 데이터를 모아 1차로 분석·집계한 뒤, 정말 필요한 것만 클라우드로 올려보내는 역할을 한다 — 엣지보다는 넓은 범위를, 클라우드보다는 낮은 지연을 제공하는 절충 지점이다. 다중 로봇 시스템에서는 여러 로봇이 매번 클라우드까지 조회하지 않고도 포그 계층에서 서로 데이터를 공유할 수 있다.

<aside>엣지-클라우드 하이브리드 구조</aside>

실무에서는 엣지와 클라우드를 배타적으로 선택하기보다, 계층적으로 함께 사용한다.

- **엣지**: 실시간 센서 처리, 즉각적인 제어·안전 판단
- **클라우드**: 엣지에서 처리한 요약 데이터의 장기 저장, 다수 로봇 데이터의 통합 분석, 대규모 모델 재학습

<aside>예시 — 협동 로봇의 안전 정지</aside>

**예시**: 협동로봇 근처에 작업자가 접근하면, 로봇에 내장된(엣지) 센서 처리 로직이 즉시 감지해 로봇을 즉각 정지시킨다. 이 판단을 클라우드 서버에 문의하고 응답을 기다렸다면, 통신 지연 동안 사고가 발생할 수 있다. 반면 하루 동안의 작업자 접근 패턴 통계는 클라우드로 전송해 안전 정책 개선에 활용한다.

---

<aside>핵심 정리</aside>

- 엣지 컴퓨팅은 로봇 가까이(로봇 내부/현장 로컬 서버)에서 즉시 처리해 지연을 최소화하는 방식이다
- 실시간 제어·안전 기능은 엣지에서, 대규모 분석·데이터 통합은 클라우드에서 처리하는 역할 분담이 원칙
- 포그 컴퓨팅은 엣지와 클라우드 사이에서 데이터를 1차 집계해 클라우드 부담을 줄이는 중간 계층이다
