# Summary

로봇에 인공지능(AI) 기능을 넣는 방법은 크게 두 가지다 — [[2. 클라우드 컴퓨팅과 로봇|클라우드]] 서버에서 대규모 모델을 돌려 결과만 받는 **클라우드 AI**와, 로봇 자체에 경량화된 모델을 올려 직접 추론하는 **[[온디바이스 AI(On-device AI)|온디바이스(엣지) AI]]** 다. 두 방식은 서로 배타적이지 않고, 로봇의 상황에 맞게 역할을 나눠 함께 쓰이는 경우가 많다.

# Notes

<aside>클라우드 AI 서비스</aside>

음성 인식, 자연어 처리, 대규모 이미지 인식처럼 **연산량이 크고 최신 모델이 필요한 AI 기능**을 로봇이 직접 수행하지 않고, 클라우드의 AI 서비스에 데이터를 보내 처리 결과만 받아오는 방식이다.

| 장점 | 설명 |
|---|---|
| 최신·고성능 모델 활용 | 로봇 하드웨어 성능과 무관하게, 클라우드의 대규모 모델을 그대로 활용 가능 |
| 지속적 개선 | 클라우드 쪽 모델만 업데이트하면 모든 로봇이 즉시 개선된 성능을 사용 |
| 로봇 경량화 | 로봇에 고성능 AI 연산 하드웨어를 탑재할 필요가 줄어듦 |

<aside>온디바이스 AI(엣지 AI)</aside>

로봇 자체에 경량화된 AI 모델을 올려, 네트워크 연결 없이도 **로봇 안에서 직접 추론**하는 방식이다.

| 장점 | 설명 |
|---|---|
| 낮은 지연시간 | 네트워크 왕복이 없어 즉시 결과를 얻을 수 있음 |
| 오프라인 동작 | 네트워크가 끊겨도 핵심 AI 기능이 계속 동작 |
| 프라이버시 | 민감한 데이터(영상, 음성 등)를 외부로 전송하지 않고 로봇 내부에서 처리 |

<aside>온디바이스 AI를 가볍게 만드는 방법 — 모델 경량화</aside>

로봇처럼 자원이 제한된 장치에 AI 모델을 올리려면 **[[모델 경량화(Model Compression)|모델 경량화]]**가 필요하다. 대표적으로 가중치를 더 적은 비트로 표현하는 **양자화(Quantization)**, 영향이 적은 가중치를 제거하는 **가지치기(Pruning)**, 큰 "교사 모델"의 출력을 작은 "학생 모델"이 모방하도록 학습시키는 **지식 증류(Knowledge Distillation)**가 있다. 이런 기법들을 거쳐야 비로소 로봇 내부의 제한된 하드웨어(엣지 AI 가속기 등)에서 실제로 추론이 가능한 크기가 된다.

<aside>두 방식의 선택 기준</aside>

**실시간성·오프라인 동작·프라이버시가 중요한 기능**(예: 즉각적인 장애물 인식, 개인정보가 담긴 음성 처리)은 온디바이스 AI로, **연산량이 크고 최신성이 중요하지만 약간의 지연은 허용되는 기능**(예: 복잡한 자연어 질의응답, 대규모 이미지 분류)은 클라우드 AI로 나누는 것이 일반적이다. "온디바이스 AI는 항상 클라우드 AI보다 정확도가 높다"는 서술은 온디바이스 AI가 모델 경량화로 정확도를 일부 희생하는 대신 지연·프라이버시 이점을 얻는다는 트레이드오프를 무시한 오답이다.

<aside>예시 — 음성 비서 로봇의 하이브리드 AI</aside>

**예시**: 서비스 로봇이 "정지"처럼 즉시 반응해야 하는 짧은 명령어는 온디바이스 AI로 즉시 인식해 처리하고, "오늘 날씨와 일정을 요약해서 알려줘"처럼 복잡한 자연어 질의는 클라우드 AI 서비스로 보내 답변을 받아온다.

---

<aside>핵심 정리</aside>

- 클라우드 AI는 최신·고성능 모델을 활용할 수 있지만 네트워크에 의존하고, 온디바이스(엣지) AI는 지연이 적고 오프라인·프라이버시에 유리하지만 모델이 경량화된다
- 경량화는 양자화(비트 수 축소)·가지치기(불필요한 가중치 제거)·지식 증류(작은 모델이 큰 모델을 모방)로 이뤄진다
- 두 방식은 배타적이지 않으며, 실시간성이 중요한 기능은 온디바이스, 연산량이 큰 기능은 클라우드로 역할을 나눠 함께 쓰는 것이 일반적이다
