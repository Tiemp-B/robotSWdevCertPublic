# Summary

ADC 드라이버는 **기준전압·데이터 정렬·채널·변환 모드**를 설정해야 하며, 스위치 입력에서 발생하는 채터링은 **디바운싱**으로 제거해야 한다.

# Notes

<aside>ADC 드라이버 구현 시 고려사항</aside>

| 고려 항목 | 내용 |
|---|---|
| 기준 전압(Reference) | AREF 핀 입력 전압·내부 기준 전압 등 중 무엇을 기준으로 변환할지 |
| 데이터 정렬 | 변환된 디지털 값을 레지스터에 좌측 정렬할지 우측 정렬할지 |
| 채널 선택 | 여러 아날로그 입력 핀 중 어떤 채널을 변환할지 |
| 변환 모드 | 필요할 때만 변환하는 단발(single) 모드로 할지, 계속 변환하는 프리러닝(free running) 모드로 할지 |
| 인터럽트 사용 여부 | 변환 완료를 인터럽트로 알릴지, 폴링으로 확인할지 |
| 분주비(prescaler) | ADC 클럭 속도(변환 속도)를 몇 분의 1로 낮출지 |

"ADC 드라이버 구현 시 고려해야 할 사항으로 적절하지 않은 것은 변환 완료 후 결과를 저장할 메모리 주소를 매번 사람이 프로그램 실행 중 수동으로 지정하는 것이다"라는 서술처럼, ADC 드라이버는 기준전압·정렬·채널·변환모드·인터럽트·분주비를 **사전에 레지스터로 설정**해두는 것이지, 실행 중 사람이 수동 개입할 대상이 아니다.

<aside>디바운싱(Debouncing)</aside>

기계식 스위치는 눌리거나 떼어질 때 접점이 순간적으로 여러 번 떨리는 **채터링(chattering)** 현상이 발생해, MCU가 하나의 버튼 입력을 여러 번의 입력으로 잘못 인식할 수 있다. 디바운싱은 이런 채터링을 제거하는 기법이다.

- **하드웨어 디바운싱**: 저항·커패시터로 구성된 RC 필터로 채터링의 고주파 성분을 걸러내고 직류 성분만 MCU에 전달
- **소프트웨어 디바운싱**: 신호가 바뀐 후 일정 시간(예: 수십 ms) 동안 값을 다시 확인해, 그 사이에 값이 안정적으로 유지되었을 때만 정식 입력으로 인정

"디바운싱을 구현하는 가장 적절한 방법은 스위치 신호가 변화하는 즉시 그 값을 그대로 최종 입력으로 확정하는 것이다"라는 서술은 오답이다 — 신호 변화 즉시 확정하면 채터링을 그대로 여러 번의 입력으로 오인하게 되며, 디바운싱은 오히려 **일정 시간 대기 후 안정된 값만 인정**하는 것이 핵심이다.

---

<aside>핵심 정리</aside>

- ADC 드라이버는 기준전압·정렬·채널·변환모드·인터럽트·분주비를 사전에 설정하는 것이지 실행 중 수동 개입 대상이 아니다
- 디바운싱은 신호 변화 즉시 확정하는 것이 아니라, 일정 시간 안정성을 확인한 뒤 입력을 확정하는 기법이다(하드웨어 RC필터 또는 소프트웨어 지연 확인)
