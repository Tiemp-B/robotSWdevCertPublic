# Summary

통신으로 수신되는 데이터는 폴링보다 빠르게 도착할 수 있어, 인터럽트로 즉시 저장해두는 버퍼가 필요하며 그 구조는 **스택(LIFO)·큐(FIFO)·링버퍼(원형 큐)**로 나뉜다.

# Notes

<aside>스택(Stack)</aside>

**나중에 들어간 데이터가 먼저 출력**되는 LIFO(Last In First Out) 구조다. 데이터를 넣는 것을 푸시(push), 꺼내는 것을 팝(pop)이라 하며, 주로 인터럽트나 함수 호출이 중첩될 때 이전 실행 위치를 저장하는 데 사용된다.

<aside>큐(Queue)</aside>

**먼저 들어간 데이터가 먼저 출력**되는 FIFO(First In First Out) 구조다. 통신 데이터 수신처럼 도착한 순서대로 처리해야 하는 경우에 적합하다. 다만 출력을 위한 버퍼 시작 주소가 고정(예: buffer[0])되어 있고, 입력 데이터 길이가 제공된 큐의 길이를 초과할 수 없다는 제약이 있다.

"큐(Queue)는 나중에 들어간 데이터가 먼저 출력되는 LIFO 구조의 버퍼다"라는 서술은 **스택**과 뒤바뀐 오답이다 — 나중에 들어간 데이터가 먼저 나오는 것은 스택이며, 큐는 먼저 들어간 데이터가 먼저 나오는 FIFO 구조다.

<aside>링버퍼(Ring Buffer)</aside>

큐의 마지막 공간과 처음 공간이 서로 연결된 것으로 가정하는 원형 구조다. 큐와 달리 두 개의 포인터(입력 위치 **pHead**, 출력 위치 **pTail**)를 사용하며, 버퍼 끝에 도달하면 나머지(modulo) 연산으로 처음 위치로 되돌아간다.

$$pHead = (pHead + 1) \bmod \text{BUFFER\_SIZE}$$

이 구조 덕분에 링버퍼는 수신 인터럽트 서비스 루틴이 저장하고, MCU가 적절한 간격으로 읽어내기만 하면 **수신 데이터 길이에 제한이 없이** 계속 순환하며 사용할 수 있다.

"링버퍼는 큐와 동일하게 데이터를 읽는 시작 주소가 항상 buffer[0]으로 고정되어 있다"라는 서술은 오답이다 — 읽는 주소가 고정된 것은 큐이며, 링버퍼는 **이전에 읽은 데이터의 다음 주소(pTail)**를 따라 계속 이동한다.

---

<aside>핵심 정리</aside>

- 스택은 LIFO(나중 데이터 먼저 출력), 큐는 FIFO(먼저 데이터 먼저 출력)이며 서로 반대다
- 링버퍼는 pHead·pTail 두 포인터로 원형 순환하며, 큐와 달리 읽기 시작 주소가 고정되지 않는다
