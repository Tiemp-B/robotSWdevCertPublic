# Summary

로봇 통신 프로토콜을 설계할 때는 **QoS(서비스 품질)**, 여러 센서 데이터의 **시간 동기화**, **보안**, 그리고 **실시간성 보장**을 함께 고려해야 한다.

# Notes

<aside>QoS(Quality of Service)</aside>

QoS는 통신 서비스의 품질(지연시간·대역폭·신뢰성 등)을 보장하는 정책이다. 로봇 통신 프로토콜 설계에서 QoS를 보장하기 위한 가장 중요한 요소는 **우선순위가 높은 데이터(제어 명령 등)를 먼저 처리하도록 보장하는 것**이다 — 모든 데이터를 동일한 우선순위로 처리하면, 덜 중요한 데이터가 중요한 제어 데이터의 지연을 유발할 수 있다.

<aside>센서 데이터의 시간 동기화</aside>

여러 센서에서 온 데이터를 함께 사용(센서 융합 등)하려면, 각 데이터가 **언제 측정되었는지**를 일치시켜야 한다. 이때 고려할 요소는 다음과 같다.

- 각 센서의 측정 시각(타임스탬프)을 정확히 기록
- 센서마다 다른 샘플링 주기·전송 지연을 보정
- 여러 장치 간 기준 시계(clock)를 일치시키는 동기화 프로토콜(예: NTP, PTP) 적용

<aside>보안 고려사항</aside>

로봇 소프트웨어의 통신 보안에서는 데이터의 기밀성(암호화), 무결성(변조 여부 확인), 인증(정당한 장치인지 확인) 등을 고려해야 한다. 통신 데이터의 압축률은 성능·저장 공간과 관련된 요소일 뿐, 기밀성·무결성·인증 같은 보안 요소와는 무관하다.

<aside>실시간성 보장 방법</aside>

통신 프로토콜에서 실시간성을 보장하려면 다음과 같은 방법을 사용한다.

- 우선순위 기반 스케줄링(중요 데이터를 먼저 전송)
- 정해진 시간 안에 전송을 완료하도록 하는 시분할(TDMA) 등 결정론적(deterministic) 접근 방식
- 인터럽트 기반 처리로 지연 최소화

모든 데이터를 무조건적인 폴링 방식으로만 처리하면 오히려 처리 지연을 유발할 수 있으므로, 실시간성 보장에는 위와 같은 우선순위 기반 스케줄링·결정론적 접근·인터럽트 활용이 더 적합하다.

전송 계층에서 실시간 제어 데이터에 가장 적합한 프로토콜을 고르는 문제(TCP/IP vs UDP)는 [[2. 원격제어 통신 프로토콜 개요|원격제어 통신 프로토콜 개요]](1과목)에서 이미 다뤘다 — 신뢰성을 우선하는 TCP/IP보다, 재전송·순서보장 절차를 생략해 지연시간을 최소화하는 **UDP**가 실시간 제어 데이터 전송에 더 적합하다.

---

<aside>핵심 정리</aside>

- QoS는 데이터 중요도에 따른 차등 우선순위 부여가 핵심이다
- 시간 동기화는 타임스탬프·샘플링 주기 보정·클록 동기화를 고려하며, 보안은 압축률이 아니라 기밀성·무결성·인증이 핵심이다
