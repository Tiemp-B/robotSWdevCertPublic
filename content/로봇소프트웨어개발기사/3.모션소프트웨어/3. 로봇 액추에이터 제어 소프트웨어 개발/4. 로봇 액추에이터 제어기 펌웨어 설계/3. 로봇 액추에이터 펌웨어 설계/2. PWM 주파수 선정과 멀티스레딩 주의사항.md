# Summary

모터 드라이버의 PWM 주파수는 너무 낮으면 소음·진동이, 너무 높으면 스위칭 손실이 커지므로 절충이 필요하며, 멀티스레딩 설계에서는 공유 자원 접근·우선순위 문제에 주의해야 한다.

# Notes

<aside>PWM 주파수 선정</aside>

모터 드라이버는 PWM(Pulse Width Modulation)의 듀티비를 조절해 모터에 인가되는 평균 전압(속도·토크)을 제어한다. PWM 주파수를 정할 때는 다음을 함께 고려해야 한다.

- **너무 낮은 주파수**: 가청 주파수 대역과 겹쳐 모터에서 소음(가청음)이 발생하고, 전류 리플이 커져 진동·발열이 늘어남
- **너무 높은 주파수**: 스위칭(On/Off 전환) 횟수가 늘어나 스위칭 손실이 커지고 드라이버 발열이 증가함

<aside>PWM 주파수와 분해능(해상도)의 트레이드오프</aside>

PWM 주파수는 타이머 클럭과 카운터로 만들어지며, 다음 관계를 가진다.

$$f_{PWM} = \frac{f_{clock}}{N_{counter} + 1}$$

타이머 클럭 $f_{clock}$이 고정된 상태에서 PWM 주파수를 높이려면 한 주기 안의 카운터 최대값 $N_{counter}$을 줄여야 하는데, 이는 듀티비를 표현할 수 있는 단계 수(분해능)가 줄어드는 것을 의미한다. 즉 **주파수를 높일수록 듀티비를 세밀하게 조절할 수 있는 분해능은 낮아진다**.

<aside>멀티스레딩 사용 시 주의사항</aside>

여러 스레드(태스크)가 동시에 실행되는 임베디드 펌웨어에서는 다음을 주의해야 한다.

- **공유 자원(경쟁 조건)**: 여러 스레드가 같은 변수·레지스터에 동시 접근하면 값이 꼬일 수 있어 [[3. 동기화 메커니즘(세마포어·뮤텍스·데드락)|동기화 메커니즘]]으로 보호해야 함(1과목에서 이미 다룸)
- **우선순위 설정**: 실시간성이 중요한 태스크(모터 제어 등)에 더 높은 우선순위를 부여해야 하며, 우선순위가 뒤바뀌면 제어 주기를 놓칠 수 있음
- **스택 크기**: 스레드마다 별도의 스택 공간이 필요하므로, 메모리가 제한된 임베디드 환경에서는 스레드 수·스택 크기를 신중히 설계해야 함
- **인터럽트와의 상호작용**: 인터럽트 서비스 루틴 안에서 공유 자원을 다룰 때는 일반 스레드와의 동기화에 특히 주의해야 함

<aside>예시 — 모터 드라이버 펌웨어 설계</aside>

**예시**: 소형 서보모터 드라이버는 가청 주파수 대역을 피하기 위해 PWM 주파수를 20kHz 이상으로 설정하되, 지나치게 높이면 스위칭 손실로 드라이버 발열이 심해지므로 20~30kHz 범위에서 절충점을 찾으며, 동시에 모터 제어 스레드에는 통신·로깅 스레드보다 높은 우선순위를 부여해 제어 주기를 안정적으로 지킨다.

---

<aside>핵심 정리</aside>

- PWM 주파수는 낮으면 소음·리플, 높으면 스위칭 손실·발열이 커지는 트레이드오프가 있어 절충이 필요하다
- PWM 주파수 = 타이머 클럭 ÷ (카운터 최대값+1)이며, 타이머 클럭이 고정이면 주파수를 높일수록 듀티비 분해능은 낮아진다
- 멀티스레딩에서는 공유 자원 보호, 실시간성에 따른 우선순위 차등, 스택 크기 관리에 주의해야 한다
