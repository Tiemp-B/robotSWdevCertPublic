# Summary

**정적 분석**은 프로그램을 실행하지 않은 상태에서 코드 자체를 검토해 결함을 찾는 방법으로, 사람이 직접 검토하는 코드리뷰와 자동화 도구를 이용한 정적 분석으로 나뉘며, 정해진 코딩 표준을 기준으로 삼는다.

# Notes

<aside>정적 분석의 두 방식</aside>

| 방식 | 특징 |
|---|---|
| 코드리뷰 | 사람(피어 리뷰·워크스루 등)이 직접 코드를 검토 — 참여자 역량에 따라 결과 편차가 큼 |
| 자동화 도구 | 코딩 규칙 위배, 실행 시간 오류(메모리 누수·널 포인터 참조 등), **[[순환 복잡도(Cyclomatic Complexity)\|순환 복잡도]]** (조건문·반복문 개수 기반 복잡도), 데드코드를 자동 검출 — 결과 편차가 거의 없음. 다만 정형화된 패턴의 오류는 잘 찾아내는 반면 프로그래머의 의도와 다른 논리 오류까지는 판단하지 못해 코드리뷰로 보완해야 함 |

<aside>실행 시간 오류(runtime error) 검출</aside>

정적 분석 도구는 프로그램을 실행하지 않고도 실행 시점에 발생할 수 있는 오류 유형을 코드 경로 추적으로 미리 찾아낸다. 대표적 유형(CWE-658/659 목록 기준)으로는 버퍼 오버런/언더런, 메모리 누수(Leak), 초기화되지 않은 변수(Uninitialized Variable), 널 포인터 역참조(Null Pointer Dereference), 데드락(Deadlock) 등이 있다.

<aside>코딩 표준(Coding Standard)</aside>

코딩 표준은 코드의 가독성·신뢰성 향상을 위해 정한 규칙의 집합이며, 산업·기관별로 다른 표준을 사용한다. 코딩 표준 위배 코드는 문법적으로는 정상이라 컴파일·실행에는 문제가 없을 수 있다.

| 표준 | 제정 주체 | 특징 |
|---|---|---|
| MISRA-C/C++ | 자동차산업소프트웨어신뢰성협회 | 자동차용 C/C++ 개발 표준, 규칙을 필수/요구/권고로 구분 |
| SEI CERT | 미국 CERT | 취약성 분석 기반, 안전한 코딩 방법 제시 |
| CWE-658/659 | MITRE | C/C++ 공통 취약 결함 목록(실행 시간 오류 분류 표준) |
| OWASP | 오픈소스 웹보안 프로젝트 | 웹 애플리케이션 보안 취약점(OWASP TOP 10) |
| DAPA SCR-G | 한국 방위사업청 | 무기체계 SW용 주석·명명·프로그램 작성 규칙 |

<aside>예시 — 정적 분석으로 찾은 결함</aside>

**예시**: `char* buf = new char[8]; strcpy(buf, str);` 같은 코드는 컴파일·실행에는 문제가 없지만, 정적 분석 도구는 `buf`에 대한 `delete` 누락(메모리 누수)이나 입력 문자열 길이에 따른 버퍼 오버플로우 가능성을 미리 경고할 수 있다.

---

<aside>핵심 정리</aside>

- 정적 분석은 코드리뷰(수동)와 자동화 도구로 나뉘며, 자동화 도구는 정형화된 오류는 잘 찾지만 논리 오류까지 완전히 잡아내지는 못한다
- 순환 복잡도는 조건문·반복문 개수 기반의 복잡도 지표이며, [[4. 동적 분석과 코드 커버리지|분기 커버리지]] 100%에 필요한 테스트 케이스 개수의 상한과 같다
- 코딩 표준(MISRA-C, CERT, CWE, OWASP, DAPA 등)은 문법 오류가 아니라 가독성·신뢰성을 위한 관례적 규칙이다
