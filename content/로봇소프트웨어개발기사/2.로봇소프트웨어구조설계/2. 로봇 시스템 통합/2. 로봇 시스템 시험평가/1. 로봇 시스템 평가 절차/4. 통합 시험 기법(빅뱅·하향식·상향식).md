# Summary

통합 시험(Integration Test)은 모듈이 결합되는 순서에 따라 **빅뱅·하향식·상향식** 기법으로 나뉘며, 하향식·상향식은 각각 스텁과 테스트 드라이버를 필요로 한다.

# Notes

<aside>통합 시험의 목적</aside>

단위 시험에서는 시험 대상 모듈을 다른 모듈로부터 분리하기 위해 테스트 드라이버(대상을 호출하는 가짜 상위 모듈)와 스텁(대상이 호출하는 가짜 하위 모듈)을 사용한다. 통합 시험은 이렇게 개별 검증된 모듈들을 실제로 결합했을 때, 모듈 간 상호작용(매개변수 전달, 데이터 손상, 호출 순서)에 문제가 없는지 확인하는 단계다.

<aside>통합 시험 기법 비교</aside>

| 기법 | 결합 순서 | 필요한 대체물 | 특징 |
|---|---|---|---|
| 빅뱅 | 모든 모듈을 한꺼번에 결합 | 없음 | 가장 빠르지만 오류 위치 추적이 어려움 |
| 하향식(top-down) | 최상위 모듈부터 하위로 점진적 결합 | 스텁(미구현 하위 모듈 대체) | 상위 제어 로직을 일찍 검증 |
| 상향식(bottom-up) | 최하위 모듈부터 상위로 점진적 결합 | 테스트 드라이버(상위 모듈 대체) | 하위 모듈(하드웨어 인터페이스 등)을 일찍 검증 |

<aside>통합 시험과 통합 설계의 관계</aside>

어떤 통합 시험 기법을 쓸지는 [[3. 인터페이스 설계와 통합 전략|통합 설계 단계에서 선택한 통합 전략]]과 직접 연결된다. 하드웨어 의존성이 큰 로봇 시스템에서는 하위 하드웨어 인터페이스를 먼저 검증할 수 있는 상향식이, 전체 제어 로직의 정합성을 먼저 확인하려면 하향식이 유리하다.

<aside>예시 — 로봇 팔 제어 소프트웨어의 통합 시험</aside>

**예시**: 로봇 팔의 최상위 "동작 시퀀스 관리" 모듈부터 시험하고자 한다면 아직 구현되지 않은 "관절 제어" 하위 모듈을 스텁으로 대체하는 하향식을 적용하고, 반대로 이미 완성된 "관절 제어"·"센서 읽기" 모듈부터 먼저 검증하고 싶다면 상위의 "동작 시퀀스 관리"를 테스트 드라이버로 대체하는 상향식을 적용한다.

---

<aside>핵심 정리</aside>

- 빅뱅은 오류 추적이 어렵고, 하향식은 스텁(하위 대체), 상향식은 테스트 드라이버(상위 대체)를 필요로 한다
- 통합 시험 기법 선택은 통합 설계 단계에서 정한 통합 전략과 연동된다
