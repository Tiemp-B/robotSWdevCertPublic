# Summary

시스템 통합(System Integration)은 독립적으로 개발·검증된 서브시스템들을 결합해 하나의 완결된 시스템으로 만드는 과정이며, 통합 설계 단계에서는 **무엇을 통합할지**와 **어떤 기준으로 통합의 성공을 판단할지**를 먼저 정의해야 한다.

# Notes

<aside>시스템 통합의 정의와 목적</aside>

시스템 통합이란 별도로 개발된 하드웨어 모듈, 소프트웨어 컴포넌트, 미들웨어, 외부 시스템(서버·클라우드)을 결합해, 개별 요소만으로는 달성할 수 없는 완전한 로봇 시스템의 기능을 구현하는 과정이다. 통합이 끝난 뒤에는 반드시 [[1. 로봇 시스템 평가 절차 개요\|통합 시험]]을 통해 결합 결과를 검증한다.

<aside>통합 대상</aside>

| 대상 | 예시 |
|---|---|
| 하드웨어 간 통합 | 액추에이터, 센서, 제어 보드 간 물리적·전기적 연결 |
| 소프트웨어 모듈 간 통합 | 미들웨어, 응용 소프트웨어, 라이브러리 간 결합 |
| 하드웨어-소프트웨어 통합 | 디바이스 드라이버를 통한 하드웨어 제어 |
| 외부 시스템과의 통합 | 서버, 클라우드, 타사 장비와의 연동 |

<aside>통합 설계 시 고려 요소</aside>

- **호환성(compatibility)**: 서로 다른 팀·업체가 개발한 모듈 간 데이터 형식·프로토콜이 맞아야 함
- **인터페이스 명세**: 각 서브시스템이 주고받는 데이터의 형식·순서·타이밍을 사전에 문서화([[3. 인터페이스 설계와 통합 전략|다음 페이지]] 참고)
- **성능**: 통합 후 지연시간(latency)·처리량(throughput)이 개별 모듈 요구 사항을 만족하는지
- **안전성**: 한 모듈의 오류가 전체 시스템에 연쇄적으로 전파되지 않도록 격리 — **[[서킷 브레이커(Circuit Breaker)|서킷 브레이커]]** 패턴이 대표적인 구현 방식으로, 특정 모듈 호출이 반복 실패하면 일시적으로 차단해 다른 모듈로의 연쇄 장애를 막고, 이후 자동으로 상태를 재확인해 복구되면 호출을 재개함
- **확장성·유지보수성**: 향후 모듈 교체·추가가 쉬운 구조

"로봇 시스템 통합 설계에서 가장 중요하게 고려해야 할 요소는 각 모듈을 개발한 순서다"라는 서술은 오답이다 — 통합 설계에서 중요한 것은 개발 **순서**가 아니라 모듈 간 **호환성·인터페이스·성능·안전성** 같은 결합 품질이다.

<aside>예시 — 로봇 팔과 비전 시스템의 통합</aside>

**예시**: 별도 팀이 개발한 로봇 팔 제어 모듈과 비전 인식 모듈을 통합할 때, 비전 모듈이 인식한 물체 좌표를 어떤 데이터 형식·주기로 팔 제어 모듈에 전달할지(인터페이스), 비전 처리 지연이 팔의 실시간 제어 주기를 넘지 않는지(성능), 비전 모듈이 다운되어도 팔이 안전하게 정지하는지(안전성)를 통합 설계 단계에서 미리 정의한다.

---

<aside>핵심 정리</aside>

- 시스템 통합은 하드웨어·소프트웨어·외부 시스템을 결합해 완전한 로봇 시스템을 만드는 과정이다
- 통합 설계에서는 호환성·인터페이스 명세·성능·안전성·확장성을 고려해야 하며, 개발 순서 자체는 핵심 고려 요소가 아니다
- 서킷 브레이커는 반복 실패하는 모듈 호출을 일시 차단해 연쇄 장애를 막는 안전성 확보의 구체적 구현 방식이다
