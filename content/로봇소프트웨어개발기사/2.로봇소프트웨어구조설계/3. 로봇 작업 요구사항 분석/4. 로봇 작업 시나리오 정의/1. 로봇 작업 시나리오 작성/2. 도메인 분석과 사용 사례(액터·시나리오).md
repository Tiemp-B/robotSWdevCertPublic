# Notes

<aside>도메인 분석</aside>

도메인이란 해당 소프트웨어의 적용 범위 또는 동작 범위를 말한다. 도메인 분석에는 다음 두 산출물이 포함된다.

- **도메인 사전**: 도메인 내에서 쓰이는 용어를 정의(명칭·타입·설명 또는 예시로 구성)
- **비즈니스 규칙**: 시스템이 반드시 지켜야 할 규칙·정책(고객 인터뷰, 매뉴얼, 업무 지시서 등을 통해 수집)

비즈니스 규칙이 문서로 관리되지 않으면, 규칙을 잘 아는 개발자가 퇴사했을 때 새 개발자가 그 규칙을 파악하는 데 큰 비용이 든다.

<aside>사용 사례(Use Case)의 핵심 용어</aside>

| 용어 | 정의 |
|---|---|
| 액터(Actor) | 시스템과 상호작용하는 외부 객체 — 사람, 사물(장애물), 다른 시스템 모두 가능 |
| 시나리오(Scenario) | 액터와 시스템 사이에 일어나는 일들을 사용자 관점에서 기술한 것(정상 흐름 + 오류·예외 흐름 포함) |
| 사용 사례(Use Case) | 하나 또는 여러 시나리오를 종합해 일반화한 것 — 개발자·고객 간 의사소통 수단 |

액터는 사용 사례에서 맡는 역할에 따라 **[[주 액터와 보조 액터(Primary·Secondary Actor)|주 액터(Primary Actor)와 보조 액터(Secondary Actor)]]** 로도 구분된다. 주 액터는 목표를 가지고 사용 사례를 시작(개시)시키는 액터이고, 보조 액터는 그 목표 달성을 위해 시스템이 도움을 요청하는 액터로 사용 사례를 직접 시작시키지 않는다.

<aside>사용 사례가 중요한 이유</aside>

사용 사례는 요구 분석 단계에서는 기능적 모델링의 단초를 제공하고, 설계 단계에서는 상세 설계 구성 요소가 되며, 테스팅 단계에서는 테스트 시나리오로 재사용된다 — 즉 요구 분석부터 테스팅까지 이어지는 길잡이 역할을 한다.

<aside>예시 — 재난 구조용 로봇의 액터와 사용 사례</aside>

**예시**: 재난 구조용 모바일 로봇이 단독으로 동작할 때는 "사용자"만 액터가 되지만, 장애물 감지·회피처럼 사용자 개입 없이 로봇 스스로 수행하는 사용 사례는 액터가 없을 수도 있다. "로봇 시동" 사용 사례는 사용자가 시동 버튼을 누르는 것이 시작 조건이고, "장애물 회피" 사용 사례는 초음파 센서가 장애물을 감지하는 것이 시작 조건이다.

---

<aside>핵심 정리</aside>

- 도메인 분석은 도메인 사전(용어 정의)과 비즈니스 규칙(지켜야 할 규칙)으로 구성된다
- 액터는 사람뿐 아니라 사물·다른 시스템도 될 수 있으며, 사용 사례는 요구분석-설계-테스팅을 잇는 길잡이 역할을 한다
- 주 액터는 사용 사례를 시작시키는 목표의 주체이고, 보조 액터는 시작시키지 않고 도움만 제공한다
