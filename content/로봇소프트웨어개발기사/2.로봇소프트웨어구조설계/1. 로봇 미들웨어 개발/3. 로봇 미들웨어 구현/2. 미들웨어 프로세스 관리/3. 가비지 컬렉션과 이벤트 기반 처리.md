# Summary

미들웨어가 장시간 안정적으로 동작하려면 더 이상 쓰지 않는 메모리를 회수하는 **[[가비지 컬렉션(Garbage Collection)|가비지 컬렉션]]**과, 주기적 처리가 아닌 예외적 상황을 즉시 처리하는 **이벤트 기반 처리** 방식이 중요하다.

# Notes

<aside>가비지 컬렉션(Garbage Collection)이란</aside>

프로그램이 더 이상 참조하지 않는 메모리를 자동으로 탐지해 회수하는 메모리 관리 기법이다. 개발자가 메모리 해제를 직접 호출하지 않아도 되도록 런타임(또는 미들웨어)이 대신 처리한다.

<aside>가비지 컬렉션의 장점</aside>

- **메모리 누수(memory leak) 방지**: 개발자가 해제를 깜빡해 메모리가 계속 쌓이는 문제를 줄임
- **개발 편의성 향상**: 메모리 해제 시점을 일일이 관리하지 않아도 되어 로직 구현에 집중 가능
- **안정성 향상**: 이미 해제된 메모리에 접근하는 오류(dangling pointer 등)를 줄여 장시간 구동해야 하는 로봇 소프트웨어의 안정성에 기여

<aside>GC의 두 가지 구현 방식 — 참조 계산 vs 추적</aside>

가비지 컬렉션은 크게 두 방식으로 구현된다. **참조 계산(Reference Counting)**은 객체마다 "몇 곳에서 참조되는지" 카운터를 두어, 참조가 생기면 늘리고 없어지면 줄이다 0이 되는 즉시 회수하는 방식이다 — 회수가 프로그램 실행 중 조금씩 분산되지만, 서로를 참조하는 **순환 참조는 회수하지 못하는** 한계가 있다. **추적(Tracing)**은 루트(전역 변수 등)에서 출발해 도달 가능한 객체를 표시하고, 표시되지 않은 객체를 한꺼번에 회수하는 방식으로, 순환 참조도 처리할 수 있지만 탐색 시점에 **한꺼번에 정지**하기 쉽다.

<aside>실시간 시스템에서 GC의 한계 — Stop-the-World</aside>

추적 방식의 GC는 탐색하는 동안 프로그램의 다른 스레드를 모두 멈추는 **일시정지(stop-the-world)**가 발생할 수 있으며, 이 정지 시간이 길어지면 마감시한이 엄격한 하드 실시간 제어 루프의 데드라인을 놓칠 위험이 있다. 이 때문에 로봇의 실시간 제어 루프처럼 지연을 예측할 수 있어야 하는 부분에서는 GC 언어보다 **수동/정적 메모리 관리**를 선호하는 경우가 많다.

<aside>오브젝트 풀링(Object Pooling) — GC 부담을 줄이는 실무 기법</aside>

GC의 지연을 피하기 위한 대표적인 실무 기법이 **오브젝트 풀링**이다. 객체를 매번 새로 생성하고 폐기하는 대신, 미리 만들어 둔 객체 묶음(풀)을 필요할 때 꺼내 쓰고 다 쓰면 풀에 반납해 재사용한다. 이렇게 하면 GC가 회수해야 할 대상 자체가 줄어들어, 실시간성이 중요한 로봇 제어 루프에서도 GC 지연의 영향을 줄일 수 있다.

<aside>이벤트 기반 처리(Event-driven Processing)</aside>

일정 주기(periodic)로 반복 확인하는 방식과 달리, **특정 사건(이벤트)이 발생했을 때만 즉시 해당 처리 로직이 호출**되는 방식이다. 로봇 미들웨어에서 센서 값처럼 계속 갱신되는 데이터는 주기적 방식으로, 버튼 입력·오류 발생처럼 드물지만 즉각 반응해야 하는 사건은 이벤트 기반 방식으로 처리하는 것이 효율적이다.

<aside>주기적 처리 vs 이벤트 기반 처리</aside>

| 방식 | 특징 | 적합한 예 |
|---|---|---|
| 주기적(Periodic) | 정해진 시간마다 반복 호출되어 상태를 확인 | 센서 값 갱신, 상태 모니터링 |
| 이벤트 기반(Event-driven) | 특정 사건 발생 시에만 즉시 호출 | 긴급 정지 버튼, 통신 오류 발생 |

<aside>예시 — 로봇 미들웨어의 메모리·이벤트 관리</aside>

**예시**: 로봇이 장시간 무인 운영되는 서비스에서, 센서 데이터 처리 중 생성되는 임시 객체들을 가비지 컬렉션이 자동으로 회수해 메모리 누수를 방지하고, 동시에 비상정지 버튼 입력은 이벤트 포트를 통해 즉시 감지되어 다른 처리를 기다리지 않고 곧바로 정지 로직이 호출된다.

---

<aside>핵심 정리</aside>

- 가비지 컬렉션은 더 이상 쓰지 않는 메모리를 자동 회수해 메모리 누수를 방지하고 개발 편의성·안정성을 높이며, 개발자의 수동 정밀 제어를 위한 것이 아니다
- 참조 계산은 즉시 회수하지만 순환 참조를 못 걸러내고, 추적은 순환 참조도 처리하지만 일시정지가 발생하기 쉽다
- 추적 GC의 일시정지(stop-the-world)는 하드 실시간 제어 루프의 데드라인을 위협할 수 있어, 오브젝트 풀링 같은 기법으로 GC 부담을 줄이거나 수동/정적 메모리 관리를 선호하기도 한다
- 반복적으로 갱신되는 데이터는 주기적 처리로, 드물지만 즉각 반응해야 하는 사건은 이벤트 기반 처리로 다루는 것이 효율적이다
