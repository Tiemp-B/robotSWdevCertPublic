# Summary

**[[결합도(Coupling)|결합도]]**는 모듈 간에 상호 의존하는 정도를 의미한다. 독립적인 모듈이 되려면 결합도가 **약해야** 하며, 결합도가 높을수록 한 모듈의 변화가 다른 모듈에도 영향을 주어 유지보수가 어려워진다.

# Notes

<aside>결합도란 무엇인가</aside>

두 모듈 사이의 연관 관계(정보 교환)의 정도다. 모듈들 사이의 정보 교환이 많고 서로의 정보에 따라 구동되는 기능이 많을수록 결합도는 높아진다. 인터페이스가 정확히 설정되어 있지 않거나 기능이 제대로 세분화되어 있지 않으면 불필요한 인터페이스가 생겨 결합도가 증가한다.

<aside>결합도의 다섯 가지 유형(약함 → 강함 순)</aside>

| 유형 | 내용 |
|---|---|
| 자료 결합도 | 모듈 간 인터페이스가 **자료 요소로만** 구성됨 — 데이터를 넘기고 결과를 돌려받는 방식. 한 모듈의 내용 변경이 다른 모듈에 영향을 주지 않음(**가장 약한 결합도**) |
| 스탬프 결합도 | 배열·레코드 같은 **자료 구조** 자체가 인터페이스로 전달됨 — 자료 구조 변화가 그것을 조회하는 모든 모듈에 영향 |
| 제어 결합도 | 논리적 흐름을 제어하는 **제어 요소**(플래그 등)가 전달됨 — 상위 모듈이 하위 모듈의 처리 절차를 통제 |
| 공유(공통) 결합도 | 여러 모듈이 **공유되는 공통 데이터 영역**을 사용 — 공통 영역의 작은 변경도 이를 쓰는 모든 모듈에 영향 |
| 내용 결합도 | 한 모듈이 다른 모듈의 **내부 기능·내부 자료를 직접 참조·수정** — 다른 모듈 중간으로 분기되는 경우도 포함(**가장 강한(나쁜) 결합도**) |

<aside>결합도와 모듈 독립성의 관계</aside>

두 모듈이 완벽하게 독립적으로 기능을 수행한다면 서로 상호 교류가 전혀 없는 것과 같다. 결합도가 높을수록 한 모듈의 변화가 다른 모듈에 영향을 주는 범위가 커지고, 그만큼 시스템 유지보수가 어려워진다. 따라서 소프트웨어 설계에서는 **결합도를 최대한 낮추는 것**이 목표다.

<aside>예시 — 로봇 미들웨어에서의 결합도</aside>

**예시**: 센서 인터페이스 모듈이 제어 모듈에 측정값(데이터)만 넘겨주고 결과를 돌려받는 구조는 자료 결합도(바람직)에 해당하지만, 제어 모듈이 센서 모듈 내부의 특정 변수를 직접 읽고 고치는 방식으로 구현하면 내용 결합도(가장 나쁨)가 되어, 센서 모듈을 조금만 바꿔도 제어 모듈이 오작동할 위험이 커진다.

---

<aside>핵심 정리</aside>

- 결합도는 모듈 간 상호 의존 정도이며, 약할수록(자료 결합도) 좋고 강할수록(내용 결합도) 나쁘다
- 강도 순서(약함→강함): 자료 → 스탬프 → 제어 → 공유(공통) → 내용
- 결합도가 높을수록 한 모듈의 변경이 다른 모듈에 영향을 미치는 범위가 커져 유지보수가 어려워진다
