# Summary

로봇 산업에서는 여러 국가·기관이 저마다 로봇 전용 운영체제(미들웨어 포함)를 개발해 왔다. 그중 **[[ROS(Robot Operating System)|ROS]]**(미국)와 **[[OPRoS(Open Platform for Robotics Services)|OPRoS]]**(한국)가 대표적이며, 이 밖에도 RTC·iCub·OROCOS·MRSRS 등 다양한 운영체제가 존재한다.

# Notes

<aside>ROS(Robot Operating System)</aside>

미국 스탠퍼드 대학 AI Lab의 프로젝트에서 출발해 Willow Garage사가 이어받아 개발한 로봇 운영체제다. BSD 라이선스 기반의 오픈소스로, 하드웨어 추상화·저수준 장치 제어·프로세스 간 메시지 전달·패키지 관리 등 로봇 소프트웨어 운영에 필요한 기능을 제공한다. 그래프 기반 아키텍처(노드의 연결)를 채택하고 있으며, 통합된 개발 환경이 아니라 개별 도구들의 집합 형태라 접근성은 다소 낮은 편이다. 구체적인 아키텍처는 [[1. 로봇 구성요소간 통신프로토콜 개요|다음 세세항목]]에서 다룬다.

이후 등장한 **ROS2**는 이 ROS(1)의 마스터 중심 구조가 가진 단일 장애점·실시간성 부족 문제를 해결하기 위해, 마스터 없이 노드가 서로를 자동으로 찾는 DDS 기반 통신으로 재설계한 후속 버전이다 — 구체적인 구조와 QoS 정책은 [[3. ROS2와 DDS QoS|다음 세세항목]]에서 다룬다.

<aside>OPRoS(Open Platform for Robotics Services)</aside>

**[[OPRoS(Open Platform for Robotics Services)|OPRoS]]**는 한국이 국가 주도로 개발한 컴포넌트 기반의 오픈소스 로봇 플랫폼이다. 통합 개발 환경과 시뮬레이터까지 함께 제공해, 로봇 하드웨어 없이도 미리 테스트할 수 있다는 장점이 있다. 컴포넌트 간의 연결은 **포트(port)** 를 통해 이뤄지며, 서비스 포트(메서드 호출)·데이터 포트(주기적 데이터 송수신)·이벤트 포트(이벤트 발생 시 즉시 처리)의 세 종류를 지원한다.

<aside>RTC(Robot Technology Component)</aside>

일본(AIST)과 미국(RTI)이 공동 개발한 표준으로, 로봇용 소프트웨어 컴포넌트들이 서로 조합·접속되기 위한 **공통 인터페이스 규격**이다. 로봇의 많은 소프트웨어 모듈이 내장형 소프트웨어라는 점을 고려해, 경량화된 컴포넌트 모델로 구현하는 것이 특징이다.

<aside>기타 로봇 운영체제</aside>

| 운영체제 | 개발 주체 | 특징 |
|---|---|---|
| iCub | 이탈리아(IIT) | 휴머노이드 로봇용, 전자회로도·하드웨어·소프트웨어 전부 공개(GPL) |
| OROCOS | EU(벨기에·프랑스·스웨덴 공동) | 실시간 제어 중심, C++ 라이브러리 기반, 개발 도구는 미제공 |
| MRSRS(Microsoft Robotics Studio) | 미국(MS) | 기본적인 프로그래밍 지식만으로 개발 가능, 3D 물리엔진 기반 시뮬레이션으로 실제 로봇 없이 테스트 가능 |

<aside>로봇 운영체제 선택 시 고려 사항(개념)</aside>

특정 운영체제를 선택할 때는 개발사, 지원하는 플랫폼(Windows/Linux), 오픈소스 여부, 개발 도구 제공 여부 등을 종합적으로 비교해 로봇의 요구사항에 적합한 것을 선정한다. "가장 널리 알려진 운영체제가 모든 로봇에 항상 최적이다"는 서술은 오답이다 — 로봇의 용도·환경·개발 조직의 역량에 따라 적합한 운영체제가 달라진다.

<aside>예시 — 운영체제 선정 회의</aside>

**예시**: 국내에서 개발되고 통합 개발 환경·시뮬레이터를 함께 제공하는 서비스 로봇 프로젝트라면 OPRoS가, 이미 세계적으로 널리 쓰이는 오픈소스 생태계와 다양한 커뮤니티 자료를 활용하고 싶다면 ROS가 더 적합할 수 있다.

---

<aside>핵심 정리</aside>

- ROS(미국, 그래프 기반, 오픈소스, 커뮤니티 방대)와 OPRoS(한국, 컴포넌트+포트 기반, 통합 개발환경·시뮬레이터 제공)가 대표적인 로봇 운영체제다
- RTC는 컴포넌트 간 공통 인터페이스 규격, iCub·OROCOS·MRSRS도 각자의 목적에 맞게 개발된 로봇 운영체제다
- 운영체제 선택은 "가장 유명한 것"이 아니라 로봇의 요구사항·개발 환경에 맞춰 판단해야 한다
