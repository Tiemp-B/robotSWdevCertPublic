# Summary

로봇 소프트웨어 프레임워크의 주된 목적은 **개발 생산성과 재사용성 향상**이며, **[[OROCOS(Open Robot Control Software)|OROCOS]]**는 실시간 제어에 특화된 대표적 오픈소스 프레임워크다.

# Notes

<aside>로봇 소프트웨어 프레임워크의 주요 목적</aside>

- 센서·액추에이터·통신 등 반복적으로 필요한 기능을 **재사용 가능한 컴포넌트**로 제공
- 하드웨어 차이를 추상화해 **이식성(portability)** 향상
- 표준화된 인터페이스로 **여러 개발자·조직 간 협업**을 용이하게 함
- 검증된 라이브러리를 활용해 **개발 기간 단축과 신뢰성 향상**

<aside>OROCOS(Open Robot Control Software)</aside>

OROCOS는 실시간성이 중요한 로봇 제어에 특화된 오픈소스 프레임워크로, 다음과 같은 주요 컴포넌트(라이브러리)로 구성된다.

| 컴포넌트 | 역할 |
|---|---|
| RTT(Real-Time Toolkit) | 실시간 컴포넌트 기반 애플리케이션을 구축하는 핵심 툴킷 |
| KDL(Kinematics and Dynamics Library) | 로봇의 기구학·동역학 계산 라이브러리 |
| OCL(Orocos Component Library) | 재사용 가능한 표준 컴포넌트 모음 |
| BFL(Bayesian Filtering Library) | 칼만 필터 등 베이지안 필터링 알고리즘 라이브러리 |

<aside>빅데이터 분산 처리 프레임워크</aside>

로봇이 대량의 센서 데이터(비전·라이다 등)를 처리하거나 다수 로봇의 데이터를 통합 분석할 때는 일반적인 빅데이터 분산 처리 프레임워크(예: Apache Hadoop, Apache Spark)를 함께 활용하기도 한다. 이는 로봇 전용 미들웨어(ROS 등)와는 별개로, 대규모 데이터의 분산 저장·병렬 연산을 담당하는 범용 프레임워크다.

두 프레임워크는 처리 방식이 다르다. **[[Hadoop과 Spark(디스크 기반·인메모리 분산 처리)|Hadoop(MapReduce)]]** 은 연산 단계마다 결과를 **디스크(HDFS)에 기록**하며 처리하는 반면, **Spark**는 중간 결과를 **메모리에 유지**한 채 연산을 이어가 디스크 입출력을 줄인다 — 같은 데이터를 여러 번 훑는 반복 연산에서는 Spark가 훨씬 빠르다.

<aside>예시 — 프레임워크 조합</aside>

**예시**: 실시간 관절 제어에는 OROCOS의 RTT·KDL을, 로봇 간 메시지 통신에는 ROS를, 다수 로봇에서 수집된 센서 로그의 대규모 분석에는 Spark 같은 분산 처리 프레임워크를 조합해 사용할 수 있다.

---

<aside>핵심 정리</aside>

- 프레임워크의 목적은 재사용성·이식성·협업 편의성 향상이며, 특정 하드웨어에 종속되는 것과는 반대다
- OROCOS는 실시간 제어(RTT)·기구학동역학(KDL)·필터링(BFL) 등으로 구성되며, 빅데이터 분산 처리는 별도의 범용 프레임워크(Spark 등) 영역이다
- Hadoop은 디스크 기반, Spark는 메모리 기반으로 처리하며, 반복 연산에서는 Spark가 더 빠르다
