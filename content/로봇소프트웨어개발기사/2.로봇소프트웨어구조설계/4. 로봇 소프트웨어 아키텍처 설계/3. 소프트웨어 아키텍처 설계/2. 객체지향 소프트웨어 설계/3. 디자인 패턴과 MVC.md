# Notes

<aside>싱글톤(Singleton) 패턴</aside>

싱글톤 패턴은 클래스의 **인스턴스가 프로그램 전체에서 오직 하나만 생성**되도록 보장하고, 어디서든 그 유일한 인스턴스에 접근할 수 있는 전역 접근점을 제공하는 패턴이다.

"싱글톤 패턴은 요청할 때마다 항상 새로운 인스턴스를 생성해 반환하는 패턴이다"라는 서술은 오답이다 — 싱글톤 패턴의 핵심은 정반대로, **단 하나의 인스턴스만 생성**되도록 보장하고 이후 요청에는 그 동일한 인스턴스를 반환하는 것이다.

<aside>옵저버(Observer) 패턴</aside>

옵저버 패턴은 한 객체(주체, Subject)의 상태가 변할 때, 그 객체를 구독(관찰)하고 있는 여러 객체(옵저버)들에게 자동으로 변경 사실을 통지하는 패턴이다. [[3. 통신 모델(발행-구독·요청-응답·액션)|발행-구독(Publish-Subscribe)]] 통신 패턴과 개념적으로 유사하다.

- 로봇 소프트웨어에서의 용도: 센서 값이 갱신될 때마다 이를 구독하는 여러 모듈(로깅, UI 표시, 제어 로직)에 자동으로 알림

<aside>MVC(Model-View-Controller) 패턴</aside>

MVC는 애플리케이션을 세 가지 역할로 분리하는 아키텍처 패턴이다.

| 구성 요소 | 역할 |
|---|---|
| Model | 데이터와 비즈니스 로직(예: 로봇의 현재 상태·센서 데이터) |
| View | 사용자에게 보여지는 화면(예: 로봇 상태 대시보드 UI) |
| **Controller** | **사용자 입력을 받아 Model을 갱신하거나 View의 표시 방식을 제어** |

"MVC 패턴에서 Controller의 역할은 사용자에게 보여줄 화면을 직접 렌더링하는 것이다"라는 서술은 **View**와 뒤바뀐 오답이다 — 화면 렌더링은 View의 역할이며, Controller는 **사용자 입력을 처리해 Model을 갱신**하는 역할을 한다.

<aside>예시 — 로봇 원격 제어 UI에 MVC와 옵저버 적용</aside>

**예시**: 사용자가 원격 제어 화면에서 "정지" 버튼을 누르면(Controller가 입력을 받아 처리) 로봇의 상태(Model)가 "정지"로 갱신되고, Model의 상태 변경을 구독하고 있던 옵저버(View, 로그 기록 모듈 등)들이 자동으로 통지를 받아 화면 표시와 로그를 갱신한다.

---

<aside>핵심 정리</aside>

- 싱글톤은 인스턴스를 오직 하나만 생성·공유하는 패턴이다
- 옵저버는 주체의 상태 변화를 구독자들에게 자동 통지하는 패턴이다
- MVC의 Controller는 화면 렌더링이 아니라 사용자 입력 처리와 Model 갱신을 담당한다
