# Notes

<aside>CASE(Computer-Aided Software Engineering) 도구</aside>

CASE 도구는 요구 분석·설계·구현·테스트 등 소프트웨어 개발 전 과정을 컴퓨터로 지원하는 도구를 말한다.

- **주요 기능**: 다이어그램(UML 등) 작성 지원, 요구 사항-설계-코드 간 추적성 관리, 문서 자동 생성, 코드 생성(일부 도구)
- **장점**: 설계 산출물의 일관성 유지, 팀 간 의사소통 향상, 반복 작업 자동화로 생산성 향상

"CASE 도구의 주요 기능에는 로봇 하드웨어의 전기 회로를 직접 설계하는 기능이 포함된다"라는 서술은 오답이다 — CASE 도구는 **소프트웨어 개발 과정**(설계·문서화·추적성)을 지원하는 도구이며, 하드웨어 회로 설계는 별개의 전자설계자동화(EDA) 도구의 영역이다.

<aside>버전 관리 시스템의 주요 기능</aside>

- 코드 변경 이력 추적(누가, 언제, 무엇을 변경했는지)
- 여러 개발자의 동시 작업을 브랜치로 분리했다가 병합(merge)
- 특정 시점으로 되돌리기(rollback)
- 충돌(conflict) 발생 시 변경 내용 비교·병합 지원

<aside>Git의 주요 특징</aside>

Git은 분산 버전 관리 시스템(DVCS)으로, 중앙 서버 없이도 각 개발자가 전체 이력을 가진 로컬 저장소를 가질 수 있다.

- **분산 구조**: 중앙 서버가 다운되어도 각 개발자의 로컬 저장소에 전체 이력이 보존됨
- **브랜치 관리 용이**: 가볍고 빠른 브랜치 생성·전환
- **`git pull`**: 원격 저장소의 변경 사항을 가져오면서(`fetch`) 자동으로 현재 브랜치에 병합(`merge`)까지 수행하는 명령어

"Git은 반드시 중앙 서버가 있어야만 커밋 이력을 확인할 수 있는 중앙집중형 버전 관리 시스템이다"라는 서술은 오답이다 — Git은 **분산형(DVCS)** 시스템으로, 각 로컬 저장소가 전체 이력의 완전한 사본을 가지므로 중앙 서버 없이도 이력 확인이 가능하다.

---

<aside>핵심 정리</aside>

- CASE 도구는 소프트웨어 설계·문서화·추적성을 지원하며 하드웨어 회로 설계와는 무관하다
- Git은 분산형(DVCS) 버전 관리 시스템이며, `git pull`은 fetch+merge를 한 번에 수행하는 명령어다
