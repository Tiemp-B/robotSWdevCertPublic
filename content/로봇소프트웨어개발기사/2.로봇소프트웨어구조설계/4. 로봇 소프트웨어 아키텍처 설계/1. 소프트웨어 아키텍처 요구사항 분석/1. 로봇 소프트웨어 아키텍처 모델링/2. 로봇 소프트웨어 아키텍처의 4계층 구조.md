# Summary

로봇 소프트웨어 아키텍처는 **Driver(하드웨어) → Platform(미들웨어) → Algorithm(응용) → User Interface(사용자 인터페이스)** 4계층으로 모델링하는 것이 일반적이며, 가장 하위 계층은 하드웨어와 직접 맞닿는 Driver 계층이다.

# Notes

<aside>4계층 구조</aside>

| 계층 | 다루는 내용 |
|---|---|
| Driver(드라이버) 계층 — 최하위 | 센서 인터페이스(ADC 변환, 노이즈 제거), 액추에이터 인터페이스(모터 전압 제어) |
| Platform(플랫폼/미들웨어) 계층 | 조향(steering), 센서 퓨전(엔코더+IMU로 위치 인식), 이미지 처리, 매니퓰레이터 기구학 |
| Algorithm(알고리즘/응용) 계층 | 경로 계획(path planning), 장애물 회피, 맵핑·로컬라이제이션(SLAM) |
| User Interface(사용자 인터페이스) 계층 — 최상위 | 원격 조종, 영상·센서 데이터 디스플레이, 로봇 상태 표시 |

<aside>기능적 요구사항 vs 비기능적 요구사항</aside>

각 계층의 요구 사항은 크게 두 유형으로 나뉜다. **[[기능적 요구사항과 비기능적 요구사항(Functional·Non-Functional Requirements)|기능적 요구사항]]** 은 시스템이 **무엇을 해야 하는가**(기능·동작 자체)를, **비기능적 요구사항**은 그 기능이 **어떻게 동작해야 하는가**(성능·보안·신뢰성 등 품질 제약)를 정의한다. 예를 들어 Algorithm 계층의 "경로 계획을 수행한다"는 기능적 요구사항이고, "경로 계획은 50ms 이내에 완료되어야 한다"는 비기능적 요구사항이다. 두 요구사항은 상호 보완적이며, 기능적 요구사항만 충족해도 성능·안정성 같은 비기능적 요구사항이 부족하면 실제로 쓸 수 없는 시스템이 될 수 있다.

<aside>계층 간의 관계</aside>

각 계층은 하위 계층이 제공하는 서비스(포트를 통한 인터페이스)를 이용해 자신의 기능을 구현하고, 그 결과를 상위 계층에 서비스로 제공한다. 예를 들어 Algorithm 계층의 "경로 계획"은 Platform 계층의 "센서 퓨전"이 제공하는 위치 정보를 입력받아 동작하며, 그 결과(이동 경로)를 다시 Platform 계층의 "조향" 컴포넌트에 전달한다.

<aside>컴포넌트와 포트</aside>

각 계층의 기능은 [[3. UML과 행위적 다이어그램|UML 컴포넌트 다이어그램]]으로 표현되는 **컴포넌트** 단위로 구현되며, 컴포넌트 간에는 서비스 포트·데이터 포트·이벤트 포트를 통해 상호작용한다(컴포넌트·포트의 UML 표기법은 과목2 로봇 미들웨어 개발에서 이미 다뤘으므로 여기서는 반복하지 않는다).

<aside>예시 — 재난 구조용 모바일 로봇의 계층 매핑</aside>

**예시**: 초음파 센서 신호를 디지털 값으로 변환하는 기능은 Driver 계층, 그 값을 이용해 장애물 유무를 판단하는 센서 퓨전은 Platform 계층, 장애물을 피해 목적지까지 가는 경로를 계산하는 것은 Algorithm 계층, 사용자가 원격으로 로봇 상태를 확인하는 화면은 User Interface 계층에 해당한다.

<aside>핵심 정리</aside>

- 4계층은 Driver(최하위, 하드웨어)-Platform(미들웨어)-Algorithm(응용)-User Interface(최상위) 순이며, 하위 계층 서비스를 상위 계층이 사용하는 구조다
- 각 계층의 요구사항은 "무엇을"(기능적)과 "어떻게"(비기능적)로 나뉘며, 둘 다 함께 충족해야 한다
