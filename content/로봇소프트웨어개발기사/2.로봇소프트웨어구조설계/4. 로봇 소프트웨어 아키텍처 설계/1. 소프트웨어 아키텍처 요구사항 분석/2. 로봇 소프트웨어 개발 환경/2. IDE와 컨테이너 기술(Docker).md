# Summary

**IDE(통합개발환경)**는 코드 작성부터 빌드·디버깅까지 하나의 도구에서 처리할 수 있게 해주며, **[[Docker(컨테이너 기술)|Docker]]** 는 애플리케이션을 운영체제 커널을 공유하는 경량 컨테이너로 격리·배포하는 기술이다.

# Notes

<aside>IDE(Integrated Development Environment)의 주요 기능</aside>

- **코드 편집**: 문법 강조, 자동완성 등을 지원하는 에디터
- **빌드·컴파일**: 소스 코드를 실행 파일로 변환
- **디버깅**: 중단점 설정, 변수 값 추적 등으로 오류 원인 파악
- **버전 관리 연동**: Git 등 형상관리 도구와의 통합

"IDE의 주요 기능에는 로봇 하드웨어의 물리적 조립을 자동으로 수행하는 기능이 포함된다"라는 서술은 오답이다 — IDE는 **소프트웨어 개발 과정**(편집·빌드·디버깅)을 지원하는 도구이며, 하드웨어의 물리적 조립과는 무관하다.

<aside>Docker 컨테이너의 특징</aside>

Docker는 애플리케이션과 그 실행에 필요한 라이브러리·설정을 하나의 **이미지**로 묶어, 어느 환경에서나 동일하게 실행되는 **컨테이너**로 격리해 구동하는 기술이다.

- 호스트 OS의 **커널을 컨테이너끼리 공유**하므로, 각 컨테이너가 완전한 운영체제를 포함하는 가상머신(VM)보다 훨씬 가볍고 시작 속도가 빠름
- 컨테이너는 파일 시스템·프로세스 공간이 서로 격리되어 있음
- 이미지 기반이라 동일한 환경을 여러 대의 로봇·서버에 일관되게 재현·배포하기 쉬움

"Docker 컨테이너는 각각 완전히 독립된 운영체제 커널을 포함하고 있어 가상머신(VM)과 자원 사용 방식이 동일하다"라는 서술은 오답이다 — Docker 컨테이너는 오히려 호스트 OS의 **커널을 공유**하기 때문에 각자 독립된 커널을 갖는 가상머신보다 훨씬 가볍다는 점이 핵심 차이다.

<aside>예시 — 로봇 소프트웨어 배포에 Docker 활용</aside>

**예시**: 여러 대의 물류 로봇에 동일한 버전의 소프트웨어와 라이브러리 환경을 배포해야 할 때, 개발 환경을 Docker 이미지로 만들어 두면 각 로봇에서 "환경마다 라이브러리 버전이 달라 동작이 다르다"는 문제 없이 동일한 컨테이너를 그대로 배포·실행할 수 있다.

---

<aside>핵심 정리</aside>

- IDE는 코드 편집·빌드·디버깅·버전 관리 통합을 지원하는 소프트웨어 개발 도구다
- Docker 컨테이너는 호스트 OS 커널을 공유해 가상머신보다 가볍고 빠르며, 동일 환경 재현·배포에 유리하다
