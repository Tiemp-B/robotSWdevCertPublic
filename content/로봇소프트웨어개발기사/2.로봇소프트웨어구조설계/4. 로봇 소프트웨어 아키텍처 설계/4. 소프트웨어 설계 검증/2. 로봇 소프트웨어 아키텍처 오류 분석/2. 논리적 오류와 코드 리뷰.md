# Summary

**논리적 오류(Logic Error)**는 문법적으로는 정상이지만 프로그래머가 의도한 결과와 다른 값을 내는 오류이며, **코드 리뷰**는 이런 오류를 동료의 시각으로 미리 발견하는 활동이다.

# Notes

<aside>논리적 오류(Logic Error)의 특징</aside>

논리적 오류는 컴파일·문법 검사를 통과하고 프로그램이 정상적으로 실행되지만, **결과값이 프로그래머의 의도와 다른** 오류다. 문법 오류(syntax error)와 달리 컴파일러나 정적 분석 도구가 자동으로 잡아내기 어려워, 실행 결과를 검토하는 테스트나 코드를 읽는 코드 리뷰를 통해서만 발견할 수 있다.

<aside>코드 리뷰(Code Review)의 목적</aside>

- **결함 조기 발견**: 논리적 오류처럼 자동화 도구로 잡기 어려운 문제를 사람이 검토해 발견
- **지식 공유**: 코드 작성자의 의도와 설계 배경을 팀원들이 함께 이해
- **코딩 표준 준수 확인**: 팀의 코딩 규칙·스타일을 지키고 있는지 확인
- **유지보수성 향상**: 가독성이 떨어지거나 구조가 나쁜 코드를 사전에 개선

<aside>예시 — 논리적 오류의 사례</aside>

**예시**: 로봇의 배터리 잔량이 20% 이하일 때 경고를 표시해야 하는데, 코드에서 `if (battery < 20)` 대신 실수로 `if (battery > 20)`을 써서 정상 상태일 때 오히려 경고가 뜨는 경우가 전형적인 논리적 오류이며, 컴파일은 정상적으로 되므로 코드 리뷰나 테스트를 통해서만 발견할 수 있다.

---

<aside>핵심 정리</aside>

- 논리적 오류는 컴파일은 통과하지만 결과가 의도와 다른 오류로, 자동으로 걸러지지 않는다
- 코드 리뷰의 목적은 결함 조기 발견·지식 공유·품질 향상이며, 코드를 대신 재작성하는 것이 아니다
