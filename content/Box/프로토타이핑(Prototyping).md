# Summary

프로토타이핑은 시스템의 초기 모델(프로토타입)을 만들어 사용자에게 보여주고 피드백을 받아 요구사항을 구체화·보완해 나가는 요구사항 도출 기법으로, 사용자 참여를 이끌어내는 장점이 있는 대신 비용·문서화·완제품 오인이라는 단점이 있다.

# Notes

<aside>장점</aside>

- 사용자가 프로토타입을 직접 체험하며 평가할 수 있어 **요구사항 도출에 적극적으로 참여**하게 됨
- 개발자와 사용자 간 의사소통이 원활해지고, 개발 타당성을 조기에 확인할 수 있음
- 사용자가 완성될 시스템의 모습을 미리 가늠해볼 수 있음

<aside>단점</aside>

- 프로토타입 제작 자체에 추가적인 시간·비용이 들며, 폐기(throwaway)할 경우 비경제적일 수 있음
- 문서화 과정이 축소·생략되기 쉬워, 이후 유지보수 시 관련 문서 부재로 어려움을 겪을 수 있음
- 사용자가 프로토타입을 **최종 완제품으로 오인**해, 실제로는 미완성인 부분에 대해 과도한 기대나 요구를 하게 될 위험이 있음

"프로토타이핑의 가장 큰 단점은 사용자가 요구사항 도출에 참여할 수 없다는 것이다"라는 서술은 오답이다 — 오히려 프로토타이핑의 핵심 **장점이 사용자 참여**이며, 실제 단점은 비용·문서화 부족·완제품 오인 위험이다.

---

<aside>핵심 정리</aside>

- 프로토타이핑은 초기 모델로 사용자 피드백을 받아 요구사항을 구체화하는 도출 기법이다
- 장점은 사용자 참여·의사소통 향상이며, 단점은 비용 증가·문서화 부족·완제품 오인 위험이다
