# Summary

Hadoop(MapReduce)은 연산 결과를 디스크에 기록하며 처리하는 빅데이터 분산 처리 프레임워크이고, Spark는 중간 결과를 메모리에 유지해 반복 연산을 훨씬 빠르게 처리하는 프레임워크다.

# Notes

<aside>디스크 기반 vs 인메모리 처리</aside>

| 구분 | Hadoop(MapReduce) | Spark |
|---|---|---|
| 중간 결과 저장 위치 | 디스크(HDFS)에 기록 | 메모리(RAM)에 유지 |
| 반복 연산 성능 | 디스크 입출력으로 지연 발생 | 메모리 유지로 훨씬 빠름 |
| 적합한 작업 | 대용량 배치 처리 | 반복 연산, 실시간에 가까운 분석 |

"Spark는 Hadoop과 마찬가지로 매 연산 단계마다 결과를 디스크에 기록한 뒤 다음 단계로 넘어간다"라는 서술은 오답이다 — Spark의 핵심은 오히려 **중간 결과를 메모리에 유지**해 디스크 입출력을 최소화하는 것이며, 이 덕분에 같은 데이터를 여러 번 훑는 반복 연산에서 Hadoop보다 빠르다.

<aside>로봇 데이터 분석에서의 활용</aside>

다수 로봇의 센서 로그를 여러 번 반복해서 분석해야 하는 경우(패턴 탐지, 반복 모델 학습 등)는 Spark가, 대용량 로그를 한 번에 안정적으로 배치 처리하면 되는 경우는 Hadoop이 적합하다.

---

<aside>핵심 정리</aside>

- Hadoop은 디스크에 결과를 기록하며 처리하고, Spark는 메모리에 결과를 유지하며 처리한다
- Spark는 반복 연산에서 Hadoop보다 훨씬 빠르다
