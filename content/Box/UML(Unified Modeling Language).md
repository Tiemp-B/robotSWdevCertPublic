# Summary

UML(통합 모델링 언어)은 소프트웨어의 구조와 동작을 **표준화된 다이어그램**으로 시각화해 표현하는 모델링 언어로, 클래스 다이어그램 같은 구조적 다이어그램과 상태 다이어그램 같은 행위적 다이어그램으로 나뉜다.

# Notes

<aside>구조적 다이어그램과 행위적 다이어그램</aside>

| 구분 | 목적 | 예시 |
|---|---|---|
| 구조적(Structural) 다이어그램 | 시스템의 정적인 구성 요소와 관계를 표현 | 클래스 다이어그램, 컴포넌트 다이어그램 |
| 행위적(Behavioral) 다이어그램 | 시스템이 시간에 따라 어떻게 동작하는지 표현 | 상태 다이어그램(Statechart), 시퀀스 다이어그램 |

같은 시스템이라도 "무엇으로 구성되어 있는가"(구조)와 "어떻게 동작하는가"(행위)는 서로 다른 관점이라 별도의 다이어그램으로 표현한다.

"UML의 클래스 다이어그램은 시스템이 시간에 따라 상태가 어떻게 전이되는지를 표현하는 행위적 다이어그램이다"라는 서술은 오답이다 — 클래스 다이어그램은 오히려 **정적인 구조(클래스와 관계)를 표현하는 구조적 다이어그램**이며, 상태 전이는 상태(Statechart) 다이어그램의 역할이다.

<aside>로봇 미들웨어 설계에서의 활용</aside>

로봇 미들웨어의 컴포넌트 구조는 구조적 다이어그램(컴포넌트 다이어그램)으로, 로봇의 동작 모드 전환(대기→이동→작업 등)은 행위적 다이어그램(상태 다이어그램)으로 표현해 설계를 문서화한다.

---

<aside>핵심 정리</aside>

- UML은 구조적 다이어그램(정적 구성)과 행위적 다이어그램(동적 동작)으로 시스템을 시각화한다
- 클래스 다이어그램은 구조적 다이어그램이며, 상태 전이는 행위적 다이어그램(상태 다이어그램)이 담당한다
