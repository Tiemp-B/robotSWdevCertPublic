# Summary

블로킹 큐는 **큐가 가득 찼을 때 생산자를, 큐가 비어있을 때 소비자를 자동으로 대기(block)시키는** 자료구조로, [[생산자-소비자 문제(Producer-Consumer Problem)]]를 별도의 수동 동기화 코드 없이 안전하게 해결한다.

# Notes

<aside>블로킹 큐의 자동 대기 동작</aside>

- 생산자가 데이터를 넣으려는데 큐가 가득 찼다면, 큐에 공간이 생길 때까지 생산자 스레드가 자동으로 대기함
- 소비자가 데이터를 꺼내려는데 큐가 비어있다면, 새 데이터가 들어올 때까지 소비자 스레드가 자동으로 대기함
- 이 대기·깨우기 로직이 큐 내부에 이미 구현되어 있어, 개발자가 [[세마포어(Semaphore)]]·[[뮤텍스(Mutex)]] 등을 직접 조합해 동기화 코드를 작성할 필요가 줄어듦

"블로킹 큐는 큐가 가득 차거나 비어있을 때 예외를 즉시 발생시켜 프로그램을 종료시키는 자료구조다"라는 서술은 오답이다 — 블로킹 큐의 핵심은 오히려 **예외를 던지는 대신 스레드를 대기시켰다가, 조건이 충족되면 자동으로 진행**시키는 것이다.

<aside>생산자-소비자 문제와의 관계</aside>

[[생산자-소비자 문제(Producer-Consumer Problem)]]를 직접 세마포어·뮤텍스 조합으로 구현할 수도 있지만, 블로킹 큐를 사용하면 그 동기화 로직이 이미 캡슐화되어 있어 더 안전하고 간결하게 구현할 수 있다.

---

<aside>핵심 정리</aside>

- 블로킹 큐는 큐가 가득 차거나 비었을 때 생산자·소비자를 자동으로 대기시키는 자료구조다
- 예외를 던지고 종료하는 것이 아니라, 조건이 충족될 때까지 대기시킨다는 점이 핵심이다
