# Summary

가비지 컬렉션(GC)은 프로그램이 더 이상 사용하지 않는 메모리를 **개발자가 직접 해제하지 않아도 자동으로 탐지해 회수**해주는 메모리 관리 기법이다.

# Notes

<aside>가비지 컬렉션의 동작 방식</aside>

- 프로그램 실행 중 어떤 객체를 더 이상 아무도 참조하지 않는지 주기적으로 탐지(도달 가능성 분석 등)
- 참조되지 않는(도달 불가능한) 객체를 자동으로 메모리에서 해제
- C/C++처럼 개발자가 `free`/`delete`를 직접 호출해야 하는 수동 메모리 관리와 달리, 해제를 잊어 생기는 메모리 누수를 줄여줌

<aside>참조 계산(Reference Counting) vs 추적(Tracing)</aside>

GC는 크게 두 방식으로 구현된다. **참조 계산**은 객체마다 참조 횟수를 세어 0이 되는 즉시 회수하지만 순환 참조는 회수하지 못한다. **추적**은 루트에서 도달 가능한 객체를 표시하고 나머지를 한꺼번에 회수해 순환 참조도 처리하지만, 탐색 시점에 일시정지가 발생하기 쉽다.

<aside>실시간 로봇 소프트웨어에서의 주의점</aside>

GC가 동작하는 시점에 프로그램이 잠시 멈추는 "GC 일시정지(stop-the-world)"가 발생할 수 있어, 마감시한이 엄격한 실시간 제어 루프에서는 GC 언어보다 수동/정적 메모리 관리를 선호하는 경우가 많다 — 이는 임베디드 메모리 관리에서 정적 할당을 우선하는 이유와도 통한다. 객체를 미리 만들어 재사용하는 **오브젝트 풀링**도 GC가 회수할 대상 자체를 줄여 이 지연을 완화하는 실무 기법이다.

---

<aside>핵심 정리</aside>

- 가비지 컬렉션은 더 이상 참조되지 않는 메모리를 자동으로 탐지·회수하는 메모리 관리 기법이다
- 회수 시점을 개발자가 정확히 제어할 수 없어, 실시간성이 엄격한 로봇 제어 루프에서는 예측 불가능한 지연을 유발할 수 있다
