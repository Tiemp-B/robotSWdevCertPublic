# Summary

크로스 컴파일은 개발 PC(호스트)에서 로봇 제어보드(타겟)와는 다른 프로세서 구조용 실행 파일을 만드는 것이고, 원격 디버깅은 그 실행 파일을 타겟에서 돌리며 개발 PC에서 원격으로 디버깅하는 것이다 — 둘 다 개발 PC와 실행 장치가 다른 임베디드 개발 환경의 특징이다.

# Notes

<aside>크로스 컴파일(Cross-Compilation)</aside>

- 개발 PC(호스트, 예: x86)에서 로봇 제어보드(타겟, 예: ARM)와 **다른 프로세서 구조**용 실행 파일을 생성하는 컴파일 방식
- 성능이 좋은 개발 PC의 자원을 활용해 빠르게 빌드하고, 자원이 제한된 타겟 장치에서 직접 컴파일하는 부담을 없앰

<aside>원격 디버깅(Remote Debugging)</aside>

- 개발 PC에서 실행되는 디버거가 네트워크·시리얼 통신으로 타겟 장치에서 실행 중인 프로그램과 연결해, 타겟의 실행을 원격으로 중단·변수값 추적
- 무겁고 리소스를 많이 쓰는 디버깅 도구를 자원이 제한된 타겟 장치에 직접 설치하지 않아도 됨

"로봇 소프트웨어 개발에서는 항상 로봇 제어보드에서 직접 코드를 컴파일하고 디버깅해야 한다"라는 서술은 오답이다 — 로봇 개발 환경의 핵심은 오히려 **개발 PC에서 크로스 컴파일하고, 타겟에서 실행 중인 프로그램을 원격으로 디버깅**하는 방식이 일반적이라는 점이다.

---

<aside>핵심 정리</aside>

- 크로스 컴파일은 개발 PC에서 타겟(로봇)과 다른 프로세서 구조의 실행 파일을 만드는 것이다
- 원격 디버깅은 개발 PC의 디버거가 타겟에서 실행 중인 프로그램을 네트워크로 제어·관찰하는 것이다
