# Summary

사용성 테스트는 실제 사용자가 시스템(로봇 콘텐츠 등)을 직접 사용하게 하면서 **얼마나 쉽고 직관적으로 목표를 달성하는지**를 관찰·평가하는 테스트로, 개발자의 주관적 판단이 아니라 실제 사용자 행동에 기반한다.

# Notes

<aside>사용성 테스트의 방식</aside>

- 실제(또는 대표) 사용자에게 특정 과제(예: "이 로봇 콘텐츠로 원하는 기능을 찾아 실행해보세요")를 주고 수행 과정을 관찰
- 과제 완료 시간, 오류 발생 횟수, 사용자가 헤매는 지점 등을 기록해 UX상의 문제를 발견
- [[휴리스틱 평가(Heuristic Evaluation)]]가 전문가의 규칙 기반 평가라면, 사용성 테스트는 **실제 사용자의 행동 관찰**에 기반한다는 차이가 있음

"사용성 테스트는 UX 전문가가 정해진 평가 규칙에 따라 화면을 검토하는 방식으로 진행된다"라는 서술은 오답이다 — 그것은 [[휴리스틱 평가(Heuristic Evaluation)]]의 특징이며, 사용성 테스트의 핵심은 오히려 **실제 사용자가 직접 시스템을 사용하는 과정을 관찰**하는 것이다.

<aside>휴리스틱 평가와의 관계</aside>

두 방법은 상호 보완적으로 쓰인다 — 휴리스틱 평가로 개발 초기에 전문가가 빠르게 명백한 문제를 걸러내고, 사용성 테스트로 실제 사용자 관점에서 놓친 문제를 추가로 발견하는 식이다.

---

<aside>핵심 정리</aside>

- 사용성 테스트는 실제 사용자가 시스템을 사용하는 과정을 관찰해 UX 문제를 발견하는 테스트다
- 전문가의 규칙 기반 검토(휴리스틱 평가)가 아니라, 실제 사용자 행동 관찰에 기반한다
