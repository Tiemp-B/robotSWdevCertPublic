# Summary

JWT(JSON Web Token)는 사용자 인증 정보를 서버에 별도로 저장하지 않고, **서명된 토큰 자체에 정보를 담아** 클라이언트가 요청마다 제시하는 방식의 인증 토큰 규격이다.

# Notes

<aside>JWT의 구조와 동작 방식</aside>

- 헤더(알고리즘 정보)·페이로드(사용자 정보 등 claim)·서명(위변조 검증용) 세 부분으로 구성되어 `.`으로 구분된 문자열 형태
- 서버는 로그인 시 JWT를 발급하고, 이후 클라이언트가 매 요청마다 이 토큰을 함께 보내면 서버는 **서명만 검증**해 신원을 확인함(서버가 세션 상태를 별도로 저장·조회할 필요가 없음)
- 이 무상태(stateless) 특성 덕분에 여러 서버로 요청이 분산되는 환경에서도 별도의 [[세션(Session)]] 공유 없이 인증을 처리할 수 있음

<aside>세션 기반 인증과의 비교</aside>

전통적인 [[세션(Session)]]·[[쿠키(Cookie)]] 기반 인증은 서버가 세션 저장소에 상태를 유지해야 하지만, JWT는 토큰 자체가 정보를 담고 있어 서버 확장(스케일 아웃) 시 세션 공유 문제에서 비교적 자유롭다는 차이가 있다.

---

<aside>핵심 정리</aside>

- JWT는 서명된 토큰 자체에 사용자 정보를 담아, 서버가 별도 상태를 저장하지 않고도(stateless) 인증을 검증할 수 있게 하는 방식이다
- 서버가 세션 상태를 저장·조회하는 방식이 아니다
