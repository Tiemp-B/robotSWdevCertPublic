# Summary

상태 동기화는 여러 클라이언트(모니터링 화면 등)가 로봇의 **최신 상태를 항상 일치된 값으로 유지**하도록 하는 것으로, 연결이 끊겼다 재연결되었을 때도 상태가 어긋나지 않게 처리하는 것이 핵심 과제다.

# Notes

<aside>상태 동기화에서 고려할 점</aside>

- [[WebSocket]] 같은 지속 연결로 상태 변화를 실시간으로 전달하더라도, 네트워크 단절 등으로 일부 갱신 메시지를 놓칠 수 있음
- 갱신 메시지 몇 개를 놓쳐도 최종적으로는 올바른 상태로 맞춰지도록, **재연결 시 현재 전체 상태를 다시 받아오는 절차**를 두는 것이 안전함
- 단순히 "변경된 부분만" 계속 흘려보내는 방식만 쓰면, 중간에 메시지를 놓친 클라이언트는 영영 잘못된 상태를 유지하게 될 위험이 있음

"상태 동기화는 한 번 연결을 맺은 뒤에는 재연결 시 상태 불일치 문제를 신경 쓸 필요가 없다"라는 서술은 오답이다 — 상태 동기화의 핵심 과제 중 하나가 오히려 **연결이 끊겼다 재연결되었을 때도 상태가 어긋나지 않도록 보정**하는 것이다.

<aside>WebSocket과의 관계</aside>

[[WebSocket]]은 상태 동기화를 구현하는 실시간 통신 수단으로 활용되며, 연결이 유지되는 동안 변경분만 전송하는 방식과, 재연결 시 전체 상태를 다시 보내는 방식을 함께 설계하는 것이 안정적인 상태 동기화의 핵심이다.

---

<aside>핵심 정리</aside>

- 상태 동기화는 여러 클라이언트가 최신 상태를 일치되게 유지하도록 하는 것이다
- 재연결 시 상태가 어긋나지 않도록 전체 상태를 다시 맞추는 절차가 중요한 과제다
