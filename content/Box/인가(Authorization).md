# Summary

인가(Authorization)는 신원이 확인된 사용자가 **어떤 자원·기능에 접근할 권한이 있는지를 결정**하는 과정으로, "누구인지 확인"하는 [[인증(Authentication)]]과는 순서상·개념상 다른 단계다.

# Notes

<aside>인증과 인가의 차이</aside>

- 인증(Authentication): "당신이 누구인지" 확인하는 과정(로그인)
- 인가(Authorization): 인증된 사용자가 "무엇을 할 수 있는지(권한)" 결정하는 과정(예: 일반 사용자는 조회만, 관리자는 로봇 정지 명령까지 가능)
- 인증이 항상 인가보다 **먼저** 이루어져야 함 — 신원을 모르는 상태에서 권한을 부여할 수는 없음

"인증과 인가는 동일한 개념이며, 로그인에 성공하면 자동으로 시스템의 모든 기능에 접근할 수 있는 권한도 함께 부여된다"라는 서술은 오답이다 — 인증(신원 확인)과 인가(권한 결정)는 **서로 다른 별개의 단계**이며, 로그인에 성공했다고 해서 모든 기능에 대한 권한이 자동으로 부여되는 것은 아니다.

<aside>로봇 원격제어에서의 적용</aside>

로봇 원격제어 시스템에서 일반 관찰자 계정은 상태 조회만 인가하고, 관리자 계정만 정지·이동 같은 제어 명령을 인가하는 식으로 인증 이후 별도의 인가 단계를 두는 것이 안전한 접근 제어 설계다.

---

<aside>핵심 정리</aside>

- 인가는 인증된 사용자가 어떤 자원·기능에 접근할 권한이 있는지 결정하는 과정이다
- 인증(신원 확인)과는 별개의 단계이며, 인증이 항상 먼저 이루어져야 한다
