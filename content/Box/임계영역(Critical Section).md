# Summary

임계영역(Critical Section)은 여러 스레드가 동시에 실행하면 데이터가 꼬일 수 있는 **공유 자원에 접근하는 코드 구간**으로, 한 번에 하나의 스레드만 실행하도록 [[뮤텍스(Mutex)]]·[[세마포어(Semaphore)]] 등으로 보호해야 한다.

# Notes

<aside>임계영역을 보호해야 하는 이유</aside>

- 두 스레드가 동시에 같은 변수를 읽고 수정하면(경쟁 조건, race condition), 실행 순서에 따라 결과가 달라지거나 데이터가 손상될 수 있음
- 임계영역에 들어가기 전 잠금(lock)을 걸고, 나올 때 잠금을 해제해 **한 번에 하나의 스레드만** 그 구간을 실행하도록 보장
- 임계영역은 최소한으로, 가능한 한 짧게 유지하는 것이 성능(다른 스레드의 대기 시간)에 유리함

"임계영역은 여러 스레드가 동시에 진입해도 항상 안전하게 결과가 보장되는, 특별히 보호가 필요 없는 코드 구간을 의미한다"라는 서술은 오답이다 — 임계영역의 핵심은 정반대로 **여러 스레드가 동시에 접근하면 문제가 생길 수 있어 반드시 보호가 필요한 구간**이라는 점이다.

<aside>뮤텍스·데드락과의 관계</aside>

임계영역을 [[뮤텍스(Mutex)]]로 보호할 때, 여러 임계영역(자원)에 대한 잠금 순서가 서로 다르면 [[데드락(Deadlock)]]이 발생할 수 있어 잠금 순서를 통일하는 것이 안전한 설계의 기본이다.

---

<aside>핵심 정리</aside>

- 임계영역은 공유 자원에 접근하는, 동시 접근 시 문제가 생길 수 있는 코드 구간이다
- 반드시 뮤텍스·세마포어 등으로 한 번에 하나의 스레드만 접근하도록 보호해야 한다
