# Summary

C10K 문제는 서버 하나가 **동시에 10,000개(만 단위) 클라이언트 연결을 효율적으로 처리**할 수 있는가에 대한 고전적 성능 과제로, 연결마다 스레드를 하나씩 쓰는 전통적 모델의 한계에서 출발했다.

# Notes

<aside>C10K 문제의 핵심 원인</aside>

- 연결 1개당 스레드(또는 프로세스) 1개를 할당하는 전통적 모델은, 연결 수가 수천~수만으로 늘어나면 스레드 생성·컨텍스트 스위칭 오버헤드로 서버가 감당하지 못하게 됨
- 해결책으로 **이벤트 기반(비동기 I/O) 모델**이 제시됨 — 소수의 스레드가 다수의 연결을 논블로킹 방식으로 관리(예: epoll, [[이벤트 루프(Event Loop)]])

<aside>로봇 서버 프로그램과의 관계</aside>

다수의 로봇·센서 클라이언트가 동시에 접속하는 중앙 관제 서버를 설계할 때, C10K 문제의 해법(이벤트 기반 동시성 처리 모델)을 채택하지 않으면 연결 수가 늘어날수록 서버 응답이 급격히 느려질 수 있다.

---

<aside>핵심 정리</aside>

- C10K 문제는 서버가 수만 개의 동시 연결을 효율적으로 처리할 수 있는가의 과제다
- 해법은 연결당 스레드 할당이 아니라, 이벤트 기반(비동기 I/O)으로 소수 스레드가 다수 연결을 처리하는 것이다
