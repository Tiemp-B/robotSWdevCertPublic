# Summary

액션 모델은 시간이 오래 걸리는 작업을 **목표 전송·중간 피드백·중도 취소**의 흐름으로 관리하는 통신 패턴으로, ROS의 [[ROS Action]]이 이를 구현한 대표적인 사례다.

# Notes

<aside>액션 모델이 필요한 상황</aside>

- 단순 [[요청-응답 모델(Request-Response)]]은 응답이 올 때까지 클라이언트가 계속 대기해야 해서, 오래 걸리는 작업(예: "목표 지점까지 이동")에는 부적합함
- 액션 모델은 목표를 보낸 뒤, 작업이 진행되는 동안 **중간 진행 상황(피드백)을 주기적으로 받고, 필요하면 중도에 취소**할 수 있게 함
- [[발행-구독 모델(Publish-Subscribe)]]·요청-응답과 함께, 통신 목적(단발성 조회 vs 지속적 구독 vs 장시간 작업 관리)에 따라 선택되는 통신 모델 중 하나

"액션 모델은 요청-응답 모델과 동일하게, 작업이 끝날 때까지 진행 상황을 전혀 알 수 없이 최종 결과만 기다리는 방식이다"라는 서술은 오답이다 — 액션 모델의 핵심은 오히려 **작업 도중 피드백을 받을 수 있고 취소도 가능**하다는 점이며, 이것이 단순 요청-응답과의 차이다.

<aside>ROS Action과의 관계</aside>

[[ROS Action]]은 이 액션 모델을 실제로 구현한 ROS의 통신 방식으로, 목표(Goal)·피드백(Feedback)·결과(Result) 세 단계로 오래 걸리는 작업을 관리한다.

---

<aside>핵심 정리</aside>

- 액션 모델은 목표 전송·중간 피드백·중도 취소로 오래 걸리는 작업을 관리하는 통신 패턴이다
- 최종 결과만 기다리는 단순 요청-응답과 달리, 진행 중 피드백과 취소가 가능하다
