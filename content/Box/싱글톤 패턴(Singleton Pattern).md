# Summary

싱글톤 패턴은 어떤 클래스의 **인스턴스가 프로그램 전체에서 오직 하나만 생성**되도록 보장하고, 어디서든 그 하나의 인스턴스에 접근할 수 있는 방법을 제공하는 디자인 패턴이다.

---

<div class="cues-header">Cues</div>

# Notes

<aside>싱글톤 패턴이 쓰이는 상황</aside>

- 로봇 제어기 설정값 관리자, 하드웨어 자원 관리자처럼 **시스템에 단 하나만 존재해야 의미가 있는 객체**를 다룰 때 사용
- 인스턴스를 생성하는 생성자를 외부에서 직접 호출하지 못하게 막고, 클래스 내부에서 유일한 인스턴스를 관리하며 그 인스턴스를 얻는 정적 메서드만 외부에 공개
- 여러 곳에서 동시에 같은 자원(예: 로그 파일, 하드웨어 포트)에 접근할 때 인스턴스가 여러 개면 충돌이 생길 수 있는 상황을 방지

<aside>남용 시 주의점</aside>

싱글톤을 과도하게 사용하면 전역 상태처럼 동작해 [[결합도(Coupling)]]가 높아지고 테스트하기 어려워질 수 있어, 정말로 인스턴스가 하나여야 하는 경우에만 신중히 적용하는 것이 권장된다.

---

<aside>핵심 정리</aside>

- 싱글톤 패턴은 클래스의 인스턴스가 오직 하나만 생성되도록 보장하는 디자인 패턴이다
- 필요할 때마다 새 인스턴스를 생성하는 것이 아니라, 하나의 인스턴스를 계속 재사용한다
