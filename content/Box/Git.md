# Summary

Git은 소스 코드의 변경 이력을 **분산된 각 개발자의 로컬 저장소에 완전한 형태로 저장**하며 추적하는 분산 버전관리 시스템으로, 여러 개발자가 동시에 로봇 소프트웨어를 개발할 때 변경을 병합·추적하는 데 쓰인다.

# Notes

<aside>Git의 분산 구조</aside>

- 중앙 서버 하나만 전체 이력을 갖는 중앙집중형(CVS, SVN 등)과 달리, **각 개발자의 로컬 저장소가 전체 커밋 이력의 완전한 사본**을 가짐
- 이 덕분에 중앙 서버(원격 저장소)에 연결되지 않은 상태에서도 커밋·이력 조회·브랜치 작업이 가능
- 브랜치(branch)를 생성해 독립적으로 작업한 뒤, 병합(merge)으로 다시 합치는 워크플로가 핵심

"Git은 하나의 중앙 서버만이 전체 커밋 이력을 가지고, 로컬 저장소는 그 서버의 최신 파일 사본만 가진다"라는 서술은 오답이다 — Git의 핵심은 오히려 **로컬 저장소도 전체 이력의 완전한 사본**을 갖는 분산 구조라는 점이며, 이 때문에 오프라인 작업과 빠른 이력 조회가 가능하다.

<aside>CASE 도구로서의 위치</aside>

Git은 [[CASE 도구(Computer-Aided Software Engineering)]]의 한 범주인 형상관리(버전관리) 도구로 분류되며, 여러 개발자가 동일한 로봇 아키텍처 코드베이스를 안전하게 병렬로 수정할 수 있게 지원한다.

---

<aside>핵심 정리</aside>

- Git은 각 로컬 저장소가 전체 이력의 완전한 사본을 갖는 분산 버전관리 시스템이다
- 중앙 서버 의존적인 중앙집중형 버전관리와 달리 오프라인 작업·브랜치·병합이 자유롭다
