# Summary

Git에서 브랜치를 통합하는 두 방식인 머지(Merge)와 리베이스(Rebase)는 각각 이력을 보존하는지, 재작성하는지가 다르며, 병합 시 충돌 여부는 두 브랜치의 공통 조상(merge base)을 기준으로 판단된다.

# Notes

<aside>머지(Merge) vs 리베이스(Rebase)</aside>

| 구분 | 머지(Merge) | 리베이스(Rebase) |
|---|---|---|
| 이력 | 두 브랜치의 이력을 그대로 보존, 병합 커밋 생성 | 커밋들을 다른 브랜치 끝으로 옮겨 이력을 재작성 |
| 적합한 상황 | 여러 사람이 공유하는 브랜치 | 개인 작업 브랜치를 정리할 때 |

<aside>3-way 병합(3-Way Merge)과 충돌</aside>

Git은 병합할 때 현재 브랜치, 대상 브랜치, 그리고 두 브랜치가 갈라지기 전의 **공통 조상(merge base)** 세 지점을 비교한다. 서로 다른 부분을 고쳤다면 자동으로 병합하지만, **같은 줄을 서로 다르게 고친 경우에만** 병합 충돌(conflict)로 표시한다.

---

<aside>핵심 정리</aside>

- 머지는 이력을 보존하며 공유 브랜치에, 리베이스는 이력을 재작성하며 개인 브랜치 정리에 적합하다
- Git은 공통 조상을 기준으로 비교해, 같은 줄이 서로 다르게 수정된 경우에만 충돌로 판단한다
