# Summary

코드 스멀(Code Smell)은 버그는 아니지만 더 깊은 설계 문제를 암시하는 코드의 특징이며, Extract Method는 그중 가장 흔한 스멀인 긴 메서드(Long Method)를 해결하는 대표적인 리팩토링 기법이다.

# Notes

<aside>코드 스멀(Code Smell)이란</aside>

- 프로그램이 **정상적으로 동작하지만**, 가독성·유지보수성을 떨어뜨리는 구조적 징후 — 버그가 아니라 "리팩토링이 필요하다"는 신호
- 대표적인 스멀: **긴 메서드(Long Method)** — 하나의 메서드가 너무 많은 책임을 맡아 길어진 경우, 중복 코드, 지나치게 큰 클래스 등

<aside>Extract Method — 긴 메서드를 해결하는 대표 기법</aside>

긴 메서드 안에서 하나의 독립적인 역할을 하는 코드 덩어리를 찾아, 이름을 붙여 **별도의 메서드로 분리**하고 원래 자리에서는 그 메서드를 호출하도록 바꾸는 리팩토링 기법이다. 각 메서드가 하나의 책임만 맡게 되어, 이 방향은 SOLID 원칙의 **단일 책임 원칙(SRP)** 이 지향하는 바와도 통한다.

---

<aside>핵심 정리</aside>

- 코드 스멀은 버그가 아니라 리팩토링이 필요함을 알리는 구조적 징후이며, 긴 메서드가 대표적이다
- Extract Method는 긴 메서드에서 독립적인 코드 덩어리를 별도 메서드로 분리하는 대표적인 리팩토링 기법이다
