# Summary

API(Application Programming Interface)는 서로 다른 소프트웨어 컴포넌트가 통신할 수 있도록 정한 규칙·프로토콜의 집합으로, 내부 구현을 몰라도 정해진 방식으로 기능을 요청할 수 있게 하는 추상화 계약이다.

# Notes

<aside>API의 역할</aside>

- 서로 다른 컴포넌트가 주고받을 수 있는 **요청·데이터 형식(계약)** 을 정의
- 호출하는 쪽은 **내부 구현을 몰라도** 정해진 방식으로 기능을 이용 가능(추상화)
- 검증된 기능을 재사용하게 해 개발 속도를 높이고, 접근 방식을 표준화해 여러 개발자·컴포넌트 간 협업을 쉽게 함

"API는 내부 구현 세부사항까지 그대로 노출해, 호출하는 쪽이 내부 코드를 직접 조작할 수 있게 하는 것이 핵심이다"라는 서술은 오답이다 — API의 핵심은 오히려 **"무엇을 할 수 있는지"(계약)만 정의**하고 "어떻게 구현되는지"는 감추는 것이다.

<aside>로봇 소프트웨어에서의 활용 — 하드웨어 추상화</aside>

로봇 소프트웨어에서 API는 흔히 [[HAL(Hardware Abstraction Layer)|HAL(하드웨어 추상화 계층)]]이 제공하는 **표준 인터페이스** 형태로 구현된다. 상위 애플리케이션은 이 API만 호출하면 되고, 실제 센서·모터가 어떤 제품으로 바뀌어도 API가 동일하게 유지되면 상위 코드를 거의 수정하지 않아도 된다.

---

<aside>핵심 정리</aside>

- API는 컴포넌트 간 통신 규칙(계약)을 정의하며, 내부 구현은 감추는 추상화 수단이다
- 로봇 소프트웨어에서는 HAL이 제공하는 표준 인터페이스 형태로 자주 구현되어, 하드웨어가 바뀌어도 상위 코드 영향을 최소화한다
