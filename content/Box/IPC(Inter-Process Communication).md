# Summary

IPC(프로세스 간 통신)는 메모리 공간이 분리된 서로 다른 프로세스들이 **데이터를 주고받거나 동작을 동기화**할 수 있도록 운영체제가 제공하는 메커니즘의 총칭이다.

# Notes

<aside>주요 IPC 메커니즘</aside>

| 메커니즘 | 특징 |
|---|---|
| 파이프(Pipe) | 한 프로세스의 출력을 다른 프로세스의 입력으로 연결(주로 부모-자식 간) |
| 공유 메모리(Shared Memory) | 여러 프로세스가 동일한 메모리 영역에 직접 접근 — 가장 빠르지만 동기화([[뮤텍스(Mutex)]] 등) 필요 |
| [[메시지 큐(Message Queue)]] | 메시지 단위로 데이터를 큐에 넣고 꺼내는 방식 |
| 소켓(Socket) | 같은 컴퓨터뿐 아니라 네트워크로 떨어진 프로세스 간 통신도 가능 |

"프로세스는 메모리 공간을 공유하는 스레드와 마찬가지로, 별도의 IPC 메커니즘 없이도 서로의 변수에 직접 접근할 수 있다"라는 서술은 오답이다 — 프로세스는 스레드와 달리 **메모리 공간이 분리**되어 있어, 데이터를 주고받으려면 반드시 IPC 메커니즘을 거쳐야 한다.

<aside>로봇 소프트웨어에서의 활용</aside>

로봇 소프트웨어에서 센서 처리 프로세스와 제어 프로세스가 별도로 분리되어 있다면, 두 프로세스 간 데이터 전달에는 공유 메모리(빠른 대용량 데이터, 예: 영상 프레임)나 메시지 큐(제어 명령 등 이산적 이벤트)처럼 목적에 맞는 IPC 방식을 선택한다.

---

<aside>핵심 정리</aside>

- IPC는 메모리 공간이 분리된 프로세스 간 데이터 교환·동기화를 위한 메커니즘의 총칭이다
- 프로세스는 스레드와 달리 메모리를 공유하지 않으므로 IPC 없이는 직접 통신할 수 없다
