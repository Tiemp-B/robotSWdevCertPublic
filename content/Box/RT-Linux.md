# Summary

RT-Linux는 표준 리눅스 커널 아래에 **별도의 초소형 실시간 마이크로커널을 두고, 일반 리눅스를 그 마이크로커널의 최저 우선순위 태스크로 실행**시켜 실시간성을 확보하는 접근 방식이다.

# Notes

<aside>RT-Linux의 이중 커널 구조</aside>

- 실시간 마이크로커널이 하드웨어 인터럽트를 먼저 가로채고, 실시간 태스크에 우선적으로 CPU를 배정함
- 일반 리눅스 커널은 이 실시간 마이크로커널 위에서 **가장 낮은 우선순위의 태스크 중 하나**로 취급되어, 실시간 태스크가 없을 때만 실행됨
- 이 구조 덕분에 리눅스 커널 내부의 비선점 구간이 있어도, 실시간 태스크의 응답성은 리눅스와 무관하게 보장됨

"RT-Linux는 표준 리눅스 커널 코드 자체를 수정해 선점성을 높이는 패치 방식이다"라는 서술은 오답이다 — RT-Linux의 핵심은 오히려 **리눅스 밖에 별도의 실시간 마이크로커널을 두고 리눅스를 그 아래 태스크로 실행**시키는 이중 커널 구조이며, 리눅스 커널 자체를 패치하는 방식은 [[PREEMPT_RT]]에 가깝다.

<aside>PREEMPT_RT·Xenomai와의 비교</aside>

RT-Linux와 [[Xenomai]]는 둘 다 리눅스 밖의 별도 실시간 도메인을 두는 이중 커널 접근인 반면, [[PREEMPT_RT]]는 리눅스 커널 자체를 패치해 개조하는 단일 커널 접근이라는 근본적 차이가 있다.

---

<aside>핵심 정리</aside>

- RT-Linux는 별도의 실시간 마이크로커널 아래에 리눅스를 최저 우선순위 태스크로 두는 이중 커널 구조다
- 리눅스 커널 자체를 패치하는 방식(PREEMPT_RT)과는 접근이 다르다
