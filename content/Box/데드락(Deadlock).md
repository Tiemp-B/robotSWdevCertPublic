# Summary

데드락(교착 상태)은 둘 이상의 프로세스(또는 스레드)가 **서로 상대방이 점유한 자원을 기다리며 무한정 멈춰버리는** 상태로, 아무도 자원을 양보하지 않으면 영원히 풀리지 않는다.

# Notes

<aside>데드락 발생의 4가지 조건</aside>

| 조건 | 의미 |
|---|---|
| 상호 배제 | 자원을 한 번에 하나의 프로세스만 사용 가능 |
| 점유와 대기 | 자원을 가진 채로 다른 자원을 기다림 |
| 비선점 | 다른 프로세스가 강제로 자원을 뺏을 수 없음 |
| 순환 대기 | A는 B가 가진 자원을, B는 A가 가진 자원을 기다리는 원형 대기 |

이 4가지 조건이 **모두 동시에 성립**해야 데드락이 발생하며, 하나라도 깨뜨리면(예: 자원을 항상 정해진 순서로 요청해 순환 대기를 방지) 데드락을 예방할 수 있다.

"데드락은 하나의 프로세스가 자원을 요청했다가 거부당하면 즉시 발생하는 흔한 현상이다"라는 서술은 오답이다 — 데드락은 단순 거부가 아니라 **여러 프로세스가 서로의 자원을 순환적으로 기다리며 아무도 진행하지 못하는 특수한 교착 상태**이며, 4가지 조건이 모두 성립해야 발생한다.

<aside>세마포어·뮤텍스와의 관계</aside>

[[세마포어(Semaphore)]]·[[뮤텍스(Mutex)]]로 자원 접근을 동기화할 때, 여러 자원을 서로 다른 순서로 잠그면 데드락이 발생할 위험이 있다 — 자원 잠금 순서를 통일하는 것이 대표적인 예방책이다.

---

<aside>핵심 정리</aside>

- 데드락은 여러 프로세스가 서로의 자원을 순환적으로 기다리며 무한정 멈추는 상태다
- 상호배제·점유와대기·비선점·순환대기 4조건이 모두 성립해야 발생한다
