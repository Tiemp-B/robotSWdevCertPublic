# Summary

폴링은 CPU가 **주기적으로 직접 장치의 상태를 확인하러 가는** 방식으로, 구현이 간단하고 이식성이 높지만 신호가 없을 때도 계속 확인해야 해 CPU 자원을 소모하고 응답이 지연될 수 있다.

# Notes

<aside>폴링과 인터럽트의 차이</aside>

- 폴링: CPU가 "신호가 왔나?"를 반복문으로 계속 직접 확인 — 구현이 단순하고 하드웨어 의존성이 적어 이식성이 높음
- [[인터럽트 서비스 루틴(ISR)]] 기반 처리: 신호가 발생했을 때만 하드웨어가 CPU에 즉시 알려, CPU는 그 사이 다른 작업을 자유롭게 수행 가능
- 폴링은 신호가 없는 동안에도 계속 확인 작업 자체에 CPU 시간을 쓰므로, 폴링 주기 사이에 짧게 발생했다 사라지는 신호를 놓칠 위험도 있음

<aside>인터럽트와의 트레이드오프</aside>

폴링은 구현이 단순하고 이식성이 높은 대신 자원 효율이 낮고, 인터럽트는 자원 효율이 높고 즉각적인 대신 구현이 하드웨어에 더 의존적이라는 트레이드오프가 있어 상황에 맞게 선택한다.

---

<aside>핵심 정리</aside>

- 폴링은 CPU가 주기적으로 직접 장치 상태를 확인하는 방식으로, 구현이 단순하지만 자원 효율이 낮다
- 인터럽트 방식보다 항상 빠르거나 효율적인 것은 아니다
