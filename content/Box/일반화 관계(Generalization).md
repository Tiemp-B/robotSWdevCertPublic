# Summary

일반화(Generalization) 관계는 두 액터 사이 또는 두 사용 사례 사이에 "~은 ~의 한 종류다(is-a)"라는 상속 관계를 표현하는 UML 사용 사례 다이어그램의 관계로, 포함·확장 관계와는 성격이 다르다.

# Notes

<aside>일반화의 의미</aside>

- 부모(상위) 액터·사용 사례의 속성과 행동을 자식(하위)이 그대로 물려받으면서, 자신만의 특성을 추가로 가짐
- 액터 간에도, 사용 사례 간에도 적용 가능 — 예: "결제한다"는 사용 사례에 "카드로 결제한다", "현금으로 결제한다"가 일반화의 자식 사용 사례가 될 수 있음

<aside>포함·확장과의 성격 차이</aside>

| 관계 | 성격 |
|---|---|
| 포함(include) | 사용 사례 간 **실행 관계** — 반드시 함께 수행 |
| 확장(extend) | 사용 사례 간 **실행 관계** — 조건이 성립할 때만 수행 |
| 일반화(Generalization) | 액터·사용 사례 간 **분류(상속) 관계** — is-a |

---

<aside>핵심 정리</aside>

- 일반화는 액터·사용 사례 사이의 상속(is-a) 관계를 나타낸다
- 포함·확장이 실행 관계를 다루는 것과 달리, 일반화는 분류 관계를 다룬다
