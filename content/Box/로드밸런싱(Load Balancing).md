# Summary

로드밸런싱은 여러 대의 서버로 들어오는 요청을 **고르게 분산**시켜, 특정 서버 한 대에 부하가 몰려 전체 서비스가 느려지거나 마비되는 것을 방지하는 기법이다.

# Notes

<aside>로드밸런싱의 필요성</aside>

- 하나의 서버로만 모든 요청을 처리하면, 요청량이 늘어날수록 그 서버의 처리 한계에 부딪혀 응답이 느려지거나 다운될 위험이 커짐
- 로드밸런서가 여러 서버(서버 풀) 중 하나로 요청을 분배해, **전체 처리량을 늘리고 특정 서버의 과부하를 방지**함
- 서버를 늘려서 처리 능력을 확장하는 수평 확장(scale-out) 전략의 핵심 요소

"로드밸런싱은 하나의 서버 성능(CPU, 메모리)을 더 강력하게 업그레이드하는 것을 의미한다"라는 서술은 오답이다 — 이는 수직 확장(scale-up)에 해당하며, 로드밸런싱의 핵심은 오히려 **여러 서버로 요청을 분산**시키는 수평 확장 전략의 일부라는 점이다.

<aside>스티키 세션과의 관계</aside>

로드밸런싱을 적용하면 같은 사용자의 요청이 매번 다른 서버로 분산될 수 있어, 서버가 세션 상태를 저장하는 방식이면 문제가 생길 수 있다 — 이때 [[스티키 세션(Sticky Session)]]으로 같은 사용자를 항상 같은 서버로 보내거나, [[JWT(JSON Web Token)]] 같은 무상태 인증으로 이 문제를 회피한다.

---

<aside>핵심 정리</aside>

- 로드밸런싱은 여러 서버로 요청을 분산시켜 과부하를 방지하는 기법이다
- 하나의 서버 성능을 높이는 수직 확장이 아니라, 서버 대수를 늘리는 수평 확장의 일부다
