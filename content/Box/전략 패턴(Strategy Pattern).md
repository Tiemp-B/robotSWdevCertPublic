# Summary

전략(Strategy) 패턴은 여러 알고리즘을 각각 별도의 클래스로 캡슐화해, 런타임에 서로 바꿔 끼울 수 있게 하는 행위 디자인 패턴이다.

# Notes

<aside>전략 패턴의 구조</aside>

- 같은 목적을 달성하는 여러 알고리즘(전략)을 각각 독립된 클래스로 구현
- 클라이언트(외부 코드)가 상황에 맞는 전략을 선택해 주입하면, 그 전략에 따라 동작이 달라짐
- 각 전략은 서로의 존재를 모르는 독립적인 관계

<aside>로봇 소프트웨어에서의 활용 — 항법 알고리즘 교체</aside>

로봇의 경로 탐색 방식을 상황에 따라 바꿔야 할 때, "장애물 회피 우선 전략", "최단 거리 우선 전략"처럼 각 알고리즘을 별도 클래스로 만들어 두고, 환경 조건에 따라 적절한 전략을 골라 로봇에 주입하는 식으로 활용한다.

전략 패턴은 여러 알고리즘 중 하나를 클라이언트(외부)가 고정적으로 골라 주입하는 데 초점을 두는 반면, **상태(State) 패턴**은 상황이 바뀔 때마다 객체 스스로 행동(상태)을 전환하는 데 초점을 둔다 — 로봇의 "상태 기계"로 구현하는 동작 전환은 상태 패턴에 더 가깝다.

---

<aside>핵심 정리</aside>

- 전략 패턴은 여러 알고리즘을 캡슐화해 런타임에 교체 가능하게 하며, 클라이언트가 전략을 선택·주입한다
- 객체 스스로 내부 상태에 따라 행동을 바꾸는 것은 상태(State) 패턴이며, 전략 패턴과는 다르다
