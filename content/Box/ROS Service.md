# Summary

ROS Service는 클라이언트가 요청을 보내면 서버가 처리 후 **응답을 반환할 때까지 동기적으로 기다리는** ROS의 요청-응답 통신 모델로, 짧고 즉시 끝나는 작업에 적합하다.

# Notes

<aside>Service의 동작 방식</aside>

- 클라이언트 노드가 서비스 요청(request)을 보내면, 서비스를 제공하는 서버 노드가 처리한 뒤 응답(response)을 돌려줌
- 요청을 보낸 클라이언트는 응답이 올 때까지 **대기**하는 동기적(blocking) 방식이 기본
- [[발행-구독 모델(Publish-Subscribe)]]처럼 지속적인 데이터 스트림이 아니라, 필요할 때 한 번 요청하고 한 번 응답받는 단발성 상호작용에 적합

"ROS Service는 발행-구독 모델과 마찬가지로, 요청 없이도 서버가 주기적으로 데이터를 계속 밀어내는 방식이다"라는 서술은 오답이다 — Service의 핵심은 오히려 **클라이언트의 명시적 요청이 있어야만 서버가 응답**하는 단발성 요청-응답 방식이라는 점이며, 이는 발행-구독 모델과 다른 통신 패턴이다.

<aside>오래 걸리는 작업과의 관계</aside>

Service는 요청 후 응답까지 클라이언트가 계속 대기해야 하므로, 시간이 오래 걸리는 작업(내비게이션 등)에는 부적합하다 — 그런 경우 진행 상황 피드백과 취소를 지원하는 [[ROS Action]]을 사용한다.

---

<aside>핵심 정리</aside>

- ROS Service는 클라이언트의 요청에 서버가 동기적으로 응답하는 단발성 요청-응답 통신 모델이다
- 서버가 요청 없이 계속 데이터를 밀어내는 발행-구독 방식과는 다르다
