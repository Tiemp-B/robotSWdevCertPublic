# Summary

캐시 무효화는 원본 데이터가 변경되었을 때 **캐시에 저장된 예전(stale) 값을 더 이상 유효하지 않은 것으로 처리**하는 것으로, 캐싱 전략에서 성능만큼 중요한 정합성 문제를 다룬다.

# Notes

<aside>캐시 무효화가 필요한 이유</aside>

- 캐싱은 자주 조회되는 데이터를 미리 저장해두고 빠르게 응답하기 위한 기법이지만, 원본 데이터가 바뀌면 캐시에 남아있는 값은 낡은(stale) 값이 됨
- 이 낡은 값을 그대로 계속 제공하면 사용자는 실제와 다른 잘못된 정보를 보게 됨 — 캐시 무효화로 이런 값을 제거하거나 갱신해야 함
- 무효화 시점과 방식(즉시 무효화, 일정 시간 후 만료(TTL) 등)을 어떻게 설계하느냐가 캐싱 전략의 핵심 과제 중 하나

<aside>성능과 정합성의 트레이드오프</aside>

캐시를 자주 무효화하면 정합성은 높아지지만 캐시 히트율이 낮아져 성능 이점이 줄어들고, 무효화를 드물게 하면 성능은 좋아지지만 낡은 데이터를 보여줄 위험이 커진다 — 이 트레이드오프가 캐싱 전략 설계의 핵심 고려사항이다.

---

<aside>핵심 정리</aside>

- 캐시 무효화는 원본이 바뀌었을 때 캐시의 낡은 값을 유효하지 않은 것으로 처리하는 것이다
- 캐시값을 영구적으로 유지하는 것이 아니라, 원본 변경에 맞춰 갱신·무효화해야 정합성이 유지된다
