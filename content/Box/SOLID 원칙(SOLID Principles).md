# Summary

SOLID 원칙은 유지보수하기 쉽고 확장 가능한 객체지향 소프트웨어를 만들기 위한 **5가지 설계 원칙(단일 책임·개방-폐쇄·리스코프 치환·인터페이스 분리·의존관계 역전)**의 앞글자를 딴 것이다.

# Notes

<aside>SOLID 5원칙</aside>

| 원칙 | 핵심 내용 |
|---|---|
| S — 단일 책임 원칙(SRP) | 클래스는 하나의 책임(변경 이유)만 가져야 함 |
| O — 개방-폐쇄 원칙(OCP) | 확장에는 열려있고, 기존 코드 수정에는 닫혀있어야 함 |
| L — 리스코프 치환 원칙(LSP) | 자식 클래스는 부모 클래스를 대체해도 문제가 없어야 함 |
| I — 인터페이스 분리 원칙(ISP) | 클라이언트가 사용하지 않는 인터페이스에 의존하지 않아야 함 |
| D — 의존관계 역전 원칙(DIP) | 구체적인 구현이 아니라 추상화에 의존해야 함 |

이 원칙들을 지키면 특정 모듈의 변경이 다른 모듈에 미치는 영향이 줄어들어, [[결합도(Coupling)]]가 낮아지고 [[응집도(Cohesion)]]는 높아지는 효과가 있다. 특히 개방-폐쇄 원칙(OCP)은 기존 코드를 직접 수정하는 대신 **상속·인터페이스를 통한 확장**으로 새 기능을 추가하는 것이 핵심 수단이다.

<aside>디자인 패턴과의 관계</aside>

[[옵저버 패턴(Observer Pattern)]]·[[MVC 패턴(Model-View-Controller)]] 같은 디자인 패턴들은 SOLID 원칙(특히 개방-폐쇄, 의존관계 역전)을 실제 코드 구조로 구현하는 구체적인 방법이라고 볼 수 있다.

---

<aside>핵심 정리</aside>

- SOLID는 단일 책임·개방-폐쇄·리스코프 치환·인터페이스 분리·의존관계 역전 5원칙이다
- OCP는 기존 코드 수정 없이 확장 가능해야 한다는 원칙이며, 결합도를 낮추고 응집도를 높이는 데 기여한다
