# Summary

NoSQL은 고정된 테이블·스키마 구조를 강제하지 않는 데이터베이스의 총칭으로, 문서형·키-값형·컬럼형·그래프형 등 **관계형 모델과 다른 유연한 저장 방식**을 통해 대량·비정형 데이터 처리에 적합하다.

# Notes

<aside>NoSQL과 관계형 DB의 차이</aside>

- 관계형 DB(RDB)는 미리 정의된 스키마(테이블 구조)와 SQL, [[트랜잭션(Transaction)]]의 강한 일관성을 중시
- NoSQL은 스키마를 유연하게(또는 없이) 다루고, 수평 확장(여러 서버로 데이터 분산)에 강점이 있어 대용량·비정형 데이터에 적합
- 대신 일부 NoSQL은 강한 일관성 대신 최종 일관성(eventual consistency)을 채택해 성능·확장성을 우선하는 경우가 많음

"NoSQL은 관계형 데이터베이스보다 항상 엄격한 스키마와 강한 트랜잭션 일관성을 요구하는 데이터베이스다"라는 서술은 오답이다 — NoSQL의 핵심은 오히려 **고정 스키마를 강제하지 않고, 확장성·유연성을 위해 일관성 모델을 완화**하는 경우가 많다는 점이며, 이는 관계형 DB와 반대되는 특징이다.

<aside>로봇 데이터 관리에서의 활용</aside>

로봇이 수집하는 다양한 형식의 센서 로그·이벤트 데이터처럼 스키마가 자주 바뀌거나 정형화되지 않은 대용량 데이터를 저장할 때, [[시계열 데이터베이스(Time Series Database)]] 같은 NoSQL 계열이 관계형 DB보다 적합한 경우가 많다.

---

<aside>핵심 정리</aside>

- NoSQL은 고정 스키마를 강제하지 않는 유연한 데이터베이스 총칭으로, 대량·비정형 데이터와 수평 확장에 강점이 있다
- 관계형 DB보다 스키마·일관성 요구가 오히려 완화되는 경우가 많다
