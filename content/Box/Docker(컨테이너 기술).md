# Summary

Docker는 애플리케이션과 그 실행에 필요한 라이브러리·설정을 **컨테이너라는 격리된 단위로 패키징**해, "내 컴퓨터에서는 되는데" 문제 없이 어디서든 동일하게 실행할 수 있게 하는 컨테이너 기술이다.

# Notes

<aside>컨테이너와 가상머신(VM)의 차이</aside>

- 가상머신은 하드웨어를 가상화해 게스트 OS 전체를 통째로 띄우는 반면, 컨테이너는 **호스트 OS의 커널을 공유**하면서 프로세스·파일시스템만 격리함
- 이 덕분에 컨테이너는 VM보다 훨씬 가볍고 시작 속도가 빠르며, 자원 오버헤드도 적음
- 다만 커널을 공유하므로 VM만큼 완전한 격리는 아니라는 트레이드오프가 있음

"Docker 컨테이너는 가상머신처럼 각각 별도의 게스트 운영체제 커널을 실행한다"라는 서술은 오답이다 — 컨테이너의 핵심은 오히려 **호스트 OS 커널을 공유**하면서 프로세스 단위로 격리한다는 점이며, 이 때문에 VM보다 가볍다.

<aside>Docker Compose — 여러 컨테이너를 함께 관리</aside>

로봇 소프트웨어는 흔히 센서 드라이버·인식 알고리즘·UI처럼 여러 컨테이너가 함께 동작해야 한다. **Docker Compose**는 이런 다중 컨테이너의 구성(이미지·네트워크·실행 순서)을 하나의 설정 파일로 정의해, 명령 하나로 전체 컨테이너 묶음을 함께 시작·중지할 수 있게 해준다.

<aside>로봇 소프트웨어 개발 환경에서의 활용</aside>

로봇 소프트웨어 개발에서는 특정 버전의 ROS·라이브러리 조합을 컨테이너 이미지로 고정해, 개발자마다 환경이 달라 발생하는 문제를 줄이고 배포·재현성을 높이는 데 Docker가 널리 쓰인다.

---

<aside>핵심 정리</aside>

- Docker는 호스트 OS 커널을 공유하며 프로세스 단위로 격리하는 경량 컨테이너 기술이다
- 가상머신처럼 별도 게스트 OS 커널을 실행하지 않기 때문에 더 가볍고 빠르다
