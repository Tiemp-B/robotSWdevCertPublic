# Summary

이중 뱅크(dual-bank, A/B) 펌웨어 업데이트는 현재 실행 중인 펌웨어(A)를 그대로 구동하면서 새 펌웨어를 비활성 영역(B)에 받아 검증한 뒤 전환하는 구조로, 업데이트가 실패해도 기존 펌웨어로 롤백할 수 있어 기기가 완전히 먹통("벽돌")이 되는 것을 막는다.

# Notes

<aside>이중 뱅크 구조의 동작 흐름</aside>

1. **A 뱅크(현재 활성)**는 기존 펌웨어를 그대로 계속 실행한다
2. 새 펌웨어를 **B 뱅크(비활성)**에 내려받아 저장한다 — 이 과정에서도 A 뱅크는 정상 동작을 유지한다
3. 다운로드가 끝나면 새 펌웨어의 무결성·정상 동작 여부를 **검증**한다
4. 검증을 통과하면 다음 부팅부터 B 뱅크로 전환해 실행하고, **검증에 실패하거나 업데이트가 중단**(전원 차단 등)되면 부트로더가 기존 A 뱅크로 **롤백**한다

"이중 뱅크 방식에서는 새 펌웨어를 받는 동안 기존 펌웨어의 실행을 반드시 중단해야 한다"라는 서술은 오답이다 — 이중 뱅크의 핵심은 오히려 **기존 펌웨어(A)를 계속 실행하면서** 비활성 뱅크(B)에 새 펌웨어를 받는 것이며, 이 덕분에 업데이트 중에도 시스템이 계속 동작할 수 있다.

<aside>왜 필요한가 — 업데이트 실패로 인한 "벽돌" 방지</aside>

단일 영역에만 펌웨어를 덮어쓰는 방식은, 업데이트 도중 정전이나 통신 오류로 쓰기가 중단되면 새 펌웨어도 기존 펌웨어도 온전하지 않은 상태가 되어 기기가 부팅조차 되지 않는("벽돌") 상태에 빠질 수 있다. 이중 뱅크 구조는 항상 하나의 온전한 뱅크를 유지하므로 이런 위험을 피할 수 있다.

---

<aside>핵심 정리</aside>

- 이중 뱅크 업데이트는 현재 뱅크(A)를 실행 유지한 채 새 펌웨어를 비활성 뱅크(B)에 받아 검증 후 전환한다
- 검증 실패나 업데이트 중단 시에는 기존 뱅크로 롤백해, 기기가 완전히 먹통이 되는 것을 방지한다
