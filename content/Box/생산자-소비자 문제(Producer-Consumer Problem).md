# Summary

생산자-소비자 문제는 데이터를 만드는 생산자(Producer)와 그 데이터를 사용하는 소비자(Consumer)가 **공유 버퍼(큐)를 통해 안전하게 데이터를 주고받도록** 동기화해야 하는 고전적인 동시성 문제다.

# Notes

<aside>생산자-소비자 문제에서 막아야 할 상황</aside>

- 버퍼가 가득 찼는데 생산자가 계속 데이터를 넣으려 하면(버퍼 오버플로) 데이터가 유실되거나 오류가 발생할 수 있음
- 버퍼가 비어있는데 소비자가 데이터를 꺼내려 하면(빈 버퍼에서 읽기) 잘못된 데이터를 처리하게 될 수 있음
- [[세마포어(Semaphore)]]나 [[블로킹 큐(Blocking Queue)]]로 버퍼의 상태(가득 참/비어있음)에 따라 생산자·소비자를 적절히 대기시켜 이 문제를 해결

<aside>블로킹 큐와의 관계</aside>

[[블로킹 큐(Blocking Queue)]]는 생산자-소비자 문제의 동기화 로직(가득 참/비어있음 시 대기)을 캡슐화한 자료구조로, 이를 사용하면 세마포어를 직접 다루지 않고도 생산자-소비자 문제를 안전하게 해결할 수 있다.

---

<aside>핵심 정리</aside>

- 생산자-소비자 문제는 공유 버퍼를 통해 생산자·소비자가 안전하게 데이터를 주고받도록 동기화하는 문제다
- 두 속도를 강제로 맞추는 것이 아니라, 버퍼와 동기화로 속도 차이를 완충하는 것이 해법이다
