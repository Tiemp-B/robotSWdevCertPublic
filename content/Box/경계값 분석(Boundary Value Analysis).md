# Summary

경계값 분석은 입력값의 **정상 범위와 비정상 범위가 갈리는 경계 지점**(최소값, 최대값, 그 바로 앞뒤 값)을 집중적으로 테스트하는 기법으로, 오류가 경계 근처에서 자주 발생한다는 경험에 기반한다.

# Notes

<aside>경계값 분석의 테스트 케이스 선정</aside>

- 예를 들어 입력 범위가 1~100이라면, 0, 1, 2(최소 경계 부근)와 99, 100, 101(최대 경계 부근)을 테스트 케이스로 선정
- 범위의 중간값보다 **경계 근처에서 프로그래밍 오류(off-by-one 등)가 발생할 확률이 높다**는 경험적 근거에 기반
- 모든 입력값을 다 테스트할 수 없으므로, 오류 발생 가능성이 높은 지점을 효율적으로 선별하는 테스트 설계 기법

"경계값 분석은 입력 범위의 정중앙값 하나만 테스트하면 전체 범위를 충분히 검증할 수 있다는 가정에 기반한 기법이다"라는 서술은 오답이다 — 경계값 분석의 핵심은 오히려 **범위의 경계(최소·최대와 그 인접값)에서 오류가 자주 발생한다**는 가정에 기반하며, 중앙값 하나만으로는 경계 오류를 잡아낼 수 없다.

<aside>등가 분할과의 관계</aside>

[[등가 분할(Equivalence Partitioning)]]로 입력값을 유효/무효 그룹으로 나눈 뒤, 그 그룹의 경계 지점을 경계값 분석으로 테스트하는 식으로 두 기법을 함께 사용하는 것이 일반적이다.

---

<aside>핵심 정리</aside>

- 경계값 분석은 정상·비정상 범위가 갈리는 경계 지점을 집중적으로 테스트하는 기법이다
- 중앙값이 아니라 경계 근처에서 오류가 자주 발생한다는 경험에 기반한다
