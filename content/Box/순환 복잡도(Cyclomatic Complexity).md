# Summary

순환 복잡도(McCabe's Cyclomatic Complexity)는 코드의 제어 흐름 그래프에서 서로 독립적인 실행 경로의 개수를 세는 복잡도 지표로, 분기 커버리지 100%에 필요한 테스트 케이스 개수의 상한과 같다.

# Notes

<aside>순환 복잡도의 계산</aside>

- 대략 "코드 안의 조건문·반복문의 개수 + 1"로 계산됨(정확히는 제어 흐름 그래프의 간선 수 − 노드 수 + 2)
- 값이 클수록 코드 안에 분기·반복이 많아 구조가 복잡하고, 이해·테스트하기 어려움을 의미

<aside>분기 커버리지와의 관계</aside>

순환 복잡도 값은 그 코드의 **[[코드 커버리지(Code Coverage)|분기 커버리지]] 100%를 달성하는 데 필요한 테스트 케이스 개수의 상한(upper bound)** 과 같다 — 조건문이 많아 순환 복잡도가 높은 코드일수록, 모든 분기를 다 지나가려면 더 많은 테스트 케이스가 필요하다.

<aside>정적 분석 도구에서의 활용</aside>

정적 분석 도구는 순환 복잡도를 함수·모듈 단위로 자동 계산해, 값이 지나치게 높은(복잡한) 코드를 리팩터링 대상으로 표시하는 데 활용한다.

---

<aside>핵심 정리</aside>

- 순환 복잡도는 코드의 독립적 실행 경로 수를 세는 지표로, 조건문·반복문이 많을수록 값이 커진다
- 이 값은 분기 커버리지 100%에 필요한 테스트 케이스 개수의 상한과 같다
