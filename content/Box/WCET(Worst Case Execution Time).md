# Summary

WCET(최악 실행 시간)는 어떤 작업이 **최악의 조건에서 실행을 완료하는 데 걸릴 수 있는 가장 긴 시간**을 뜻하며, 실시간 스케줄링 가능성을 분석할 때 평균 실행 시간이 아니라 이 값을 기준으로 삼는다.

# Notes

<aside>WCET을 평균 시간 대신 쓰는 이유</aside>

- 실시간 시스템은 "대부분 빠르게 끝난다"가 아니라 **"항상 마감시한을 지킨다"**는 보장이 필요함
- 평균 실행 시간만으로 스케줄링을 설계하면, 드물게 발생하는 최악의 경우(캐시 미스, 인터럽트 지연 등)에 마감을 놓칠 위험이 남음
- WCET을 기준으로 스케줄링 가능성을 분석하면, 어떤 조건에서도 마감시한을 지킬 수 있는지 보수적으로(안전하게) 판단할 수 있음

<aside>스케줄링 알고리즘과의 관계</aside>

[[Rate Monotonic Scheduling]]·[[Earliest Deadline First(EDF)]] 같은 실시간 스케줄링 알고리즘의 이론적 스케줄링 가능 여부 판단은 각 작업의 WCET을 입력값으로 사용한다 — WCET을 실제보다 낮게 추정하면 이론적으로는 스케줄링 가능해 보여도 실제 최악 상황에서 마감을 놓칠 수 있다.

---

<aside>핵심 정리</aside>

- WCET은 작업이 최악의 조건에서 실행을 완료하는 데 걸리는 가장 긴 시간이다
- 실시간 스케줄링 가능성 분석은 평균 시간이 아니라 WCET을 기준으로 한다
