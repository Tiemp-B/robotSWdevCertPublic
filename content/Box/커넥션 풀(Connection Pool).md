# Summary

커넥션 풀은 데이터베이스 연결을 매번 새로 생성·종료하지 않고, **미리 여러 개의 연결을 만들어두고 필요할 때 재사용**하는 기법으로, 연결 생성 오버헤드를 줄여 서버 성능을 높인다.

# Notes

<aside>커넥션 풀이 필요한 이유</aside>

- 데이터베이스 연결을 새로 맺는 과정(네트워크 핸드셰이크, 인증 등)은 비용이 큰 작업이라, 요청마다 매번 새 연결을 만들면 성능이 크게 저하됨
- 커넥션 풀은 서버 시작 시 일정 개수의 연결을 미리 만들어 풀(pool)에 보관해두고, 요청이 오면 **풀에서 연결을 빌려 쓰고 작업이 끝나면 다시 반납**함
- 매번 연결을 생성·종료하는 오버헤드를 없애 응답 속도를 높이고, 동시에 DB에 연결되는 수를 적절히 제한해 DB 부하도 관리함

"커넥션 풀은 요청이 들어올 때마다 매번 새로운 데이터베이스 연결을 생성해 최신 상태를 보장하는 기법이다"라는 서술은 오답이다 — 커넥션 풀의 핵심은 정반대로 **미리 만들어둔 연결을 재사용**해 매번 새로 생성하는 오버헤드를 없애는 것이다.

<aside>트랜잭션과의 관계</aside>

커넥션 풀에서 빌려온 연결로 [[트랜잭션(Transaction)]]을 수행할 때는, 작업이 끝난 뒤 연결을 풀에 반납하기 전에 트랜잭션이 커밋 또는 롤백되어 정리된 상태인지 확인해야 다음 사용자가 그 연결을 안전하게 재사용할 수 있다.

---

<aside>핵심 정리</aside>

- 커넥션 풀은 미리 만들어둔 DB 연결을 재사용해 연결 생성 오버헤드를 줄이는 기법이다
- 매 요청마다 새 연결을 생성하는 것이 아니라, 풀에서 빌리고 반납하는 방식이다
