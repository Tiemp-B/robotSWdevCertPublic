# Summary

멱등성(Idempotency)은 같은 요청을 **한 번 보내든 여러 번 반복해서 보내든 결과 상태가 동일**한 성질로, 네트워크 오류로 요청이 중복 전송되어도 안전한 API를 설계할 때 중요한 기준이다.

# Notes

<aside>HTTP 메서드별 멱등성</aside>

| 메서드 | 멱등성 | 이유 |
|---|---|---|
| GET | 멱등 | 조회만 하므로 여러 번 호출해도 상태 변화 없음 |
| PUT | 멱등 | 자원을 특정 값으로 "설정"하므로 여러 번 호출해도 같은 결과 |
| DELETE | 멱등 | 이미 삭제된 것을 다시 삭제해도 최종 상태(존재하지 않음)는 동일 |
| POST | 비멱등 | 호출할 때마다 새 자원이 생성되어, 여러 번 호출하면 자원이 중복 생성됨 |

<aside>로봇 원격제어 API 설계에서의 의미</aside>

네트워크 지연으로 같은 명령이 중복 전송될 수 있는 로봇 원격제어 API를 설계할 때, "정지" 명령처럼 멱등한 동작으로 설계해두면 중복 요청이 와도 안전하게 같은 결과를 유지할 수 있다.

---

<aside>핵심 정리</aside>

- 멱등성은 같은 요청을 여러 번 보내도 결과 상태가 동일한 성질이다
- GET·PUT·DELETE는 멱등하지만, POST는 호출마다 새 자원을 생성해 비멱등하다
