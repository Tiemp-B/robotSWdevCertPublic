# Summary

인증 취약점(Broken Authentication)은 로그인·세션 관리 과정의 허점을 이용해 공격자가 **정당한 사용자로 위장**할 수 있게 되는 취약점으로, 입력값 조작이 아니라 인증·세션 관리 절차 자체의 설계 결함에서 비롯된다.

# Notes

<aside>인증 취약점의 대표 원인</aside>

- 약한 비밀번호 정책(짧고 단순한 비밀번호 허용, 다중 인증 미적용)
- 세션 ID가 URL에 노출되는 경우(주소창·로그·브라우저 히스토리에 남아 탈취 위험)
- 로그아웃 후에도 세션이 만료되지 않고 계속 유효한 경우

<aside>SQL Injection·XSS와의 차이</aside>

SQL Injection·XSS가 악의적인 입력값을 데이터베이스나 브라우저에 주입하는 공격이라면, 인증 취약점은 그런 입력 조작 없이도 **인증·세션 관리 절차 자체의 허점**만으로 성립하는 취약점이라는 점이 다르다.

---

<aside>핵심 정리</aside>

- 인증 취약점은 인증·세션 관리 절차의 설계 결함으로 공격자가 정당한 사용자로 위장할 수 있게 되는 취약점이다
- 강력한 비밀번호 정책·다중 인증, 세션 쿠키의 HttpOnly, 세션 자동 만료가 기본 방어책이다
