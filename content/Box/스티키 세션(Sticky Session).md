# Summary

스티키 세션은 [[로드밸런싱(Load Balancing)]] 환경에서 **같은 클라이언트의 요청을 항상 같은 서버로 보내도록 고정**하는 정책으로, 서버가 세션 상태를 로컬에 저장하는 방식일 때 상태 불일치를 막기 위해 쓰인다.

# Notes

<aside>스티키 세션이 필요한 상황</aside>

- 각 서버가 [[세션(Session)]] 정보를 자신의 로컬 메모리에만 저장하고 있다면, 로드밸런서가 같은 사용자의 요청을 매번 다른 서버로 보낼 경우 그 서버에는 해당 사용자의 세션 정보가 없어 문제가 생김
- 스티키 세션은 로드밸런서가 **같은 클라이언트를 항상 같은 서버로 고정**해서 보내, 이런 세션 불일치 문제를 회피함
- 다만 특정 서버에 특정 사용자들이 쏠리면 부하 분산 효과가 줄어들 수 있다는 단점이 있음

<aside>다른 해법과의 비교</aside>

스티키 세션 대신, 세션 정보를 여러 서버가 공유하는 중앙 저장소에 두거나 [[JWT(JSON Web Token)]]처럼 서버가 상태를 저장하지 않는 방식을 쓰면 로드밸런싱의 부하 분산 효과를 유지하면서도 세션 문제를 해결할 수 있다.

---

<aside>핵심 정리</aside>

- 스티키 세션은 같은 클라이언트의 요청을 항상 같은 서버로 고정해 보내는 로드밸런싱 정책이다
- 부하를 고르게 분산시키는 것과는 반대로, 특정 서버로 쏠림이 발생할 수 있다
