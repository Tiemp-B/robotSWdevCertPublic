# Summary

CI(지속적 통합)·지속적 전달(Continuous Delivery)·지속적 배포(Continuous Deployment)는 자동화 수준이 점점 높아지는 세 단계이며, 핵심 차이는 프로덕션 배포 전에 **사람의 승인이 필요한지**다.

# Notes

<aside>세 단계의 차이</aside>

| 단계 | 내용 | 프로덕션 배포 |
|---|---|---|
| CI(지속적 통합) | 코드를 자주 병합하고 자동으로 빌드·테스트 | 배포 단계 아님 |
| 지속적 전달(Continuous Delivery) | 테스트를 통과한 빌드를 항상 배포 가능한 상태로 유지 | **사람이 승인**해야 실제 배포 |
| 지속적 배포(Continuous Deployment) | 지속적 전달에서 승인 단계까지 자동화 | **승인 없이 자동** 배포 |

"지속적 전달(Continuous Delivery)과 지속적 배포(Continuous Deployment)는 완전히 같은 개념으로, 둘 다 사람의 승인 없이 자동으로 프로덕션에 배포한다"라는 서술은 오답이다 — 두 개념의 핵심 차이는 정확히 **사람의 승인 여부**이며, 지속적 전달은 승인이 필요하고 지속적 배포는 승인 없이 자동 배포된다.

<aside>로봇 소프트웨어에서의 활용</aside>

협동로봇처럼 사람과 가까이서 동작하는 로봇 소프트웨어는, 검증된 코드라도 실제 로봇에 곧바로 자동 배포하면 안전 위험이 크다. 그래서 완전 자동인 지속적 배포보다, 사람이 최종 확인 후 배포를 승인하는 **지속적 전달** 방식이 더 흔히 쓰인다.

---

<aside>핵심 정리</aside>

- CI는 빌드·테스트 자동화, 지속적 전달은 배포 준비 상태 유지(승인 필요), 지속적 배포는 승인 없는 완전 자동 배포다
- 로봇처럼 안전이 중요한 소프트웨어는 지속적 배포보다 사람이 승인하는 지속적 전달이 더 안전하다
