# Summary

인터럽트 서비스 루틴(ISR)은 인터럽트가 발생했을 때 CPU가 즉시 실행하는 **짧고 신속한 처리 함수**로, 원래 하던 작업을 잠시 멈추고 실행된 뒤 다시 원래 작업으로 복귀한다.

# Notes

<aside>ISR의 특징</aside>

- 인터럽트 발생 시 CPU는 현재 실행 중인 작업의 상태를 저장하고, 해당 인터럽트에 등록된 ISR로 즉시 제어를 넘김
- ISR은 **최대한 짧고 빠르게 실행**되도록 작성하는 것이 원칙 — 오래 걸리는 처리를 ISR 안에 넣으면 다른 인터럽트 응답이 지연되거나 시스템 전체 반응성이 나빠짐
- ISR 안에서 시간이 걸리는 작업이 필요하면, 플래그만 세팅해두고 실제 처리는 ISR 밖의 일반 코드(메인 루프 등)에서 나중에 수행하는 방식이 일반적

<aside>폴링·워치독과의 관계</aside>

[[폴링(Polling)]]이 계속 감시하며 CPU를 소모하는 반면, ISR 기반 인터럽트 처리는 이벤트가 없을 때 다른 작업을 하다가 필요한 순간에만 짧게 개입한다는 점에서 자원 효율이 더 높다.

---

<aside>핵심 정리</aside>

- ISR은 인터럽트 발생 시 즉시 실행되는 짧고 신속한 처리 함수다
- 오래 걸리는 처리는 ISR 안이 아니라 ISR 밖에서 나중에 수행하도록 미루는 것이 원칙이다
