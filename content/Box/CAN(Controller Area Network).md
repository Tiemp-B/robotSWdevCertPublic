# Summary

CAN(Controller Area Network)은 **다중 마스터(멀티마스터) 구조**로 여러 제어기(ECU)가 하나의 버스를 공유하며 통신하는 필드버스로, 메시지 ID의 우선순위에 따라 버스 접근 충돌을 조정(버스 중재)한다.

# Notes

<aside>CAN의 멀티마스터 구조와 버스 중재</aside>

- 특정 장치가 항상 마스터 역할을 고정하는 것이 아니라, **버스에 연결된 모든 노드가 대등하게 메시지를 송신**할 수 있음(멀티마스터)
- 여러 노드가 동시에 송신을 시도하면, 메시지에 부여된 **ID 값이 낮을수록(우선순위가 높을수록)** 버스 점유권을 얻는 방식으로 충돌을 중재(비파괴적 중재)
- 이 구조 덕분에 중요한 제어 메시지(낮은 ID)가 덜 중요한 메시지(높은 ID)보다 항상 먼저 전송됨을 보장

"CAN 통신은 고정된 하나의 마스터 장치만 버스에 메시지를 송신할 수 있는 단일 마스터 구조다"라는 서술은 오답이다 — CAN의 핵심은 오히려 **여러 노드가 대등하게 송신할 수 있는 멀티마스터 구조**이며, 우선순위가 낮은 메시지 ID가 버스를 먼저 점유하도록 중재된다.

<aside>로봇 제어기에서의 활용</aside>

로봇 관절 모터 드라이버, 센서 모듈 등 여러 제어기가 하나의 버스에 물려 실시간으로 상태·명령을 주고받아야 할 때 CAN이 널리 쓰인다. 노이즈에 강한 차동 신호 방식과 오류 검출 기능도 산업·차량 환경에서 CAN이 선호되는 이유다.

---

<aside>핵심 정리</aside>

- CAN은 멀티마스터 구조의 필드버스로, 메시지 ID 우선순위로 버스 접근을 비파괴적으로 중재한다
- 단일 고정 마스터 구조가 아니다
