# Summary

V-모델은 개발 단계(요구사항→설계→구현)와 대응하는 검증 단계(단위→통합→시스템 시험)를 **V자 형태로 짝지어**, 각 개발 단계에서 무엇을 검증해야 하는지를 명확히 하는 소프트웨어 개발·시험 프로세스 모델이다.

# Notes

<aside>V-모델의 좌우 대응 관계</aside>

| 개발 단계(왼쪽) | 대응 시험 단계(오른쪽) |
|---|---|
| 요구사항 분석 | 인수 시험(요구사항을 만족하는지) |
| 시스템 설계 | 시스템 시험(전체 시스템이 설계대로 동작하는지) |
| 상세 설계 | 통합 시험(모듈 간 연동이 설계대로 동작하는지) |
| 구현(코딩) | 단위 시험(개별 모듈이 의도대로 동작하는지) |

이렇게 각 개발 단계마다 **대응하는 시험 단계를 미리 정의**해두면, 구현이 끝난 뒤에야 어떻게 시험할지 고민하는 대신 개발 초기부터 시험 계획을 함께 수립할 수 있다.

"V-모델에서는 모든 개발 단계가 끝난 뒤에야 비로소 어떤 시험을 할지 계획을 세우기 시작한다"라는 서술은 오답이다 — V-모델의 핵심은 오히려 **각 개발 단계와 짝을 이루는 시험 단계를 개발 초기부터 미리 정의**해둔다는 점이며, 구현 완료 후에야 계획을 세우는 것이 아니다.

<aside>로봇 시스템 시험평가에서의 활용</aside>

로봇 시스템을 개발할 때 V-모델을 적용하면, 요구사항 분석 단계에서 이미 "이 요구사항을 어떤 인수 시험으로 검증할지"를 함께 정의해, 시스템 시험평가 절차의 누락을 줄일 수 있다.

---

<aside>핵심 정리</aside>

- V-모델은 개발 단계와 대응 시험 단계를 V자 형태로 짝짓는 개발·시험 프로세스 모델이다
- 시험 계획을 구현 완료 후가 아니라, 각 개발 단계와 함께 미리 정의한다
