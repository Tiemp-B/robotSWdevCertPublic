# Summary

응집도(Cohesion)는 하나의 모듈 안에 있는 요소들이 **얼마나 서로 밀접하게 관련된 하나의 책임을 수행하는지**를 나타내는 지표로, 응집도가 높을수록 모듈의 역할이 명확하고 이해·유지보수가 쉽다.

# Notes

<aside>응집도의 높고 낮음</aside>

- 응집도가 높다: 모듈 안의 모든 함수·데이터가 하나의 명확한 목적을 위해 긴밀하게 협력함(예: "사용자 인증"만 담당하는 모듈)
- 응집도가 낮다: 모듈 안에 서로 관련 없는 여러 기능이 뒤섞여 있어, 모듈의 역할이 불명확함(예: 로그 기록과 결제 처리가 한 모듈에 섞여 있음)
- 좋은 설계는 [[결합도(Coupling)]]는 낮추고 **응집도는 높이는** 것을 함께 목표로 함

"좋은 소프트웨어 설계의 목표는 응집도를 낮춰 하나의 모듈이 최대한 다양한 관련 없는 기능을 담당하게 만드는 것이다"라는 서술은 오답이다 — 좋은 설계의 핵심은 오히려 **응집도를 높여** 하나의 모듈이 명확히 관련된 하나의 책임만 담당하게 하는 것이며, 관련 없는 기능을 뒤섞는 것은 낮은 응집도의 특징이다.

<aside>응집도의 7유형(강함 → 약함 순)</aside>

| 유형 | 정의 |
|---|---|
| 기능적(Functional) | 모든 요소가 단 하나의 명확한 기능 수행에 집중 — 가장 강함 |
| 순차적(Sequential) | 한 요소의 출력이 다음 요소의 입력이 됨 |
| 교환·통신적(Communicational) | 다른 기능이지만 같은 입출력 데이터를 공유 |
| 절차적(Procedural) | 특정 순서로 실행되어야 하는 절차들을 모음 |
| 시간적(Temporal) | 같은 시점(초기화·종료 등)에 실행된다는 이유로 묶임 |
| 논리적(Logical) | 범주만 유사하고, 제어 플래그로 분기해 실행 |
| 우연적(Coincidental) | 의미 있는 관련 없이 우연히 한 모듈에 모임 — 가장 약함 |

<aside>결합도와의 관계</aside>

응집도와 [[결합도(Coupling)]]는 함께 논의되는 짝 개념으로, "모듈 내부는 응집도를 높이고, 모듈 간에는 결합도를 낮춘다"는 것이 좋은 모듈화 설계의 기본 원칙이다.

---

<aside>핵심 정리</aside>

- 응집도는 모듈 내부 요소들이 하나의 책임을 위해 얼마나 밀접하게 관련되어 있는지를 나타낸다
- 응집도를 낮추는 것이 아니라 높이는 것이 좋은 설계의 목표다
