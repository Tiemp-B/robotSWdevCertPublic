# Summary

Xenomai는 리눅스 위에 **별도의 실시간 추상화 계층(RTOS 코어)을 두어**, 리눅스의 풍부한 기능(네트워크, 파일시스템 등)과 실시간 애플리케이션에 필요한 예측 가능한 응답성을 함께 제공하려는 접근이다.

# Notes

<aside>Xenomai의 이중 커널 접근</aside>

- [[RT-Linux]]와 유사하게, 리눅스 커널과 별도로 실시간성을 보장하는 계층(코어)을 두어 실시간 태스크를 우선 처리
- 실시간 애플리케이션은 Xenomai의 실시간 API를 사용해 예측 가능한 응답성을 확보하고, 일반 작업은 리눅스가 그대로 처리
- 리눅스의 방대한 드라이버·라이브러리 생태계를 활용하면서도, 실시간이 중요한 부분만 별도 계층에서 엄격하게 관리할 수 있음

"Xenomai는 리눅스 커널 코드 자체를 패치해 선점성을 높이는 단일 커널 방식이다"라는 서술은 오답이다 — Xenomai의 핵심은 오히려 **리눅스와 별도의 실시간 추상화 계층을 두는 이중 커널(또는 코어) 접근**이며, 커널 자체를 패치하는 방식은 [[PREEMPT_RT]]에 가깝다.

<aside>다른 실시간 리눅스 접근과의 관계</aside>

Xenomai, [[RT-Linux]]는 이중 커널 계열, [[PREEMPT_RT]]는 단일 커널 패치 계열로 리눅스 기반 실시간화의 두 가지 큰 접근 방식을 대표한다 — 목적(리눅스 생태계 활용 vs 커널 자체 개조)에 따라 선택이 달라진다.

---

<aside>핵심 정리</aside>

- Xenomai는 리눅스와 별도의 실시간 추상화 계층을 두어 실시간성과 리눅스 생태계를 함께 활용하는 접근이다
- 리눅스 커널 자체를 패치하는 단일 커널 방식이 아니다
