# Summary

세션은 서버가 특정 사용자의 로그인 상태 등 **연속된 여러 요청에 걸친 정보를 서버 측에 유지**하는 방식으로, 클라이언트에는 세션을 식별할 수 있는 세션 ID만 [[쿠키(Cookie)]] 등으로 전달된다.

# Notes

<aside>세션의 동작 방식</aside>

- 사용자가 로그인하면 서버는 그 사용자의 상태(로그인 여부 등)를 서버 측 저장소(메모리, DB 등)에 세션으로 저장하고, 그 세션을 식별하는 세션 ID를 클라이언트에 발급
- 클라이언트는 이후 요청마다 이 세션 ID를 (보통 쿠키에 담아) 함께 보내고, 서버는 그 ID로 저장된 세션 정보를 조회해 사용자를 식별
- HTTP 자체는 무상태(stateless)이므로, 세션은 이 무상태성을 보완해 "로그인 상태 유지" 같은 연속성을 구현하는 방법

"세션 정보는 클라이언트(브라우저)에 전부 저장되며, 서버는 아무 상태도 유지하지 않는다"라는 서술은 오답이다 — 그것은 오히려 [[JWT(JSON Web Token)]] 같은 무상태 인증 방식에 가까우며, 전통적인 세션의 핵심은 **서버 측에 상태를 저장**하고 클라이언트에는 식별자(세션 ID)만 전달한다는 점이다.

<aside>JWT와의 비교</aside>

세션 방식은 서버가 상태를 저장해야 하므로 서버 확장(여러 대로 분산) 시 세션 공유 문제가 발생할 수 있는 반면, [[JWT(JSON Web Token)]]은 토큰 자체에 정보를 담아 서버가 상태를 저장하지 않아도 된다는 차이가 있다.

---

<aside>핵심 정리</aside>

- 세션은 서버 측에 사용자 상태를 저장하고, 클라이언트에는 세션 ID만 전달하는 방식이다
- 클라이언트에 모든 정보를 저장하고 서버가 상태를 유지하지 않는 방식(JWT)과는 반대다
