# Summary

로그 로테이션은 로그 파일이 무한정 커지지 않도록 **일정 주기나 크기마다 현재 로그 파일을 닫고 새 파일을 시작**하며, 오래된 로그는 압축·삭제하는 로그 관리 기법이다.

# Notes

<aside>로그 로테이션이 필요한 이유</aside>

- 로봇이 계속 동작하며 로그를 기록하면, 하나의 로그 파일이 시간이 지날수록 무한정 커져 디스크 공간을 모두 차지하거나 파일을 열람·검색하기 어려워짐
- 로그 로테이션은 일정 주기(매일 등)나 파일 크기 한계에 도달하면 **현재 파일을 보관용으로 이름을 바꾸고, 새로운 빈 로그 파일부터 다시 기록**을 시작함
- 일정 개수·기간이 지난 오래된 로그 파일은 압축하거나 삭제해 디스크 공간을 관리함

"로그 로테이션은 로그 기록을 아예 중단시켜 디스크 공간을 절약하는 기법이다"라는 서술은 오답이다 — 로그 로테이션의 핵심은 로그 기록 자체를 중단하는 것이 아니라, **파일을 주기적으로 교체하면서 로그 기록은 계속 이어가고, 오래된 파일만 정리**하는 것이다.

<aside>이상치 탐지와의 관계</aside>

로그 로테이션으로 관리되는 로그 데이터는 [[IQR(사분위수 범위)]]·[[Z-score(표준점수)]] 같은 기법으로 이상치를 탐지하는 데이터 로깅 파이프라인의 기반이 된다.

---

<aside>핵심 정리</aside>

- 로그 로테이션은 로그 파일을 주기적으로 교체하며 오래된 파일을 정리하는 로그 관리 기법이다
- 로그 기록 자체를 중단하는 것이 아니라, 계속 기록하면서 파일만 교체·정리한다
