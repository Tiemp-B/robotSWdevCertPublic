# Summary

배치 처리는 데이터를 **일정량이 쌓이거나 일정 시간이 지날 때까지 모았다가 한꺼번에 처리**하는 방식으로, 데이터가 발생하는 즉시 처리하는 [[스트림 처리(Stream Processing)]]와 대비된다.

# Notes

<aside>배치 처리와 스트림 처리의 차이</aside>

| 구분 | 처리 시점 | 지연시간 | 적합한 용도 |
|---|---|---|---|
| 배치 처리 | 데이터를 모아뒀다가 주기적으로 한꺼번에 처리 | 큼(다음 배치까지 기다림) | 일별 통계, 대량 로그 분석 |
| 스트림 처리 | 데이터가 발생하는 즉시 하나씩(또는 작은 단위로) 처리 | 작음(거의 실시간) | 실시간 이상 감지, 즉각 알람 |

로봇의 즉각적인 이상 상황을 실시간으로 감지해야 한다면 배치 처리보다 스트림 처리가 적합하며, 반대로 하루치 데이터를 모아 트렌드를 분석하는 용도는 배치 처리가 더 효율적일 수 있다.

"배치 처리는 데이터가 발생하는 즉시 하나씩 실시간으로 처리하는 방식을 의미한다"라는 서술은 오답이다 — 그것은 [[스트림 처리(Stream Processing)]]의 특징이며, 배치 처리의 핵심은 오히려 **데이터를 일정량·일정 시간 모았다가 한꺼번에 처리**하는 것이다.

<aside>실시간 데이터 파이프라인에서의 선택</aside>

로봇 모니터링 시스템을 설계할 때, 즉각적인 알람이 필요한 데이터(배터리 급감 등)는 스트림 처리로, 정기 리포트용 통계는 배치 처리로 나눠 파이프라인을 구성하는 것이 일반적이다.

---

<aside>핵심 정리</aside>

- 배치 처리는 데이터를 모았다가 한꺼번에 처리하는 방식으로, 즉시 처리하는 스트림 처리와 대비된다
- 데이터 발생 즉시 처리하는 것은 배치 처리가 아니라 스트림 처리다
