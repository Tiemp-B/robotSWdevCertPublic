# Summary

코드 커버리지는 테스트를 실행했을 때 **전체 코드 중 실제로 실행된(테스트된) 코드의 비율**을 나타내는 지표로, 테스트가 코드를 얼마나 폭넓게 검증했는지를 정량적으로 보여준다.

# Notes

<aside>코드 커버리지의 한계</aside>

- 코드 커버리지가 100%라는 것은 모든 코드 라인이 최소 한 번은 실행되었다는 의미일 뿐, **그 코드가 모든 경우의 수(모든 입력 조건)에 대해 올바르게 동작함을 보장하는 것은 아님**
- 예를 들어 조건문의 참(true) 분기만 테스트하고 거짓(false) 분기는 테스트하지 않아도, 그 줄 자체는 "실행됨"으로 커버리지에 잡히는 경우가 있음
- 코드 커버리지는 테스트의 폭(어디까지 실행되었나)을 보여줄 뿐, 테스트의 질(그 실행 결과가 올바른지 충분히 검증했는가)까지 보장하지는 않음

"코드 커버리지가 100%이면 그 소프트웨어에 버그가 전혀 없다는 것이 수학적으로 보장된다"라는 서술은 오답이다 — 코드 커버리지의 핵심 한계는 오히려 **코드가 실행되었다는 것만 보여줄 뿐, 모든 경우의 수에 대한 정확성까지 보장하지는 않는다**는 점이다.

<aside>등가 분할·경계값 분석과의 관계</aside>

코드 커버리지를 높이는 것과 별개로, [[등가 분할(Equivalence Partitioning)]]·[[경계값 분석(Boundary Value Analysis)]] 같은 기법으로 의미 있는 테스트 케이스를 설계해야 테스트의 실질적인 질을 높일 수 있다.

---

<aside>핵심 정리</aside>

- 코드 커버리지는 테스트로 실행된 코드의 비율을 나타내는 지표다
- 100% 커버리지가 버그 없음을 보장하지는 않으며, 실행 여부와 정확성 검증은 별개다
