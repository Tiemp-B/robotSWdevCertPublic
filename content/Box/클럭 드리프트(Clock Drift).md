# Summary

클럭 드리프트는 여러 장치의 내부 시계(클럭)가 **각기 미세하게 다른 속도로 흘러 시간이 지날수록 서로 어긋나는** 현상으로, 여러 장치의 타임스탬프를 비교·정렬해야 하는 로봇 시스템에서 반드시 보정해야 하는 오차 요인이다.

# Notes

<aside>클럭 드리프트가 발생하는 이유</aside>

- 모든 장치의 수정 발진자(clock crystal)는 제조 편차, 온도 변화 등으로 정확히 동일한 주파수로 동작하지 않음
- 이 미세한 주파수 차이가 누적되면, 처음에는 동기화되어 있던 여러 장치의 시계가 시간이 지날수록 조금씩 벌어짐
- 여러 센서·로봇의 데이터를 시간 기준으로 융합하려면, 이 클럭 드리프트를 그대로 두면 실제로는 같은 시점의 데이터인데 다른 시점으로 잘못 정렬될 수 있음

"클럭 드리프트는 한 번 동기화하면 이후로는 절대 다시 발생하지 않는 일회성 오차다"라는 서술은 오답이다 — 클럭 드리프트의 핵심은 오히려 **시간이 지날수록 계속 누적되어 벌어지는 지속적인 오차**이며, 한 번의 동기화로 영구히 해결되지 않고 주기적인 재동기화가 필요하다.

<aside>NTP와의 관계</aside>

[[NTP(Network Time Protocol)]] 같은 시간 동기화 프로토콜을 주기적으로 실행해 클럭 드리프트로 벌어진 시계 차이를 계속 보정해주는 것이, 여러 장치의 시간 기준을 맞추는 기본적인 대응책이다.

---

<aside>핵심 정리</aside>

- 클럭 드리프트는 여러 장치의 시계가 미세한 주파수 차이로 시간이 지날수록 벌어지는 현상이다
- 한 번의 동기화로 영구히 해결되지 않으며, 주기적인 재동기화가 필요하다
