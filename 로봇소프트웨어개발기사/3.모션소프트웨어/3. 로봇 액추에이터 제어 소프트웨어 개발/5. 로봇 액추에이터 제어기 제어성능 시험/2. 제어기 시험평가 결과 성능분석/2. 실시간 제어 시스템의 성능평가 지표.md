# Summary

실시간 제어 시스템의 성능은 "얼마나 빠른가"가 아니라 **정해진 데드라인을 얼마나 지키는가**로 평가하며, 처리 시간의 편차(지터)도 함께 살핀다.

# Notes

<aside>실시간 제어 시스템의 성능평가 지표</aside>

| 지표 | 의미 |
|---|---|
| 데드라인 준수율 | 정해진 제어 주기(데드라인) 안에 연산을 완료한 비율 |
| 지터(Jitter) | 매 주기 실행 시점·소요 시간의 편차(들쭉날쭉한 정도) |
| 응답 지연(Latency) | 사건 발생부터 처리 시작까지 걸리는 시간 |
| 처리량(Throughput) | 단위 시간당 처리할 수 있는 작업량 |

"실시간 제어 시스템의 성능은 평균 처리 속도가 얼마나 빠른가로만 평가하면 충분하다"라는 서술은 오답이다 — 실시간 시스템에서는 평균 속도보다 **정해진 데드라인을 매번 지키는지(데드라인 준수율)와 지터**가 더 중요한 평가 지표다. 평균은 빨라도 가끔 데드라인을 놓치면 실시간 제어로서는 부적합하다.

<aside>실시간성과 처리 속도의 차이</aside>

1과목에서 이미 다뤘듯, 실시간(RT) 제어기의 핵심은 처리 속도 자체가 아니라 **정해진 데드라인 준수 여부**다. 이 관점은 시험 결과를 해석할 때도 그대로 적용되어, 같은 평균 응답 시간을 보이는 두 시스템이라도 데드라인을 놓치는 빈도(또는 지터의 크기)가 다르면 실시간 제어 시스템으로서의 신뢰성은 다르게 평가해야 한다.

<aside>예시 — 시험 결과 해석</aside>

**예시**: 두 제어기 소프트웨어가 평균 응답 시간은 동일하게 측정되었더라도, A는 매 주기 데드라인(예: 1ms)을 100% 지킨 반면 B는 가끔(예: 1% 확률로) 데드라인을 초과했다면, 로봇 관절 제어처럼 데드라인을 놓치는 즉시 위험한 상황(진동·발진)으로 이어질 수 있는 응용에서는 평균이 같더라도 A가 훨씬 더 신뢰할 수 있는 제어기로 평가된다.

---

<aside>핵심 정리</aside>

- 실시간 제어 시스템의 성능평가는 평균 속도가 아니라 데드라인 준수율·지터를 중심으로 이루어진다
- 평균 응답 시간이 같아도 데드라인 초과 빈도가 다르면 실시간 제어 시스템으로서의 신뢰성 평가는 달라진다
