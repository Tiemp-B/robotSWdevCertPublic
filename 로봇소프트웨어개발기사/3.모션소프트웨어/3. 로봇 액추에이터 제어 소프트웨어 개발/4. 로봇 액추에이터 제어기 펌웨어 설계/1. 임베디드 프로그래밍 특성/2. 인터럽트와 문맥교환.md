# Summary

인터럽트가 발생하면 CPU는 현재 실행 중이던 작업의 상태를 저장하고 인터럽트 처리 루틴으로 전환하는데, 이 전환 과정을 **문맥교환(Context Switching)**이라 한다.

# Notes

<aside>인터럽트 처리 흐름</aside>

인터럽트는 CPU가 현재 실행 중인 작업을 잠시 멈추고, 우선순위가 더 높은 긴급한 사건(센서 값 도착, 타이머 만료, 통신 수신 등)을 즉시 처리하도록 하는 메커니즘이다. 여러 인터럽트가 동시에 발생하면 우선순위가 높은 인터럽트를 먼저 처리하며, 처리 중에는 낮은 우선순위 인터럽트를 잠시 보류(마스킹)하는 방식이 일반적이다.

<aside>문맥교환(Context Switching)</aside>

문맥교환은 하나의 실행 흐름(태스크·인터럽트 처리 루틴 등)에서 다른 실행 흐름으로 CPU 제어권이 넘어갈 때, 이전 실행 흐름의 **레지스터 값·프로그램 카운터 등 상태(context)를 저장**하고 다음 실행 흐름의 상태를 복원하는 과정이다.

- 인터럽트 발생 시: 현재 태스크의 문맥을 저장 → 인터럽트 서비스 루틴(ISR) 실행 → 처리가 끝나면 저장해둔 문맥을 복원해 원래 태스크를 이어서 실행
- 문맥교환 자체에도 시간(오버헤드)이 소요되므로, 지나치게 빈번한 인터럽트나 태스크 전환은 실시간 성능을 떨어뜨릴 수 있음

"문맥교환은 인터럽트가 발생해도 실행 중이던 작업의 상태를 저장할 필요 없이 곧바로 새 작업을 실행하는 것을 의미한다"라는 서술은 오답이다 — 문맥교환의 핵심은 오히려 **이전 작업의 상태(레지스터·프로그램 카운터 등)를 반드시 저장**해 두었다가, 나중에 그 지점부터 다시 이어서 실행할 수 있도록 하는 것이다.

<aside>예시 — 로봇 제어기의 인터럽트 처리</aside>

**예시**: 로봇 제어기가 주기적인 위치 제어 루프를 실행하던 중, 긴급 정지 버튼 인터럽트가 발생하면 CPU는 현재 실행 중이던 위치 제어 루프의 문맥을 저장하고 긴급 정지 처리 루틴을 즉시 실행하며, 처리가 끝나면 저장해둔 문맥을 복원해 위치 제어 루프를 이어서 실행한다.

---

<aside>핵심 정리</aside>

- 인터럽트는 우선순위가 높은 긴급 사건을 CPU가 즉시 처리하도록 하는 메커니즘이다
- 문맥교환은 실행 흐름 전환 시 이전 상태를 저장하고 복원하는 과정이며, 상태 저장 없이 곧바로 전환하는 것이 아니다
