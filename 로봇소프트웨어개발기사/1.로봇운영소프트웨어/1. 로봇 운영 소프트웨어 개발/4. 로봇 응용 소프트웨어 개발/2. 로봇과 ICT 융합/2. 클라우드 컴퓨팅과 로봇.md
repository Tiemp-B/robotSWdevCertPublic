# Summary

**[[클라우드 컴퓨팅(Cloud Computing)|클라우드 컴퓨팅]]**은 필요한 만큼의 컴퓨팅 자원(연산·저장·네트워크)을 원격 서버에서 그때그때 빌려 쓰는 방식이다. 로봇에 적용하면, 로봇 자체에는 담기 어려운 대규모 연산(정밀 지도 작성, 대규모 딥러닝 추론, 다수 로봇의 데이터 통합 분석 등)을 원격 서버로 넘겨(오프로드) 처리할 수 있다 — 이를 **클라우드 로보틱스(Cloud Robotics)** 라 부른다.

# Notes

<aside>클라우드 컴퓨팅 개념</aside>

인터넷을 통해 서버·저장소·소프트웨어 같은 컴퓨팅 자원을 **필요한 만큼 사용하고 사용한 만큼 비용을 지불**하는 방식이다. 사용자(여기서는 로봇)가 하드웨어를 직접 소유·유지보수할 필요가 없다는 점이 핵심이다.

<aside>클라우드 로보틱스(Cloud Robotics)</aside>

로봇이 자체적으로 감당하기 어려운 무거운 연산을 클라우드 서버로 넘겨 처리하는 구조다.

| 로봇에 남기는 작업 | 클라우드로 넘기는 작업 |
|---|---|
| 실시간 센서 수집, 기본적인 장애물 회피 | 대규모 지도 작성·경로 최적화 |
| 저수준 모터 제어 | 다수 로봇의 데이터를 통합한 학습·분석 |
| 로컬 안전 정지 판단 | 대용량 딥러닝 모델 추론 |

<aside>클라우드 로보틱스를 쓰는 이유</aside>

로봇 하드웨어는 배터리·발열·무게라는 물리적 제약 때문에 탑재할 수 있는 프로세서 성능에 한계가 있다. 반면 클라우드는 필요할 때만 대규모 연산 자원을 빌려 쓸 수 있어, **로봇을 경량·저비용으로 유지하면서도 고성능 연산 결과를 활용**할 수 있게 해 준다. 또한 여러 대의 로봇이 각자 겪은 경험(지도, 장애물 정보 등)을 클라우드에 모아 서로 공유하면, 한 로봇이 학습한 내용을 전체 로봇이 함께 활용하는 것도 가능하다.

<aside>한계 — 네트워크 의존성</aside>

클라우드 활용은 결국 네트워크 연결에 의존한다는 한계가 있다. 통신이 끊기거나 지연되면 클라우드에 의존하는 기능은 즉시 동작하지 못하므로, **매우 빠른 반응이 필요한 실시간 제어·안전 기능은 클라우드에 맡기지 않고 로봇 자체(또는 엣지)에서 처리**하는 것이 일반적이다. "클라우드 컴퓨팅을 활용하면 모든 로봇 기능의 응답 속도가 빨라진다"는 서술은 이 한계를 무시한 오답 함정이다.

<aside>예시 — 클라우드 기반 지도 작성</aside>

**예시**: 여러 대의 청소로봇이 각자 수집한 실내 공간 데이터를 클라우드로 전송하면, 클라우드 서버가 이를 통합해 훨씬 정밀한 전체 지도를 만들고, 그 결과를 다시 모든 로봇에 배포한다. 개별 로봇은 저사양 센서만으로도 클라우드의 통합 연산 덕분에 정밀한 지도를 활용할 수 있게 된다.

---

<aside>핵심 정리</aside>

- 클라우드 컴퓨팅은 필요한 만큼 원격 자원을 빌려 쓰는 방식이며, 클라우드 로보틱스는 로봇의 무거운 연산을 클라우드로 오프로드하는 구조다
- 로봇을 경량·저비용으로 유지하면서 대규모 연산·다수 로봇 간 데이터 공유가 가능하다는 것이 핵심 이점
- 네트워크 연결에 의존하므로, 실시간성이 중요한 제어·안전 기능은 클라우드가 아니라 로봇 자체나 엣지에서 처리해야 한다
