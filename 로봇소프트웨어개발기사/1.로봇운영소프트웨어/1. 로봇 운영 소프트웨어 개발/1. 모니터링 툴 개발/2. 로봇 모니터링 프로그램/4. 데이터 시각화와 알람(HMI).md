# Summary

**[[HMI(Human-Machine Interface)|HMI]]**는 [[3. SCADA 구조와 산업용 모니터링 시스템|SCADA]] 구조의 최상위 계층으로, 수집된 데이터를 운영자가 한눈에 파악할 수 있는 그래픽(게이지·트렌드그래프·상태 인디케이터)으로 변환해 보여준다. **[[알람(Alarm)|알람]]**은 이 위에서 임계값 이탈·이상 상태를 신속히 통보하는 기능으로, 목적은 **문제를 자동으로 해결하는 것이 아니라 운영자가 빠르게 인지·대응하도록 유도하는 것**이다.

# Notes

<aside>HMI의 역할</aside>

HMI는 SCADA 계층 구조의 최상단에서 두 방향의 상호작용을 담당한다.

- **표시(Display)**: 로봇/설비 상태를 시각적으로 표현
- **조작(Operation)**: 운영자가 시작/정지·모드 전환 등 상위 명령을 입력하는 창구([[3. SCADA 구조와 산업용 모니터링 시스템|SCADA]]의 "원격 명령" 기능과 연결)

<aside>시각화 요소별 용도</aside>

| 요소 | 적합한 용도 |
|---|---|
| 게이지/미터 | 배터리 잔량·모터 온도처럼 "현재 값이 정상 범위 내인지"가 중요한 값 |
| 트렌드 그래프 | 관절 각도·전류값처럼 시간 흐름에 따른 추이 파악이 필요한 값 |
| 상태 인디케이터(색상) | 가동/정지/에러 등 몇 가지 이산 상태로 나뉘는 값 |
| 프로세스 개요도(Mimic Diagram) | 여러 로봇 셀의 배치와 상태를 공간적으로 함께 파악해야 할 때 |

설계 원칙: ①정상=녹색·경고=노랑·위험=빨강처럼 **색상 규약을 화면 전체에서 일관**되게 유지, ②안전·가동 관련 핵심 지표를 시각적으로 **우선순위화**, ③빠르게 변하는 값은 트렌드 그래프, 느리게/이산적으로 변하는 값은 인디케이터로 표현.

**가공되지 않은 원시 로그(raw text log)를 그대로 나열하는 것은 적합한 시각화로 보기 어렵다** — 시각화의 목적은 수치 데이터를 사람이 즉각 해석 가능한 그래픽으로 요약하는 것이며, 원시 로그 자체는 [[5. 데이터 로깅과 이상치 탐지]]에서 다루는 "기록·추후 분석" 영역에 가깝다.

<aside>알람의 개념과 등급</aside>

**[[알람(Alarm)|알람]]**은 사전 정의된 임계값을 데이터가 벗어나거나 이상 상태가 감지됐을 때 운영자에게 통보하는 기능이다. 핵심은 **신속한 인지·대응 유도**이지, 알람 자체가 문제를 진단하거나 자동으로 해결하지는 않는다 — 실제 대응(정지, 재시작 등)은 여전히 운영자 판단이나 별도 제어 로직이 수행한다.

| 등급 | 예시 | 대응 시급성 |
|---|---|---|
| Critical | E-stop 작동, 안전 회로 차단 | 즉시 대응 필요 |
| Warning | 배터리 잔량 저하, 온도 상승 추세 | 단기간 내 확인 필요 |
| Info | 정기 점검 시점 도래, 업데이트 알림 | 즉시 대응 불필요 |

<aside>알람 폭주(Alarm Flooding)</aside>

하나의 근본 원인(예: 특정 로봇 셀의 전원 이상)이 여러 연쇄 알람(통신 두절, 배터리 경고, 위치 갱신 중단 등)을 동시에 일으켜 운영자가 정작 중요한 원인을 놓치는 현상을 **[[알람 폭주(Alarm Flooding)|알람 폭주]]**라 한다. 대응책:

- **알람 그룹화**: 연관된 알람을 하나의 카드/그룹으로 묶어 표시
- **우선순위 필터링**: Critical은 화면 상단 고정, Info성 알람은 별도 로그로 분리
- **근본 원인 알람(Root Cause Alarm)만 강조**: 파생 알람은 축소, 최초 원인만 부각

<aside>예시 — 로봇 셀 HMI 화면 구성</aside>

**예시**: 배터리 잔량은 게이지로, 관절 전류값은 최근 5분 트렌드 그래프로, 가동/정지/에러 상태는 색상 인디케이터로, 비상정지 발생 시 화면 상단에 Critical 알람 배너가 고정 표시되는 구성이 전형적이다. 통신 두절로 파생된 여러 알람은 "전원 이상"이라는 근본 원인 알람 하나로 묶여 표시된다.

---

<aside>핵심 정리</aside>

- HMI는 SCADA 최상위 계층 — 데이터를 게이지·트렌드그래프·상태인디케이터로 표현 + 명령 입력 창구
- 원시 로그를 그대로 나열하는 것은 시각화로 부적합 — 로그 기록/분석은 별도 영역
- 알람의 목적은 **신속한 인지·대응 유도**(자동 해결 아님), Critical/Warning/Info 등급화
- 알람 폭주는 그룹화·우선순위 필터링·근본 원인 알람 강조로 완화
