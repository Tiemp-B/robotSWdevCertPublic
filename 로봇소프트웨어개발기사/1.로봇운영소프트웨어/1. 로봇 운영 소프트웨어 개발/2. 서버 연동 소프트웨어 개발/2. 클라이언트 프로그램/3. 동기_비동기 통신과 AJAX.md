# Summary

**동기(Synchronous) 통신**은 요청을 보낸 후 응답이 올 때까지 다음 작업을 멈추고 기다리는 방식이고, **비동기(Asynchronous) 통신**은 응답을 기다리지 않고 다른 작업을 계속하다가 응답이 도착하면 그때 처리하는 방식이다. **[[AJAX(Asynchronous JavaScript and XML)|AJAX]]**는 이 비동기 통신을 웹 브라우저에서 구현한 대표적 기술로, 페이지 전체를 새로고침하지 않고 필요한 부분만 서버와 통신해 갱신할 수 있게 해준다.

# Notes

<aside>동기 vs 비동기 통신</aside>

| 항목 | 동기 통신 | 비동기 통신 |
|---|---|---|
| 응답 대기 | 응답이 올 때까지 다음 코드 실행 중단 | 응답을 기다리지 않고 다른 작업 계속 |
| 사용자 경험 | 응답이 늦으면 화면이 멈춘 것처럼 보임 | 응답을 기다리는 동안에도 화면 조작 가능 |
| 처리 방식 | 순차적 | 콜백/이벤트로 응답 도착 시점에 처리 |

<aside>AJAX 개념과 동작</aside>

**AJAX**는 브라우저가 페이지 전체를 다시 불러오지 않고, 자바스크립트로 서버와 비동기 통신을 해 화면의 필요한 부분만 갱신하는 기법이다. 이름에 XML이 들어가지만 실제로는 JSON 등 다른 데이터 형식도 널리 쓰인다.

브라우저의 **XHR(XMLHttpRequest)** 또는 **Fetch API**로 백그라운드에서 서버에 요청을 보내고, 응답이 도착하면 등록해 둔 콜백이 실행되어 페이지의 특정 부분(DOM 일부)만 갱신한다 — 사용자가 보고 있는 화면은 그대로 유지된 채 데이터만 바뀐다는 점이 "AJAX의 특징"으로 가장 자주 언급된다.

<aside>비동기 통신의 장점</aside>

- **응답성(Responsiveness)**: 서버 응답을 기다리는 동안에도 사용자가 화면을 계속 조작할 수 있어 화면이 멈추지 않음
- **부분 갱신**: 페이지 전체가 아니라 필요한 데이터만 주고받아 트래픽 절감
- **서버 자원 활용**: 클라이언트가 대기 없이 다른 작업을 하므로 여러 요청을 효율적으로 겹쳐 처리 가능

<aside>콜백과 Promise</aside>

- **콜백(Callback)**: 비동기 작업이 끝난 후 실행할 함수를 미리 등록하는 방식 — 콜백 안에 또 콜백을 넣는 구조가 중첩되면 **콜백 지옥(Callback Hell)** 문제가 생길 수 있다
- **[[Promise(프라미스)|Promise]]**: 비동기 작업의 최종 성공/실패 결과를 나타내는 객체 — `.then()`으로 성공 시 처리를, `.catch()`로 실패 시 처리를 연결해 콜백 중첩 문제를 완화한다

<aside>예시 — 로봇 대시보드에서의 AJAX 활용</aside>

**예시**: 로봇 관제 대시보드가 5초마다 백그라운드에서 AJAX로 로봇 상태를 조회해 배터리 게이지와 상태 인디케이터만 갱신한다면, 운영자는 페이지가 깜빡이며 새로고침되는 것을 보지 않고도 최신 상태를 계속 확인할 수 있다.

<aside>핵심 정리</aside>

- 동기는 응답을 기다리며 다음 작업을 멈추고, 비동기는 응답을 기다리지 않고 다른 작업을 계속함
- AJAX는 페이지 새로고침 없이 필요한 부분만 서버와 통신해 갱신하는 비동기 통신 기법
- 비동기 통신의 장점: 응답성 향상, 부분 갱신에 의한 트래픽 절감, 효율적 자원 활용
- Promise는 콜백 중첩(콜백 지옥) 문제를 완화하는 비동기 처리 방식
