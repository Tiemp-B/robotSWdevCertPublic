# Summary

**[[생산자-소비자 문제(Producer-Consumer Problem)|생산자-소비자 문제]]**는 데이터를 생성하는 생산자(Producer)와 그 데이터를 사용하는 소비자(Consumer)가 서로 다른 속도로 동작할 때 발생하는 동기화 문제다. 이를 해결하기 위해 가장 널리 쓰이는 자료구조가 **[[블로킹 큐(Blocking Queue)|블로킹 큐]]**다.

# Notes

<aside>생산자-소비자 문제 개념</aside>

생산자가 소비자보다 빠르게 데이터를 만들면 처리되지 못한 데이터가 계속 쌓이고(버퍼 오버플로), 반대로 소비자가 더 빠르면 처리할 데이터가 없어 대기하게 된다(버퍼 언더플로). 두 주체의 속도 차이를 흡수하면서 데이터를 안전하게 주고받는 것이 이 문제의 핵심이다.

<aside>공유 버퍼와 경쟁 상태</aside>

생산자와 소비자가 같은 버퍼에 아무 보호 장치 없이 동시에 접근하면 **경쟁 상태(Race Condition)**가 발생할 수 있다 — 예를 들어 소비자가 값을 읽는 도중에 생산자가 그 값을 덮어쓰는 식이다. 이를 막으려면 버퍼에 대한 접근을 동기화해야 한다.

<aside>생산자-소비자 문제를 해결하는 자료구조 — 큐</aside>

**생산자-소비자 문제를 해결하기 위해 사용되는 대표적 자료구조는 큐(Queue), 특히 [[블로킹 큐(Blocking Queue)|블로킹 큐]]다.** 블로킹 큐는 버퍼가 가득 차면 생산자를 대기시키고, 버퍼가 비어 있으면 소비자를 대기시켜 두 주체가 안전하게 데이터를 주고받도록 한다.

<aside>블로킹 큐의 동작 방식</aside>

| 연산 | 동작 |
|---|---|
| put(생산자) | 버퍼에 값을 추가, 버퍼가 가득 차 있으면 공간이 생길 때까지 대기 |
| take(소비자) | 버퍼에서 값을 꺼냄, 버퍼가 비어 있으면 값이 들어올 때까지 대기 |

내부적으로는 [[3. 동기화 메커니즘(세마포어·뮤텍스·데드락)|세마포어나 뮤텍스]]로 이 대기·알림을 구현한다.

<aside>세마포어와의 관계 — 고전적 해법</aside>

카운팅 세마포어 두 개로 "채워진 슬롯 수"와 "빈 슬롯 수"를 각각 추적하는 것이 생산자-소비자 문제의 고전적인 해법(Dijkstra의 해법)이다. [[3. 동기화 메커니즘(세마포어·뮤텍스·데드락)]]에서 다룬 세마포어 개념이 실제로 이렇게 활용된다.

<aside>원형 버퍼(Ring Buffer)와의 비교</aside>

고정 크기 배열을 순환적으로 사용하는 **원형 버퍼(Ring Buffer)**도 생산자-소비자 문제에 자주 쓰인다. 큐보다 메모리 할당이 고정적이어서 예측 가능한 성능이 필요한 실시간 시스템에서 선호되는 경우가 많다.

<aside>예시 — 로봇 명령 큐</aside>

**예시**: 여러 운영자가 동시에 로봇에 명령을 보내면(생산자), 로봇 제어기는 이 명령들을 블로킹 큐에 순서대로 쌓아 두고 하나씩 꺼내 처리한다(소비자). 이렇게 하면 여러 명령이 동시에 들어와도 유실되거나 뒤섞이지 않고 순서대로 안전하게 처리된다.

---

<aside>핵심 정리</aside>

- 생산자-소비자 문제는 생산·소비 속도 차이로 인한 버퍼 오버플로/언더플로, 그리고 동시 접근으로 인한 경쟁 상태 문제다
- 이를 해결하는 대표 자료구조는 **블로킹 큐**이며, 내부적으로 세마포어(채워진/빈 슬롯 수 추적)로 구현된다
- 실시간성이 중요하면 원형 버퍼가 대안이 될 수 있다
