# Summary

**세부항목 "외부 툴과의 동기화 소프트웨어 개발"**은 로봇이 외부의 도구(원격 제어기, 모니터링 시스템, 다른 로봇 등)와 상호작용할 때 발생하는 두 가지 문제를 다룬다 — [[1. 로봇 원격제어기 인터페이스|로봇 원격제어기 인터페이스]]가 "명령을 어떻게 전달하는가"에 초점을 맞췄다면, **동기화 프로그램**은 그 상호작용 과정에서 여러 주체의 **시간·데이터 접근·상태가 서로 어긋나지 않도록 맞추는 방법**에 초점을 맞춘다.

# Notes

<aside>동기화(Synchronization)란</aside>

여러 주체(프로세스, 시스템, 기기)가 공유하는 시간·데이터·상태를 서로 어긋나지 않게 맞추는 것을 말한다. 로봇과 외부 툴은 물리적으로 분리된 별도의 시스템이기 때문에, 로컬(단일 프로세스) 환경과 달리 시간차·경쟁 상태·데이터 불일치 같은 문제가 자연스럽게 발생하며, 이를 해소하는 것이 동기화 프로그램의 역할이다.

<aside>세부항목 안에서의 위치</aside>

| 세세항목 | 초점 |
|---|---|
| [[1. 로봇 원격제어기 인터페이스]] | 외부에서 로봇에 명령을 전달하는 통신 채널·프로토콜·HMI |
| 2. 동기화 프로그램(이 세세항목) | 그 상호작용 과정에서 발생하는 시간·동시접근·상태 불일치 문제 해결 |

즉 원격제어기 인터페이스가 "무엇으로 전달하는가"를 다뤘다면, 동기화 프로그램은 "전달된 것들이 서로 어긋나지 않게 맞추는 방법"을 다룬다.

<aside>이 세세항목에서 다루는 세 가지 동기화 문제</aside>

| 문제 | 내용 |
|---|---|
| 시간 동기화 | 여러 기기의 시계를 일치시키는 문제 ([[2. 시간 동기화와 NTP]]) |
| 동시 접근 동기화 | 여러 주체가 같은 자원(큐 등)에 동시에 접근할 때의 문제 ([[3. 생산자-소비자 문제와 동기화 자료구조]]) |
| 상태 동기화 | 클라이언트와 로봇 간 실시간 상태를 일치시키는 문제 ([[4. WebSocket과 상태 동기화]]) |

<aside>예시 — 세 문제가 함께 나타나는 상황</aside>

**예시**: 여러 대의 로봇에서 발생한 이벤트 로그를 시간 순서대로 재구성하려면 **시간 동기화**(NTP)가 필요하고, 여러 운영자가 동시에 명령을 보낼 때는 **생산자-소비자 큐**로 처리 순서를 관리하며, 관제 대시보드는 **WebSocket**으로 로봇의 최신 상태와 화면을 실시간으로 일치시킨다. 이 세 가지는 서로 다른 층위의 동기화 문제이지만, 모두 "분리된 시스템 간 불일치를 어떻게 없애는가"라는 동일한 질문에서 출발한다.

---

<aside>핵심 정리</aside>

- 동기화 프로그램은 로봇과 외부 툴 사이의 **시간·동시접근·상태** 불일치를 해소하는 소프트웨어를 다룬다
- "로봇 원격제어기 인터페이스"(명령 전달 방법)와 대비되는, "전달된 것들을 서로 맞추는 방법"이 이 세세항목의 초점이다
- 이후 페이지는 시간 동기화(NTP), 동시 접근 동기화(생산자-소비자 문제), 상태 동기화(WebSocket) 순으로 다룬다
