# Summary

**로봇 원격제어기 인터페이스**는 운영자가 물리적으로 로봇과 떨어진 위치에서 명령을 내리고 로봇의 상태를 확인할 수 있게 해주는 소프트웨어/하드웨어 인터페이스다. 로컬 제어와 달리 **네트워크를 매개로 한다**는 점 때문에, 통신 프로토콜 선택, 로봇 미들웨어(ROS)를 통한 명령 전달, 안전한 조작 화면(HMI) 설계, 네트워크 지연 관리라는 문제들을 함께 고려해야 한다.

# Notes

<aside>로봇 원격제어기 인터페이스 개념</aside>

운영자(클라이언트)와 로봇(제어 대상) 사이에서 **명령 전달과 상태 피드백을 중개**하는 인터페이스다. 로봇에 직접 부착된 조작기로 제어하는 **로컬 제어**와 달리, 네트워크를 거쳐 원격지에서 제어하는 것이 **원격 제어**다.

<aside>구성 요소</aside>

| 구성 요소 | 역할 |
|---|---|
| 클라이언트(조작 UI/HMI) | 운영자가 명령을 입력하고 로봇 상태를 확인 |
| 통신 채널(프로토콜) | 명령과 상태 데이터를 네트워크로 전달 |
| 로봇 측 수신부(제어기) | 수신한 명령을 실제 동작으로 변환하고, 상태를 다시 보고 |

<aside>원격제어와 로컬제어의 차이</aside>

로컬 제어는 물리적 배선이나 근거리 통신으로 지연이 거의 없고 신뢰성이 높다. 반면 원격 제어는 네트워크를 거치므로 **지연시간, 패킷 유실, 보안 위협**이라는, 로컬 제어에는 없던 문제가 새로 생긴다. 이 때문에 원격제어기 인터페이스 설계에는 로컬 제어에는 없는 고려사항들이 추가로 필요하다.

<aside>예시 — 로봇 원격제어 시스템 전체 흐름</aside>

**예시**: 운영자가 웹 대시보드(클라이언트)에서 정지 버튼을 클릭하면, 명령이 통신 채널(MQTT 등)을 통해 전송되고, 로봇 제어기의 ROS 노드가 이 명령을 수신해 실제 정지 동작을 수행한 뒤, 그 결과 상태가 다시 Topic으로 발행되어 대시보드에 반영된다. 이 한 번의 "클릭→정지→화면 갱신" 흐름 안에 이 세세항목의 네 페이지가 다루는 요소가 모두 관여한다.

---

<aside>핵심 정리</aside>

- 원격제어기 인터페이스는 **클라이언트(HMI) — 통신 채널(프로토콜) — 로봇 측 제어기** 세 구성 요소로 이뤄진다
- 원격 제어는 로컬 제어와 달리 네트워크를 거치므로 지연·유실·보안 문제를 새로 안게 된다
- 이 세세항목의 나머지 페이지는 이 구성 요소들을 각각 통신 프로토콜, ROS, HMI, 네트워크 지연/QoS 관점에서 다룬다
