# Summary

사용 패턴 분석은 비정상적인 사용을 찾아내는 **이상치 탐지**와, 자주 쓰는 기능을 UI에서 더 쉽게 접근할 수 있도록 하는 **사용빈도 기반 설계 원칙**으로 이어진다.

# Notes

<aside>이상치(Anomaly) 탐지 방법</aside>

| 방법 | 개요 |
|---|---|
| 통계적 방법(Z-score 등) | 평균에서 표준편차 기준 일정 범위를 벗어나면 이상치로 판단 |
| 군집 기반(clustering) | 데이터를 군집화한 뒤, 어느 군집에도 속하지 않는 데이터를 이상치로 판단 |
| 머신러닝 기반(Isolation Forest 등) | 정상 패턴을 학습해 이를 벗어나는 패턴을 탐지 |

"로봇의 사용 패턴에서 이상치를 탐지하는 가장 적절한 방법은 사용 빈도가 가장 높은 값을 그대로 이상치로 간주하는 것이다"라는 서술은 오답이다 — 사용 빈도가 **가장 높은** 값은 오히려 전형적인 정상 패턴에 해당하며, 이상치는 정상 분포에서 **크게 벗어난 드문** 값을 가리킨다.

<aside>사용빈도 기반 설계 원칙</aside>

사용 패턴 분석 결과 자주 쓰이는 기능이 파악되면, 이를 UI 설계에 반영한다.

- 사용 빈도가 높은 기능은 [[3. UI 설계 법칙(Fitts·Hick·Miller)|피츠의 법칙]]에 따라 화면 중앙 가까이, 크게 배치
- 사용 빈도가 낮은 기능은 하위 메뉴로 이동시켜 [[3. UI 설계 법칙(Fitts·Hick·Miller)|힉의 법칙]]에 따라 주 화면의 선택지 개수를 줄임
- 자주 함께 쓰이는 기능은 한 화면(청크)으로 묶어 [[3. UI 설계 법칙(Fitts·Hick·Miller)|밀러의 법칙]] 범위 내로 구성

"사용 빈도가 높은 기능의 설계 원칙은 해당 기능을 가장 깊은 하위 메뉴에 숨겨 실수로 누르지 않도록 하는 것이다"라는 서술은 오답이다 — 사용 빈도가 높은 기능은 오히려 **접근성을 높여 쉽게 도달**할 수 있도록 상위 화면에 배치해야 한다.

<aside>예시 — 사용 패턴 분석에서 설계로 이어지는 흐름</aside>

**예시**: 사용 이력 분석 결과 "긴급 정지"와 "일시 정지" 기능이 전체 사용의 60%를 차지한다면, 이 두 기능을 메인 화면 상단에 크고 인접하게 배치하고, 상대적으로 드물게 쓰이는 "고급 설정" 기능은 하위 메뉴로 옮겨 화면의 선택지 수를 줄인다.

---

<aside>핵심 정리</aside>

- 이상치는 정상 분포에서 크게 벗어난 드문 값이며, 사용 빈도가 높은 값은 이상치가 아니라 전형적 패턴이다
- 사용 빈도가 높은 기능은 숨기는 것이 아니라 접근성을 높여 배치해야 한다(피츠·힉·밀러 법칙 적용)
