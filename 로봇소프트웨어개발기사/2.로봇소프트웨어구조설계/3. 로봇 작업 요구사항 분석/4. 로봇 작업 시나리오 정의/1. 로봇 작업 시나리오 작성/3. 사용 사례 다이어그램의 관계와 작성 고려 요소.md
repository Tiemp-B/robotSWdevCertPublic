# Summary

사용 사례 다이어그램에서 액터와 사용 사례, 사용 사례들끼리는 **연결·포함(include)·확장(extend)** 세 가지 관계로 표현되며([[3. UML과 행위적 다이어그램|UML use case diagram]] 표기 기반), 좋은 작업 시나리오를 작성하려면 정해진 요소를 빠짐없이 포함해야 한다.

# Notes

<aside>사용 사례 다이어그램의 세 가지 관계</aside>

| 관계 | 표시 | 의미 |
|---|---|---|
| 연결(association) | 실선 화살표 | 액터와 사용 사례가 직접 상호작용 |
| 포함(include) | 점선 화살표 + «include» | 여러 사용 사례에서 공통으로 쓰이는 부분을 분리 — 포함하는 사용 사례가 수행되면 **반드시 같이 수행**되어야 함 |
| 확장(extend) | 점선 화살표 + «extend» | 특별한 조건에서만 다른 사용 사례로 확장 — **조건이 성립할 때만** 수행됨 |

"포함(include) 관계에 있는 사용 사례는 특정 조건이 성립할 때만 선택적으로 수행된다"라는 서술은 **확장(extend)** 관계와 뒤바뀐 오답이다 — 포함 관계는 **반드시 함께** 수행되어야 하며, 조건에 따라 선택적으로 수행되는 것은 확장 관계다.

<aside>로봇 작업 시나리오 작성 시 고려 요소</aside>

- 시나리오는 **정상 흐름**뿐 아니라 **오류·예외 흐름**까지 포함해야 함
- 특정 장소·시간에 따라 달라지는 조건도 반영
- 액터의 관점에서 기술하되, 시스템 내부 동작 방식은 기술하지 않음(행위 과정이 아닌 행위 자체만 표현)
- 사용자·개발자가 함께 검토해 상충되는 시나리오를 정리

"로봇 작업 시나리오 작성 시 고려해야 할 요소로는 시스템 내부 알고리즘의 세부 구현 코드가 있다"라는 서술은 오답이다 — 시나리오는 **액터와 시스템의 상호작용(행위)** 만 표현하며, 알고리즘의 구체적 구현 방법은 개발 단계에서 결정할 사항이지 시나리오에 포함되지 않는다.

<aside>포함되어야 할 요소</aside>

작업 시나리오(사용 사례) 문서에는 사용 사례 이름, 참여 액터, 시작 조건, 사건의 흐름(정상 흐름 + 선택/예외 흐름)이 반드시 포함되어야 한다. "장애물 회피" 사용 사례처럼 액터가 없는 경우도 있을 수 있다.

<aside>예시 — 포함·확장 관계의 실제 사례</aside>

**예시**: "경로 계획을 수행한다"와 "장애물을 감지한다"는 "액추에이터를 제어한다"가 수행되기 위해 반드시 함께 실행되어야 하므로 **포함(include)** 관계이며, "맵 빌딩을 수행한다"는 감지된 장애물이 지도를 갱신할 만큼 중요할 때만 조건부로 실행되므로 **확장(extend)** 관계다.

---

<aside>핵심 정리</aside>

- 포함(include) = 반드시 함께 수행 / 확장(extend) = 조건이 성립할 때만 선택적으로 수행
- 시나리오는 정상 흐름과 예외 흐름을 모두 포함하되, 시스템 내부 구현 코드는 기술하지 않는다
