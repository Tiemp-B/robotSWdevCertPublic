# Summary

CPU·메모리 최적화는 병목 지점을 **프로파일링으로 먼저 찾아낸 뒤**, 불필요한 반복 작업을 줄이고 알고리즘·자료구조·동시성 구조를 개선하는 순서로 진행한다.

# Notes

<aside>최적화의 출발점 — 프로파일링</aside>

프로파일링(profiling)은 실행 중인 프로그램의 CPU·메모리 사용량을 함수·모듈 단위로 측정해 병목 지점을 찾는 작업이다. 병목을 확인하지 않고 감으로 코드를 최적화하면 실제 성능에 영향이 적은 부분에 시간을 낭비하기 쉽다.

<aside>CPU 사용률 최적화 기법</aside>

- **불필요한 폴링(polling) 축소**: 일정 주기로 계속 상태를 확인하는 대신, 상태 변화가 있을 때만 반응하는 [[3. 가비지 컬렉션과 이벤트 기반 처리\|이벤트 기반 처리]]로 전환
- **알고리즘 개선**: 시간 복잡도가 낮은 알고리즘·자료구조로 교체
- **불필요한 연산 제거**: 매 주기 반복되는 계산 중 캐시 가능한 값은 캐싱
- **스레드/프로세스 우선순위 조정**: 실시간성이 중요한 작업에 높은 우선순위 부여
- **락(lock) 경합 최소화**: 과도한 [[3. 동기화 메커니즘(세마포어·뮤텍스·데드락)\|뮤텍스]] 사용으로 인한 대기시간 축소

"CPU 사용률을 낮추기 위해서는 모든 프로세스에 동일하게 높은 우선순위를 부여하는 것이 효과적이다"라는 서술은 오답이다 — 모든 프로세스의 우선순위를 동일하게 높이면 스케줄링상 의미가 없어지고 오히려 컨텍스트 스위칭 부담만 늘어난다. 우선순위는 **실시간성이 중요한 작업에 선별적으로** 부여해야 한다.

<aside>메모리 최적화 기법</aside>

- **메모리 재사용**: 객체를 매번 새로 생성하지 않고 풀(pool)에서 재사용(object pooling)
- **불필요한 복사 최소화**: 큰 데이터를 값으로 복사하지 않고 참조로 전달
- **메모리 누수 방지**: [[3. 가비지 컬렉션과 이벤트 기반 처리|가비지 컬렉션]] 미지원 환경에서는 할당·해제 짝을 명확히 관리(정적 분석 도구로 사전 검출 — [[3. 정적 분석과 코딩 표준|정적 분석]] 참고)

<aside>예시 — 센서 폴링을 이벤트 기반으로 전환</aside>

**예시**: 매 10ms마다 초음파 센서 값을 읽어 장애물 유무를 확인하던 구조를, 센서 인터럽트가 발생했을 때만 값을 읽는 구조로 바꾸면 불필요한 CPU 점유가 줄어 다른 제어 루프에 자원을 더 할당할 수 있다.

---

<aside>핵심 정리</aside>

- CPU·메모리 최적화는 프로파일링으로 병목을 먼저 확인한 뒤 진행해야 하며, 폴링을 이벤트 기반으로 전환하거나 락 경합을 줄이는 방식이 효과적이다
- 모든 프로세스에 동일하게 높은 우선순위를 주는 것은 최적화가 아니라 스케줄링 효과를 무력화하는 오답 함정이다
