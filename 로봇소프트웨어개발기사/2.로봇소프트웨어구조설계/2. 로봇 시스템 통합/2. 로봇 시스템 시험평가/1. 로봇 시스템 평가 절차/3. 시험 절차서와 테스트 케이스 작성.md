# Summary

시험을 체계적으로 수행하려면 시험 대상과 방법을 정의한 **시험 절차서**, 입력·예상 출력을 정의한 **테스트 케이스**, 요구 사항이 빠짐없이 검증되었는지 확인하는 **요구 사항 추적성 매트릭스**가 필요하다.

# Notes

<aside>시험 절차서의 구성</aside>

시험 절차서에는 시험 목적·항목, 시험 환경 및 필요 장비, 개발환경, 테스트 케이스(입력 자료·예상 결과·평가 기준), 시험 순서, 요구 사항 추적성 매트릭스가 포함된다.

<aside>테스트 케이스 작성</aside>

테스트 케이스는 시험 대상 함수에 **입력값**을 주고, **실제 출력값**이 **예상 출력값**과 같은지 비교하는 방식으로 구성한다. 좋은 테스트 케이스는 다음 원칙을 따른다.

- 한 번에 1개의 기능만 시험하도록 작성
- Positive(정상) 시나리오와 Negative(비정상/예외) 시나리오를 모두 커버
- 추상적이지 않고 명확하게 작성
- 반복 시험이 가능하도록 재사용 가능하게 작성

<aside>블랙박스 테스트 케이스 설계 기법</aside>

| 기법 | 방식 |
|---|---|
| 신택스 시험 | 입력 데이터가 정의된 조건(valid/invalid)에 부합하는지 확인 |
| [[등가 분할(Equivalence Partitioning)\|등가 분할]] | 입력값의 범위를 유사한 부분집합으로 나눠 각 집합에서 대표값만 시험 |
| [[경계값 분석(Boundary Value Analysis)\|경계값 분석]] | 등가 분할한 부분집합의 경계값과 그 주변값을 집중적으로 시험 |

"등가 분할 기법은 부분집합의 경곗값과 그 주변값을 테스트 케이스로 추출하는 방법이다"라는 서술은 **경계값 분석**과 뒤바뀐 오답이다 — 등가 분할은 유사한 값들을 하나의 집합으로 묶어 **대표값 하나만** 시험하는 방법이고, 경계값을 집중적으로 시험하는 것은 경계값 분석이다.

<aside>요구 사항 추적성 매트릭스</aside>

요구 사항 추적성 매트릭스(Requirements Traceability Matrix)는 각 요구 사항 ID와 그 요구 사항을 검증하는 테스트 케이스 ID를 매칭한 표로, 모든 요구 사항이 빠짐없이 시험되었는지 확인하는 데 쓰인다. 시스템 통합 시험 수준에서는 요구 사항별 검증 방법(검사·분석·데모·시험)을 매트릭스로 정리한 VCRM(Verification Cross Reference Matrix)을 사용하기도 한다.

<aside>예시 — 속도 입력값 테스트 케이스</aside>

**예시**: "이동 속도는 0~10 사이 값으로 설정 가능해야 한다"는 요구 사항에 대해, 등가 분할로는 "5"(유효 범위 대표값) 하나만 시험하고 끝낼 수 있지만, 경계값 분석을 적용하면 "-1, 0, 1, 9, 10, 11" 같은 경계 인접값까지 시험해 유효 범위의 양 끝단에서 발생하는 오류를 더 잘 잡아낸다.

<aside>핵심 정리</aside>

- 시험 절차서는 목적·환경·테스트 케이스·시험 순서·요구 사항 추적성 매트릭스로 구성된다
- 등가 분할(대표값 시험)과 경계값 분석(경곗값 집중 시험)은 서로 다른 기법이며 자주 뒤바뀌어 출제된다
