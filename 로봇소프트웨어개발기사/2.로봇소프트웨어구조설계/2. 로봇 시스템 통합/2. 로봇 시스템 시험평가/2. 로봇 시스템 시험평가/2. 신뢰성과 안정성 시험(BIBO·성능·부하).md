# Summary

로봇 시스템의 신뢰성은 소프트웨어의 오류 없는 동작 확률뿐 아니라, 제어 시스템 자체의 **안정성**(BIBO 안정성)과 부하 상황에서의 성능까지 포괄해 평가한다.

# Notes

<aside>소프트웨어 신뢰성이란</aside>

소프트웨어 신뢰성이란 **주어진 환경에서 주어진 시간 동안 오류 없이 동작할 확률**을 말한다. 하드웨어와 달리 소프트웨어는 물리적으로 마모되지 않으므로, 신뢰성은 결함 발생률·평균 고장 간격 등 통계적 지표나 정적/동적 분석([[3. 정적 분석과 코딩 표준|다음 페이지]] 참고)을 통해 간접적으로 측정한다.

"소프트웨어 신뢰성을 측정하는 가장 적절한 방법은 소프트웨어를 오래 사용해 본 사용자의 주관적 만족도를 조사하는 것이다"라는 서술은 오답이다 — 신뢰성은 반복적인 시험·결함 통계·코드 분석 등 **객관적·정량적 지표**로 측정해야 한다.

<aside>[[BIBO 안정성(BIBO Stability)|BIBO 안정성]]</aside>

BIBO(Bounded Input Bounded Output) 안정성은 제어 시스템에 **유한한(bounded) 입력**을 가했을 때 **출력도 유한(bounded)** 하면 그 시스템이 안정하다고 정의하는 제어 이론의 개념이다. 로봇 제어 시스템의 안정성 분석에서 입력이 발산하지 않는데 출력이 발산한다면 그 시스템은 불안정하다고 판단한다.

"BIBO 안정성은 입력이 0으로 수렴하면 출력도 반드시 0으로 수렴한다는 정의다"라는 서술은 오답이다 — BIBO 안정성의 정의는 입력이 **유한(bounded)** 하면 출력도 **유한**하다는 것이지, 입력·출력이 0으로 수렴해야 한다는 의미가 아니다.

<aside>성능·부하 시험</aside>

| 시험 종류 | 정의 |
|---|---|
| 성능 시험 | 시스템에 부하를 주면서 요구 성능 지표를 확인 |
| [[부하 테스트(Load Testing)\|부하 테스트]] | 시스템이 처리할 수 있는 최대 부하를 측정 |
| 장애 시험 | 장애 발생 시 감지·복구 능력 검증 |
| 안정성 시험(비기능) | 장시간 운영해도 문제가 없는지 검증 |
| 확장성 시험 | 시스템 증설에 따라 용량이 선형적으로 증가하는지 확인 |

"부하 테스트의 목적은 시스템이 평상시 요구 성능을 만족하는지 확인하는 것이다"라는 서술은 오답이다 — 부하 테스트의 목적은 평상시 성능 확인이 아니라, 시스템이 처리할 수 있는 **최대 부하(한계치)** 를 측정하는 것이다.

<aside>로그(Log) 시스템</aside>

로그 시스템의 주요 목적은 시스템 실행 중 발생한 이벤트·오류·상태 변화를 기록해, 장애 발생 시 원인을 추적하고 재현할 수 있게 하는 것이다. 로그는 신뢰성 시험 과정에서 결함을 리포팅하고 재현 테스트를 수행할 때 핵심 근거 자료로 쓰인다.

<aside>예시 — 배송 로봇의 신뢰성·안정성 확인</aside>

**예시**: 배송 로봇의 주행 제어 시스템에 유한한 크기의 조향 명령(입력)을 반복적으로 주었을 때 로봇의 위치 궤적(출력)이 발산하지 않고 유한한 범위 내에서 움직이면 BIBO 안정성을 만족한다고 판단하며, 동시에 다수의 동시 배송 요청(부하)을 처리할 때 응답 지연이 급격히 늘어나는 시점을 부하 테스트로 찾아낸다.

---

<aside>핵심 정리</aside>

- 소프트웨어 신뢰성은 정량적 지표로 측정하며, BIBO 안정성은 "유한 입력 → 유한 출력"으로 정의된다(0 수렴이 아님)
- 부하 테스트는 시스템의 최대 처리 한계를 측정하는 시험이며, 평상시 성능 확인은 성능 시험의 몫이다
