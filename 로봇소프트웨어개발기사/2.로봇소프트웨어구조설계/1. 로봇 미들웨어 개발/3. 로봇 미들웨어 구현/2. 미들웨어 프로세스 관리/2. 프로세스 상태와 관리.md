# Summary

미들웨어에서 실행되는 각 프로세스(또는 컴포넌트)는 생성부터 종료까지 정해진 **상태**를 거치며, 미들웨어는 이 상태들을 관리해 여러 프로세스가 자원을 두고 충돌하지 않도록 조정한다.

# Notes

<aside>프로세스의 주요 상태</aside>

| 상태 | 의미 |
|---|---|
| New(생성) | 프로세스가 생성되고 있는 상태 |
| Ready(준비) | CPU 할당을 기다리며 대기 중인 상태 |
| **Running(실행)** | **CPU를 할당받아 실제로 실행 중인 상태** |
| Waiting/Blocked(대기) | 입출력 등 특정 이벤트가 완료되기를 기다리는 상태 |
| Terminated(종료) | 실행이 끝나 자원이 반납된 상태 |

"CPU를 할당받아 실행 중인 상태"를 묻는 문항의 정답은 **Running(실행)** 상태다. Ready(자원을 기다리는 대기 상태)나 Waiting(이벤트를 기다리는 상태)과 혼동하지 않아야 한다 — Ready는 CPU를 아직 할당받지 못한 상태이고, Running은 이미 CPU를 할당받아 동작 중인 상태다.

<aside>미들웨어의 프로세스 관리 주요 기능</aside>

- **상태 전이 관리**: 각 컴포넌트/프로세스가 New→Ready→Running→(Waiting)→Terminated로 올바르게 전이하도록 관리
- **생명주기 관리**: OPRoS 컴포넌트의 onInitialize → onStart → (실행 중 onExecute/onEvent) → onStop → onDestroy처럼, 컴포넌트가 초기화·시작·실행·정지·자원 해제의 정해진 순서를 따르도록 함
- **자원 할당·회수**: 프로세스 종료 시 점유하던 메모리·핸들 등의 자원을 정확히 회수
- **동시 실행 조정**: 여러 프로세스가 동시에 실행될 때 충돌 없이 조정(세부적인 동기화 메커니즘은 [[3. 동기화 메커니즘(세마포어·뮤텍스·데드락)|세마포어·뮤텍스]] 참고)

"미들웨어의 프로세스 관리 기능에는 사용자 인터페이스 렌더링이 포함된다"는 서술은 프로세스 관리(생명주기·자원·상태 전이)와 무관한 기능을 끼워 넣은 오답이다.

<aside>예시 — 로봇 컴포넌트의 생명주기</aside>

**예시**: 로봇 팔 제어 컴포넌트는 생성되어(New) 초기화 절차를 거친 뒤(onInitialize), CPU 할당을 기다리다(Ready) 실행되어(Running) 매 주기마다 제어값을 계산하고, 센서 입력을 기다리는 동안 잠시 대기(Waiting)했다가, 로봇 전원이 꺼지면 자원을 반납하고 종료(Terminated)된다.

---

<aside>핵심 정리</aside>

- 프로세스는 New → Ready → Running → Waiting → Terminated 상태를 거치며, "CPU를 할당받아 실행 중"인 상태는 **Running**이다
- 미들웨어의 프로세스 관리는 상태 전이·생명주기·자원 할당/회수·동시 실행 조정을 담당한다
