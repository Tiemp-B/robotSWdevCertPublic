# Summary

로봇은 대부분 **임베디드 시스템**을 기반으로 동작하며, 그 소프트웨어는 어플리케이션부터 하드웨어까지 여러 계층으로 나뉜다. **미들웨어**는 이 계층 구조에서 어플리케이션과 디바이스 드라이버/운영체제 사이에 위치해, 하드웨어의 세부 사항을 감춘 채 애플리케이션에 필요한 기능을 제공한다.

# Notes

<aside>임베디드 소프트웨어 계층 구조</aside>

로봇 소프트웨어는 대체로 다음과 같은 계층으로 구성된다(위에서 아래로).

| 계층 | 역할 |
|---|---|
| 어플리케이션 | 사용자가 직접 사용하는 소프트웨어(UX/UI, 지능, 컨텐츠 등) |
| 미들웨어 | 애플리케이션에 필요한 기능을 운영체제·하드웨어를 은폐한 형태로 제공 |
| 디바이스 드라이버 | 특정 하드웨어·장치를 제어하는 커널의 일부 프로그램 |
| 운영체제 | 하드웨어 추상화와 공통 시스템 서비스 제공 |
| 하드웨어 | 실제 물리적 장치 |

<aside>임베디드 시스템과 임베디드 소프트웨어</aside>

**임베디드 시스템**은 기계나 제어가 필요한 시스템의 일부로 내장되어 특정 목적의 제어 기능을 수행하는 컴퓨터 시스템이다. 개인용 컴퓨터 같은 범용 목적 시스템과 대조되며, 마이크로컨트롤러나 DSP 같은 프로세서 코어가 핵심 두뇌 역할을 한다. 로봇 시스템은 임베디드 시스템을 기반으로 개발되며, 이를 운영하는 소프트웨어를 **임베디드 소프트웨어**라 한다.

<aside>펌웨어(Firmware)</aside>

장치 안의 ROM(또는 플래시 메모리)에 저장되어 영구적으로 실행되는 소프트웨어다. 메인보드의 BIOS도 펌웨어의 한 예다.

<aside>디바이스 드라이버와 미들웨어의 차이</aside>

**디바이스 드라이버**는 특정 하드웨어를 직접 제어하기 위한 커널의 일부이며, **미들웨어**는 그 위에서 애플리케이션에게 하드웨어·운영체제의 세부 사항을 감춘 채 필요한 기능을 제공하는 소프트웨어다. 임베디드 시스템의 경우 운영체제가 제공하는 기능 수준에 따라 미들웨어가 담당해야 할 기능 범위가 달라진다.

<aside>모듈화(Modularity)의 실무적 이점</aside>

로봇 소프트웨어를 계층·기능별로 모듈화하면 다음과 같은 이점이 있다.

- 복잡도 감소 및 변경 용이성 향상
- 프로그램 구현 용이성 증가
- 확장성·융통성·경제성 향상
- 특정 계층(예: 디바이스 드라이버)만 교체해도 다른 계층에 미치는 영향을 최소화

"모듈화의 장점은 모듈 간의 상호 의존성(결합도)을 높여 기능을 통합하는 것이다"라는 서술은 모듈화의 목적(오히려 결합도를 낮추고 독립성을 높이는 것)과 반대되는 오답이다.

<aside>예시 — 계층 구조에 따른 이식성</aside>

**예시**: 로봇의 모터가 다른 제품으로 교체되어도, 미들웨어가 하드웨어 세부 사항을 감춘 채 동일한 API를 제공한다면 상위 애플리케이션(UX/UI, 지능 등)은 코드를 거의 수정하지 않고도 그대로 동작할 수 있다 — 계층 구조와 모듈화가 함께 만들어내는 이식성의 예다.

---

<aside>핵심 정리</aside>

- 로봇 소프트웨어는 어플리케이션-미들웨어-디바이스 드라이버-운영체제-하드웨어의 계층으로 구성되며, 로봇은 대부분 임베디드 시스템을 기반으로 한다
- 미들웨어는 디바이스 드라이버·운영체제 위에서 애플리케이션에게 하드웨어 세부사항을 감춰 제공하는 계층이다
- 모듈화의 목적은 결합도를 낮추고 변경·확장을 쉽게 하는 것이며, 결합도를 높이는 것이 아니다
